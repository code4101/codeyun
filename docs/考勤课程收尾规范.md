# 考勤课程收尾规范

## 目的

课程收尾不是单纯填写“考勤实际完成结点”，而是一组必须按顺序完成并相互核对的动作：最终统计、返款核验、课程汇总归档、调度摘除和脚本归档。

## 一、统计集合：只统计有效订单行

课程汇总中的所有资金与人数指标，必须基于同一个“有效付费订单集合”计算。

- 首选判据：`商户订单号`非空。
- 微信支付订单号、订单金额、姓名、用户 ID 或考勤数据存在，都不能单独证明该行属于付费报名。
- 商户订单号为空的旁听、复课、工作人员、补录学员，即使模板带出了订单金额，也不得计入课程汇总。
- 缺少`商户订单号`时必须先补齐订单匹配，不得用其他字段猜测有效付费订单。

同一有效订单集合用于计算：

- `报名人数`：有效订单行数。
- `实际总报名费`：有效订单行的订单金额合计。
- `已返款`：有效订单行的支付侧已返款合计。
- `剩余促学金`：实际总报名费减已返款，再按课程汇总既有矫正规则计算。
- `返款率`：已返款除以实际总报名费。

这些字段不能分别使用不同筛选口径。

## 二、返款核验

CodeYun 课程的资金步骤分工如下：

- `step3`在 CodeYun 中计算应返款。
- `step4`提交真实支付返款，属于资金动作。
- `step5`把支付结果更新到 CodeYun 的`已返款`字段。

收尾时先核对`返款配置`和`当前应返款`。只有在明确需要支付且业务人员授权时才能运行`step4`；不得为了“把课程状态跑完”而强制执行资金动作。

若`已返款`高于当前公式计算的`总应返款`，应保留支付侧事实，记录历史补返或规则变化原因，不得生成负向返款或倒扣。

业务负责人可以明确决定放弃剩余待返款并按当前已返款收尾。此时不得运行`step4`，必须在课程汇总备注中记录未处理金额、对应周期和“按当前已返款收尾”的决策；`剩余促学金`继续如实保留，不得为了归零而篡改已返款。

## 三、完结归档

确认统计与返款完成后：

1. 回写课程汇总的报名人数、实际总报名费、已返款等事实数据。
2. 填写`考勤实际完成结点`，通常为课程结束日次日；有延迟处理时使用真实完成日。
3. 确认课程行进入灰色的已完成系列，公式无`#DIV/0!`等错误。
4. 从`xlproject/src/xlsln/kq5034/kqmain.py`对应活跃课程列表移除课程。
5. 将课程脚本移入`courses/已完结/`，保留历史追溯能力，不删除脚本。

## 四、验收清单

- 有效订单人数与课程汇总报名人数一致。
- 无订单人员未进入任何资金汇总。
- 实际总报名费、已返款、剩余促学金和返款率能相互勾稽。
- 没有待提交的返款配置；异常返款差异已有说明。
- 完成结点和灰色归档样式已生效。
- `kqmain.py`不再调度该课程。
- 课程脚本已归档且可编译、可追溯。
- 修改前已留存可恢复备份。
