### OCR 文本匹配

新版 shape 已支持 OCR 匹配配置，并增加了文本匹配模式：

- 包含
- 精确
- 正则
- 通配符：支持 `?` 和 `*`

文本匹配不需要置信度参数。OCR 和图像匹配都可以参与同一个 shape 的综合检测结果；检测结果应同时展示图像相似度和 OCR 命中文本。

### 三态匹配语义

图像和 OCR 使用三态强度：

- `关`
- `必`
- `定`

设计语义：

- `关`：该条件不参与要求。
- `必`：必要条件，失败则不能执行对应动作。
- `定`：更强的直接判定条件，适合稳定场景标识或强锚点。

注意：图像关闭时，右侧参数不一定完全无效。例如抠图/透明通道等预处理思路后续仍可服务于 OCR，以减少背景干扰。

### 日常页标注结构

`#69 日常` 目前是关键帧。它的结构应理解为：

- `日常`：稳定场景标识。
- `滚动窗口`：日常任务列表的滚动容器，内容方向应为 `down`。
- `任务块模板`：滚动窗口内单个任务块模板，是一个普通 shape，同时也是字段子树的父节点。
- `标题`、`次数`、`任务状态`、`活跃度`：任务块模板下的相对字段。

关键原则：

`任务块模板` 可以作为浮动锚点，但它的子字段不是独立浮动目标。运行时先通过标题命中某个实际任务块，再按模板里的相对位置读取次数、状态和活跃度。

这点很重要，不能把 `标题`、`次数`、`任务状态`、`活跃度` 都设置成相对全屏独立浮动，否则会破坏旧版 `create_sub_view("任务块", "标题", anchor)` 的核心思想。

这比让 UI 输入任意文本更合理，因为参数不一定总是字符串，后续可能包含函数、扫描策略、业务状态机等结构。

### 抓包运行态观察

抓包解析可以作为并行子任务推进，不阻塞步进器主线。相关文档见：

- [凡修运行态抓包观察事实层.md](凡修运行态抓包观察事实层.md)

原则是：运行中才能观察到的数据，如当前物资清单、榜单排名、战力、灵石等，先进入观察事实层，再作为图鉴 overlay 自动增量更新，不要直接污染静态 catalog。
