# CodeYun 本地作业与服务解耦审计

## 目标

CodeYun 作为控制面，负责鉴权、配置、触发和状态投影；耗时一次性任务由 Local Job Worker 执行，长期运行能力由 Service 执行。Web 进程退出不应抹掉运行事实，也不应直接终止已经启动的本地工作。

## 当前执行模型

| 模型 | 状态位置 | Web 重启影响 | 目标处理 |
| --- | --- | --- | --- |
| `BackgroundTaskQueue` | Python deque / daemon thread | 队列和状态丢失，当前任务中断 | 迁移耗时任务到 Local Job |
| `LongTaskManager` | Python dict / ThreadPoolExecutor | Future、进度和结果丢失 | 业务实例已清零；框架暂留兼容参考 |
| API 自建 daemon thread | API 模块全局 dict 或业务 Run 表 | 线程中断；部分状态残留为 running | 保留业务 Run，执行改由 Local Job |
| 独立媒体 Worker | JSON 状态文件 / 子进程 | 继续运行 | 迁入统一 Local Job 后删除专用框架 |
| Service | 独立进程 / 健康状态 | 继续运行或由监控恢复 | 保持 Service 边界 |

### 保持为 Service

- 凡修唯一 Kernel、Scheduler/Arbiter、抓包和设备运行时。
- OCR daemon、Device Agent、游戏窗口 daemon。
- 微信 iLink 等需要长期连接和健康检查的组件。

### 明确保留的专用执行边界

- 凡修微信提醒与 Runtime 瘦身仍走凡修专用队列；它们受唯一 Kernel、Cell 和运行权开关约束，不能机械改成通用 Local Job。
- 远端设备媒体扫描已使用“设备凭证引用 + 大结果快照”；后续相同类型任务禁止把请求 Header、设备 Token 或完整结果写入 `LocalJobRun`。
- Git 归纳的显式临时 API Key/Base URL 兼容路径仍留在进程内；标准配置路径已经 Local Job 化，临时凭据不得持久化。

### 保持在请求内

- 鉴权、CRUD、短查询和单次事务性写入。
- 上传字节接收；文件完整落盘后才能提交后续 Local Job。
- WebSocket/SSE 等与客户端连接生命周期绑定的传输逻辑。

## 验收标准

每个迁移任务必须分别证明：

1. API/Scheduler/CLI 使用同一提交入口。
2. CodeYun Web 进程退出后 Worker 继续运行。
3. 新进程能读取运行状态、结果和日志位置。
4. 同资源互斥、不同资源可并行。
5. 取消请求可被 Worker 观察并形成明确终态。
6. Worker 异常退出标记执行通道中断，不污染业务失败语义。
7. 旧内存线程、旧入口和兼容回退从活跃项目移除。
