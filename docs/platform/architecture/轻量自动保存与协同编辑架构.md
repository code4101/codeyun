# 轻量自动保存与协同编辑架构

## 定位

CodeYun 的星图笔记与星云表格面向低并发、以单人编辑为主的场景。默认体验必须像普通本地编辑器：连续输入安静保存，刷新不丢内容，不因版本通知打断用户；只有两个页面确实修改同一字段或同一单元格且新值不同时，才要求用户选择。

本架构落实 [资源保存与并发更新约定](../conventions/资源保存与并发更新约定.md)，不把 `version` 当成冲突本身。它借鉴成熟实现的共同模式：编辑事件节流并串行等待保存、使用条件写入防止丢失更新、通知与内容同步分离、离线草稿只同步尚未确认的本地变化。参考：[CKEditor Autosave](https://ckeditor.com/docs/ckeditor5/latest/features/autosave.html)、[MDN Conditional requests](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Conditional_requests)、[Liveblocks conflict resolution](https://liveblocks.io/docs/guides/how-conflict-resolution-works-in-liveblocks-sync)、[Yjs offline support](https://docs.yjs.dev/getting-started/allowing-offline-editing)。

## 五个正交层次

| 层次 | 责任 | 不负责 |
| --- | --- | --- |
| 编辑会话 | 维护当前页面的基线、最新输入和保存状态 | 判断其它页面内容是否正确 |
| 自动保存队列 | 合并短时间连续输入、串行提交、失败后保留待保存状态 | 用版本号提前宣判冲突 |
| 崩溃草稿 | 在本地保存当前页尚未确认的变化 | 充当跨标签页共享文档 |
| 并发协议 | 用期望字段值或期望单元格值识别真实覆盖 | 将所有过期版本一律拒绝 |
| 在线通知 | 提醒页面权威资源已有新版本 | 携带权威正文或直接覆盖本地输入 |

草稿键必须包含“资源 × 标签页实例”。标签页实例存于 `sessionStorage`，刷新后保持，另一个标签页使用不同实例；历史无实例草稿只允许被一个标签页一次性迁移。这样既能恢复本页崩溃前的输入，也不会把另一个标签页的草稿误认成自己的内容。

## 保存状态机

```text
saved
  └─ 用户输入 → unsaved（立即写入内存并同步写崩溃草稿）
       └─ 防抖到期 → saving（一次只允许一个请求）
            ├─ 成功且无更新输入 → saved（更新基线，清草稿）
            ├─ 成功但期间又有输入 → unsaved（继续下一轮）
            ├─ 异目标过期 → 基于最新状态自动重放
            ├─ 同目标冲突 → 一次差异决策
            └─ 网络/服务失败 → unsaved（保留草稿，可重试）
```

正文连续输入采用约 1 秒防抖，离散元数据操作可更快提交。保存请求必须串行；保存期间的新输入不能被旧响应覆盖。
这里的防抖只用于合并服务端请求，不得延迟本地耐久化；编辑事件返回前必须已经形成可供刷新恢复的当前标签页草稿。

## 星图笔记

- 每次提交只发送相对编辑基线变化的字段，并携带 `base_version`、`expected_fields`、`mutation_id` 和 `client_instance_id`。
- 后端只要收到 `expected_fields` 就校验，不因 `base_version` 恰好等于当前版本而跳过。这样可覆盖“页面已收到新版本通知，但字段基线仍旧”的竞态。
- 服务器只修改其它字段时，当前字段 patch 自动重放；同字段已是请求目标值时按幂等成功处理。
- 同字段不同新值时，编辑器读取服务器最新版，展示服务器值和本地值：选择服务器版本立即回载；选择本地版本则以服务器最新版为新基线重试。
- 启动恢复采用三方比较：草稿基线、草稿内容、服务器内容。无本地增量的陈旧草稿静默丢弃，异字段自动合并，只有同字段差异弹一次对话框。
- 恢复决策是单飞的。弹窗等待期间的 store 刷新只能更新该决策的服务器快照，不能重复打开弹窗。

## 星云表格

- 普通单元格、粘贴和填充走 Sheet patch 队列；每个值操作携带稳定 `row_id/column_id`、`expected_value` 和目标值。
- 两个页面修改不同单元格时，后端按稳定身份在最新 Sheet 上重放，整批原子提交。
- 两个页面修改同一单元格时，页面读取最新 Sheet，展示准确行、列、服务器值和本地值。选择服务器值立即回载；选择本地值则把服务器当前值作为新期望值重试。
- 格式、结构、导入、分页整体替换等不能可靠表达为普通值 patch 的操作保持保守 CAS；发生冲突时保留草稿，不冒充自动合并。
- WebSocket 只在 commit 后发送版本与来源通知。同源通知忽略；页面无本地编辑时静默刷新，有本地编辑时等待 patch 协议决定，不盲目覆盖。

## CRDT 升级边界

当前不引入 OT/CRDT。字段级笔记和单元格表格的主要冲突可以用短事务、稳定目标身份和期望值解决，复杂协同引擎会增加迁移、权限、历史和运维成本。

只有在真实产品数据证明“多人同时修改同一富文本正文”是常态，并且需要光标、选区和字符级实时合并时，才为富文本正文单独引入 Yjs/同类 CRDT；元数据、权限、表结构和业务动作仍使用现有资源事务协议。

## 验收基线

- 单标签页连续输入至少三轮，等待保存后刷新，内容一致且无恢复/冲突弹窗。
- 单标签页输入后立即刷新（早于服务端防抖到期），正文从本地草稿恢复并继续后台同步。
- 同资源双标签页修改不同字段或不同单元格，双方最终静默收敛，刷新后权威值同时存在。
- 同资源双标签页修改同一字段或单元格，只在失败页出现一份差异决策；两种选择都能自动收敛并经刷新确认。
- 一个标签页的失败草稿不会在另一个成功标签页出现。
- 接口回归覆盖异目标重放、同目标 409、目标已达成的幂等成功，以及“当前版本号 + 旧字段基线”的竞态。
