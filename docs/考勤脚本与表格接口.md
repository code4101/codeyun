# CodeYun 表格 API 与 mf 考勤单机运行

> Last Updated: 2026-08-10

> 说明：本文讲 `codepc_mf` 上的表格 API 与课程脚本协作。若任务是“如何启动/停止/诊断考勤行为树本身”，先读 [`行为树运行单元运维约定`](./行为树运行单元运维约定.md)；不要再沿用旧 `xlserver`、mi15 远程转发或旧 `kqmain.py` 路径口径。

## 背景

本文先说明 CodeYun 星云表格 API，再说明当前 `codepc_mf` 考勤流程如何使用这套 API。接口仍支持可信设备调用，但考勤生产职责已经收敛到 mf。

通用概念：

- **表格数据主机**：持有 CodeYun 星云表格数据的 CodeYun 实例，对外提供 `/api/note-sheets/.../table`。
- **可信调用设备**：持有有效设备 token 的任意设备，可以远程读取或回写表格数据。
- **业务执行设备**：负责运行具体业务脚本的设备；当前考勤固定为 `codepc_mf`。

当前考勤部署只有一台生产主机：

- `codepc_mf`：同时承担 CodeYun、考勤行为树、星云表格、小鹅通/微信支付浏览器自动化和课程脚本。报名表、考勤表、课程汇总页及采集结果都存放在 mf 的 CodeYun 数据工作区。
- `codepc_mi15`：已退出考勤生产运行，不再作为执行设备、数据源或失败回退。

阅读视角约定：

- 考勤文档显式写 `codepc_mf`，不要用“本机”制造设备视角歧义。
- 小鹅通、支付和微信登录态均以 mf 的真实环境为准；旧 mi15 Cookie、Tab、数据库或状态文件不再构成生产事实。

当前架构的基础条件：

- mf 本地课程脚本仍通过设备 token 调用 CodeYun 高层接口，保持与通用可信设备 API 一致。
- CodeYun 星云表格已经区分 `columns / grid_rows / rows / data_start_row / field_row_index`，数据区是结构化的。
- 所有考勤生产代码在 mf 的 `codeyun / xlproject / pyxllib` 同源仓库中维护和运行，不再等待另一台机器同步。

## 总体方案

不要继续为每个考勤步骤堆专门业务接口，例如：

```text
/attendance/fanbei/step1
/attendance/fanbei/step2
/attendance/fanbei/step3
...
```

推荐拆成两类基础能力：

1. **业务入口**：mf 的行为树或人工命令直接调用 `xlproject` 课程模块；可信 Python 执行 API 只保留为通用基础设施，不是考勤跨机链路。
2. **结构化表格 API**：mf 课程脚本按字段名、数据行、A1 坐标读取和回写 mf 上的星云表格。

课程脚本统一放在 `C:\home\chenkunze\slns\xlproject\src\xlsln\kq5034\courses`，保持“一个课程一个可读脚本”的业务层表达；脚本只调用目标表格数据主机的 CodeYun 表格 API。当前考勤部署中，目标表格数据主机是 `codepc_mf`。

## 可信 Python 执行 API

接口由 CodeYun 提供。当前考勤行为树直接在 mf 启动课程子进程，通常不需要绕一圈 HTTP；只有调试或外部可信调用方确需提交任务时才使用该 API。

路径是：

```text
POST /api/device-control/python-runs
GET  /api/device-control/python-runs/{run_id}
```

鉴权沿用设备 token：

```http
X-Device-Token: <device-token>
```

或：

```http
Authorization: Bearer <device-token>
```

### 调用模块函数

```python
import requests

mf = "http://127.0.0.1:8000"  # 目标：codepc_mf
token = "..."

resp = requests.post(
    f"{mf}/api/device-control/python-runs",
    headers={"X-Device-Token": token},
    json={
        "mode": "module_call",
        "module": "xlsln.kq5034.kqmain",
        "callable": "run_course_entry",
        "args": ["d260801第49届觉观", "main"],
        "timeout": 3600
    },
    timeout=3700,
)
resp.raise_for_status()
print(resp.json())
```

### 执行临时脚本

```python
resp = requests.post(
    f"{mf}/api/device-control/python-runs",
    headers={"X-Device-Token": token},
    json={
        "mode": "script",
        "script": """
from xlsln.kq5034.kqmain import run_course_entry
result = run_course_entry("d260801第49届觉观", "main")
""",
        "timeout": 3600
    },
)
```

返回值包含：

- `status`: `running / completed / failed / timeout`
- `result`: Python 返回值，尽量 JSON 化
- `stdout / stderr`: 运行日志尾部
- `run_id`: 异步任务后续查询用

如果传 `"async": true`，接口会立即返回 `run_id`，后续用 `GET /api/device-control/python-runs/{run_id}` 轮询。

## 结构化 Sheet Table API

表格接口由“持有星云表格数据的 CodeYun 实例”提供。任何可信调用设备只要持有有效设备 token，就可以远程读取或回写该实例上的表格。

当前考勤调用方向：

```text
codepc_mf 课程脚本 -> codepc_mf /api/note-sheets/sheets/{sheet_id}/table
```

路径是：

```text
GET   /api/note-sheets/sheets/{sheet_id}/table
PATCH /api/note-sheets/sheets/{sheet_id}/table
```

同样支持设备 token。对可信设备，这个接口按 manager 权限处理；当前考勤中由 mf 课程脚本调用 mf 的表格接口。

当前考勤示例中，`codepc_mf` 上的前端页面：

```text
http://localhost:5173/notes/sheets?workbook=2&sheet=4
```

对应 `codepc_mf` 后端调用：

```text
GET /api/note-sheets/sheets/4/table?workbook_id=2
PATCH /api/note-sheets/sheets/4/table?workbook_id=2
```

### 读取 workbook=2 sheet=4

```python
import requests

mf = "http://codepc-mf:8000"  # 目标：codepc_mf
token = "..."

s = requests.Session()
s.trust_env = False  # 局域网互调时避免走系统代理

resp = s.get(
    f"{mf}/api/note-sheets/sheets/4/table",
    params={"workbook_id": 2},
    headers={"X-Device-Token": token},
    timeout=30,
)
resp.raise_for_status()
table = resp.json()

print(table["columns"])
for row in table["rows"]:
    print(row["_sheet_row"], row.get("课程类型"), row.get("在线考勤表"))
```

读取接口默认使用 `value_mode=text`，也就是返回前端表格里“显示出来”的值；常规脚本应使用默认值。名称管理器里的公式会在 `defined_name_values` 中返回计算后的值，供 step4 这类业务脚本生成返款参数。

调试或迁移公式本身时可以显式读取原始值：

```python
resp = s.get(
    f"{mf}/api/note-sheets/sheets/6/table",
    params={"workbook_id": 3, "value_mode": "raw", "include_grid": True},
    headers={"X-Device-Token": token},
    timeout=30,
)
```

`value_mode` 取值：

- `text`：默认，返回显示/计算值。适合 step4 这类业务脚本直接消费。
- `raw`：返回数据库原始值，公式单元格会保留 `=...`。适合排查公式和模板。

返回结构：

```json
{
  "id": 4,
  "workbook_id": 2,
  "title": "课程",
  "version": 12,
  "value_mode": "text",
  "columns": ["课程类型", "在线考勤表", "..."],
  "defined_name_values": {
    "返款说明": "念住闯关每日返款",
    "返款id后缀": "_day502"
  },
  "rows": [
    {
      "_row_index": 0,
      "_sheet_row": 2,
      "课程类型": "梵呗初阶",
      "在线考勤表": "20260509梵呗初阶"
    }
  ],
  "data_start_row": 1,
  "field_row_index": 0
}
```

`_row_index` 是数据区 0 基下标，`_sheet_row` 是表格可见行号。课程脚本一般优先使用字段名和 `_row_index`，只有和用户界面沟通时才使用 `_sheet_row`。

### 回写字段

按某个 key 字段匹配行，适合把课程脚本算出来的状态写回指定课程：

```python
resp = s.patch(
    f"{mf}/api/note-sheets/sheets/4/table",
    params={"workbook_id": 2},
    headers={"X-Device-Token": token},
    json={
        "expected_version": table["version"],
        "operations": [
            {
                "type": "write_fields",
                "key_field": "在线考勤表",
                "fields": ["课次链接", "打卡链接"],
                "rows": [
                    {
                        "在线考勤表": "20260509梵呗初阶",
                        "课次链接": 11,
                        "打卡链接": 9
                    }
                ]
            }
        ]
    },
    timeout=30,
)
resp.raise_for_status()
```

`expected_version` 用来防止脚本基于旧表覆盖新数据。冲突时接口返回 `409`，调用方应重新读取后再写。

### 回写考勤表课次列

考勤明细表有很多类似 `19:30~20:49 第01课` 的列。调用时可以传简写字段 `第1课` 或 `第01课`，后端会尝试匹配包含同一课号的真实列名：

```python
resp = s.patch(
    f"{mf}/api/note-sheets/sheets/6/table",
    params={"workbook_id": 3},
    headers={"X-Device-Token": token},
    json={
        "operations": [
            {
                "type": "write_fields",
                "key_field": "用户ID",
                "fields": ["第1课"],
                "rows": [
                    {"用户ID": "u_xxx", "第1课": 1},
                    {"用户ID": "u_yyy", "第1课": 0}
                ]
            }
        ]
    },
)
```

### 写备注/状态行

星云表格的 `rows` 只表示真实数据区；表头、说明行、按钮行属于 `grid_rows`。如果要写第 3 行这种说明/状态行，用 `set_note_cell`：

```python
resp = s.patch(
    f"{mf}/api/note-sheets/sheets/6/table",
    params={"workbook_id": 3},
    headers={"X-Device-Token": token},
    json={
        "operations": [
            {
                "type": "set_note_cell",
                "field": "当前应返款",
                "value": "最近运行更新时间: 2026/05/10 07:10"
            }
        ]
    },
)
```

默认写到 `field_row_index + 1`，也就是字段名下一行。需要精确坐标时可以传 `sheet_row`。

当前梵呗流程里，step2 通常由业务执行设备写回打卡/课次数据；写回后需要让表格数据主机刷新静态派生结果。这个动作由持有目标考勤表的 CodeYun 实例执行：

resp = s.post(

- 渲染课次进度列的背景色。

它不会覆盖 `G/H/J/K/N/O` 等动态公式列。默认参数就是当前梵呗考勤表：

```json

  "course_name": "d260509梵呗初阶"

```

### A1 坐标写入

如果脚本已经知道可见表格坐标：

```python
resp = s.patch(
    f"{mf}/api/note-sheets/sheets/6/table",
    params={"workbook_id": 3},
    headers={"X-Device-Token": token},
    json={
        "operations": [
            {
                "type": "write_range",
                "cell": "Q4",
                "values": [[1], [0], [1]]
            }
        ]
    },
)
```

当 `cell` 落在数据区之前，会写 `grid_rows`；落在数据区之后，会写 `rows` 并自动同步 `grid_rows` 的数据区。

## workbook=2 sheet=4 的本次操作建议

`workbook=2&sheet=4` 是 `codepc_mf` 上的课程汇总/入口页。课程脚本不直接理解前端页面 DOM，而是按下面流程处理：

1. `codepc_mf` 调度器到点后，启动 mf 上的目标课程子进程。
2. 课程脚本读取 `GET http://127.0.0.1:8000/api/note-sheets/sheets/4/table?workbook_id=2`，找到目标课程行。
3. 课程脚本根据这行配置确定课程名、课次链接数、打卡链接数、负责人等信息。
4. 同一 mf 进程使用本机小鹅通登录态采集，并通过表格 API 回写课程工作簿。
5. 课程脚本把统计结果回写 `codepc_mf`：
   - 课程汇总页：回写 `课次链接 / 打卡链接 / 备注` 等状态。
   - 具体考勤表：回写用户打卡列、退款统计列、状态说明行。

业务脚本保留在 `xlproject/src/xlsln/kq5034/courses`，数据通过 CodeYun sheet table API 读写。

## 用户清单与支付账单

用户、支付主数据采用“mf 采集、mf 保存和查询”的本地数据流：

```text
mf 小鹅通/微信支付浏览器
  -> 下载原始 CSV
  -> POST mf /api/device-control/attendance/master-data/import
  -> mf 保存不可变原文件
  -> mf 解析到 attendance_user / attendance_payment_ledger
  -> mf 生成 attendance_payment_order 查询投影
  -> 报名表用户 ID、订单信息匹配直接查询 mf 本地数据库
```

导入使用 multipart 文件，不复用视频/打卡的 3 小时短期缓存。接口按“数据类型 + 范围 + 文件 SHA-256”幂等；mf 采集端只有收到本机 CodeYun 成功响应后才清理临时副本。

```text
POST /api/device-control/attendance/master-data/import
GET  /api/device-control/attendance/master-data/status
```

当前数据类型与范围：

- `xiaoe_users`，范围为 `shop:1` 或 `shop:2`。
- `wechat_pay_ledger`，范围为 `merchant:1599622041`。

原始文件保存在 mf 的 `CODEYUN_DATA_DIR/attendance/master-data/raw/`。用户表按 `(shop_id, xiaoe_user_id)` 唯一；支付流水按 `(merchant_id, voucher_id)` 唯一；订单投影按 `(merchant_id, flow_order)` 唯一。原 CSV 的额外字段保留在 `source_payload_json`，日常匹配走规范化索引字段。

迁移观察期内，PG 的 `user_table / weipay_table / weipay_matview` 只作为只读核对源，不再属于 CodeYun 日常运行路径。确认一段时间无差异后再单独决定是否改名或删除。

## 订单查询与退款接口

报名表的常规用户/订单匹配直接使用 mf 本地 CodeYun 主数据。只有需要微信支付网页实时核验或执行退款时，才由配置为 `codepc_mf` 的高层接口调用本机浏览器自动化；业务代码不要绕过接口直接调用 `kq5034.order_ops` 或 `backend.core.attendance.order`。

日常脚本和 AI 排查统一调用 CodeYun 高层接口：

```text
POST /api/attendance/order-execute
POST /api/attendance/order-refund-details
GET  /api/attendance/order-refund-history
```

调用路径是：

```text
codepc_mf /api/attendance/order-execute
  -> 根据考勤配置选择 execution_device_entry_id
  -> codepc_mf 本地执行设备
  -> mf 执行微信支付网页实时核验或退款

codepc_mf /api/attendance/order-refund-details
  -> 根据考勤配置选择 execution_device_entry_id
  -> codepc_mf 本地执行设备
  -> mf 查询微信支付退款明细
```

`/api/attendance/order-execute` 的典型查单请求：

```json
{
  "action": "inspect",
  "rows": [
    {
      "微信支付订单号": "4200000000000000000000000000",
      "商户订单号": "MA2026070100000000000000"
    }
  ],
  "order_lookup_mode": "browser_only"
}
```

`/api/attendance/order-refund-details` 的典型退款明细请求：

```json
{
  "order_id": "MA2026070100000000000000",
  "query_type": "auto"
}
```

这两个接口默认使用考勤配置里的全局执行设备；当前必须配置为 `codepc_mf`。只有在实现或测试这些 API 自身时，才可以碰底层 `backend.core.attendance.order` 兼容桥或 `kq5034.order_ops`。

## 分层约束

- `codeyun` 在 mf 负责设备鉴权、运行入口和星云表格读写接口。
- `codeyun` 在 `codepc_mf` 保存用户与支付主数据，并承担报名表用户/订单匹配；日常运行代码不再读取旧 PG 考勤表。
- `xlproject/src/xlsln/kq5034` 在 mf 负责小鹅通/微信支付采集、原始 CSV 导入、课程脚本和业务步骤编排；不再把用户或支付数据写入旧 PG。
- `pyxllib` 只沉淀跨项目通用工具；不要让 `codeyun` 依赖旧 `D:\home\chenkunze\slns\kq5034` 仓库口径，当前业务实现应以 `xlproject/src/xlsln/kq5034` 为准。
- 如果某段逻辑只服务某个课程步骤，放在 `xlproject/src/xlsln/kq5034/courses` 或 `xlproject/src/xlsln/kq5034` 功能层；不要放进 CodeYun API。

## 注意事项

- 本地 API 调用仍建议 `requests.Session().trust_env = False`，避免系统代理影响 `127.0.0.1/codepc_mf`。
- `PATCH /table` 支持多操作一次提交，能减少中途失败导致的半更新。
- 长耗时爬虫应使用 `POST /python-runs` 的 `"async": true`，前端或调度器轮询 `run_id`。
- 表格写入应优先使用字段名和 key 字段匹配，不要依赖 UI 滚动位置。
- 如果仍有配置或日志指向 `codepc_mi15`，按迁移未完成处理；修正 mf 的代码、存量配置或文档，不等待旧设备恢复。
