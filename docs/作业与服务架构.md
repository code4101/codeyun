# 作业与服务架构

## 不变量

- 作业是一次有明确输入、终态和结果的执行事实，不等同于进程；耗时或需要恢复的作业由独立 Local Worker 执行。
- 服务是长期存活的独立进程，拥有独立的启动、停止、健康检查、日志和重启策略。
- CodeYun API、Scheduler 和 CLI 只提交白名单 `job_type + payload`，不得传入任意命令、模块名或 Python callable。
- 每次 Local Job 都必须先持久化 `LocalJobRun`，再启动 Worker；状态、PID、心跳、取消命令、结果和错误不依赖 Web 进程内存。
- 取消请求是命令事实 `cancel_requested_at`，不是运行终态；Worker 安全退出后才写入 `cancelled`。
- Worker 进程消失属于执行通道中断，应投影为 `interrupted`，不得伪装成业务逻辑 `failed`。
- 规则定义、触发命令、运行状态和 UI 投影分层：Scheduler 只负责规则求值，Local Job 层只负责一次运行。
- 命令条目只表示服务；`runtime_kind=job` 的命令条目不再执行。
- 服务监控不进入作业队列；定时启动服务仍属于服务控制命令，不产生 JobRun。

## 目录边界

```text
backend/core/jobs/
  scheduler.py   规则求值与到期触发
  local_runtime.py  LocalJobRun、白名单注册、资源锁、持久状态和 Worker 启动
  local_worker.py   独立一次性 Worker 入口
  local_handlers.py 内置白名单作业注册
  executor.py    旧进程内队列；迁移期只承载尚未迁走的短任务
  models.py      作业执行策略与投影

backend/core/services/
  monitor.py     常驻服务观察与恢复
  launcher.py    唯一的隐藏进程启动入口
  _subprocess.py Windows/POSIX 进程启动细节
  models.py      服务定义、策略与观测状态
  policy.py      命令服务策略与分组
```

共享只发生在 API/UI 投影层。Local Job 和 Service 不共享执行器、队列或生命周期状态。

## Local Job 基础模型

```text
JobSpec（静态白名单）
  job_type / handler / resource_key / cancellable

提交命令
  API | Scheduler | CLI -> create LocalJobRun -> launch local_worker --run-id

LocalJobRun（持久事实）
  queued -> running -> succeeded | failed | cancelled
                    -> interrupted（执行通道消失）
```

- `resource_key` 是正交资源边界，不是业务状态。例如媒体浏览器、GPU、仓库和设备分别使用不同锁。
- 同一资源的 Worker 等待文件锁；不同资源可以并行。
- 业务 handler 只接收 `LocalJobContext + JSON payload`，通过 context 写心跳并检查取消。
- stdout/stderr 写系统临时目录；业务结果写 `LocalJobRun.result_json` 或业务自己的派生快照。

## Windows 控制台规则

- `codeyun-dev.cmd -> uv run dev.py` 是用户可见的主控制台。
- 后端使用普通 `python.exe -m uvicorn backend.app:app` 并继承主控制台，不再使用 `pythonw` 或 `uvicorn_hidden`。
- CodeYun 后端不得全局 monkey-patch `subprocess.Popen`。
- 只有独立服务入口可以安装服务进程树的无窗口策略。

## 作业注册规则

新增耗时作业必须注册为 Local Job 白名单 handler。调度器只负责判断到期并提交 `job_type + payload`，不接受命令字符串。

如果能力需要外部长期进程，应先注册为 Service，再由作业调用该服务的客户端/API；Local Job 不负责维持长期守护进程。如果现有流程只能通过任意临时命令实现，则在抽成白名单应用能力或 Service 之前不得加入作业目录。

## 已删除的旧路径

- 两份并行的 `background_task_runner` 实现。
- `runtime.units` 中依靠名称和命令猜测 job/service 的混合模型。
- `TaskManager.enqueue_task_run` 命令作业执行链。
- 作业队列里的常驻服务自检。
- `pythonw + backend.core.runtime.uvicorn_hidden` 后端入口。
- 后端进程级 `subprocess.Popen` 全局补丁。
- 前端“自定义命令作业”入口。

旧源码只保存在仓库外归档，不参与导入、测试、构建或部署。
