# 部署运维备忘

本文档记录当前 `codeyun` 项目已经验证过的部署链路、常见故障和日常核对方法。

## 1. 当前自动部署链路

- GitHub Actions workflow：`.github/workflows/deploy-ubuntu24.yml`
- 远端更新脚本：`deploy/update.sh`
- 服务器服务管理：系统级 `systemd` 服务 `codeyun-backend`

当前真实流程：

1. push 到 `main`
2. GitHub Actions 通过 `appleboy/ssh-action` 登录服务器
3. 远端执行 `deploy/update.sh`
4. `deploy/update.sh` 执行：
   - `git fetch origin main`
   - `git reset --hard origin/main`
   - `uv sync`
   - 按需重建前端
   - `sudo systemctl restart codeyun-backend`

## 2. 配置边界

- 服务器运行时 `.env` 只放应用配置，不放 SSH 登录信息。
- SSH 登录信息的职责划分：
  - 本地 `.env`：方便本地排障、运维脚本连接服务器
  - GitHub Actions Secrets：自动部署使用
- `CODEYUN_DATA_DIR` 可选：
  - 不配置时，后端默认使用 `backend/data/`
  - 只有明确要把数据移出仓库目录时才需要配置

## 3. 本次排障沉淀

### 3.1 SSH 私钥错误

典型报错：

- `Error loading key "(stdin)": error in libcrypto`

通常原因：

- GitHub Secret 中的私钥内容格式损坏
- 粘贴了错误的密钥
- 换行丢失

处理原则：

- 优先重新粘贴完整原始私钥
- 如果旧私钥来源不可信或已丢失，直接重新生成一对新的 `ed25519` 部署密钥

### 3.2 SSH 指纹校验问题

典型报错：

- `ssh: handshake failed: ssh: host key fingerprint mismatch`

实践结论：

- `appleboy/ssh-action` 的 `fingerprint` 虽然可用，但在当前组合下容易引入额外不稳定性
- 当前 workflow 已移除 `fingerprint` 配置，优先保证部署链路稳定

如果将来重新启用指纹校验，必须重新验证 action 实际协商到的 host key 类型。

### 3.3 systemd 服务口径不一致

历史上仓库里曾同时存在 `systemctl --user` 和系统级 `systemctl` 两套说法。

当前已确认的真实线上口径是：

- 使用系统级服务：`codeyun-backend`
- 常用命令：
  - `systemctl status codeyun-backend`
  - `sudo systemctl restart codeyun-backend`
  - `journalctl -u codeyun-backend -f`

### 3.4 Action 成功但前端没更新

这个问题已经真实发生过。

根因：

- 服务器代码虽然更新了，但 `frontend/dist` 没有随之重建

当前解决方式：

- `deploy/update.sh` 现在通过 `dist/.codeyun-build-commit` 判断前端构建是否已匹配当前提交
- 若当前提交涉及前端变化，或缺少构建标记，则自动重新 build

## 4. 部署验收清单

不要只看 GitHub Actions 是否成功，至少再核对下面几项：

1. 服务器仓库 HEAD 是否等于当前目标提交
   - `git -C /home/chenkunze/slns/codeyun rev-parse HEAD`
2. 服务是否启动
   - `systemctl is-active codeyun-backend`
3. 服务是否刚刚按新版本重启
   - `systemctl status codeyun-backend`
4. 后端是否能响应
   - `curl -I http://127.0.0.1:8000/docs`
5. 前端静态产物是否为新构建
   - `stat frontend/dist/index.html`
   - `cat frontend/dist/.codeyun-build-commit`

## 5. DSP 静态资源同步

戴森球子项目静态资源同步统一使用：

```bash
uv run python scripts/build_dsp_static.py
```

当前脚本行为：

- 基于 `dsp-calc` 源码内容和依赖清单计算指纹
- 指纹未变化时，直接跳过
- 指纹变化时，自动：
  - 安装依赖（如需要）
  - 执行 build
  - 替换 `frontend/public/dsp-calc`
  - 写入本地状态文件 `frontend/.codeyun-state/dsp-calc.json`

强制重建命令：

```bash
uv run python scripts/build_dsp_static.py --force
```

补充说明：

- 即使 `dsp-calc` 仓库是 dirty working tree，只要源码内容没变化，脚本也会正确跳过
- `frontend/.codeyun-state/` 已加入 `.gitignore`，不会污染正常提交
