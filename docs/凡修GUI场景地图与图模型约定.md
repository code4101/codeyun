# 凡修 GUI 场景地图与图模型约定

> Last Updated: 2026-08-11
> 本文是凡修 GUI 接入中场景帧、识别分层、识别图、弹窗插入和场景移动的唯一权威正文。其它文档只说明各自模块如何消费本模型，不再重新定义识别语义。

## 一、核心对象

### 场景帧 scene/frame

`scene/frame` 是资产树中一个可识别、可操作的场景节点，例如 `#34 世界`。它同时保存：

- 一张用于标注和全图相似度比较的参考画面；
- 若干 Shape；
- 场景身份 Shape；
- 可操作 Shape 及其真实后继场景频次。

为避免和实时输入混淆，本文把运行时刚取得的画面写作“直播帧 `x`”。业务 API 可以继续使用 `scene`，资产标注和识别算法可以使用 `frame`；二者指向同一个场景节点，不得再把资产 frame 限定解释为只有截图字节。

### Shape

一个场景帧可以包含多个 Shape。Shape 可以有版面结构嵌套关系，用于表达：

- 滚动窗口及其中的重复条目、字段和操作点；
- 场景身份；
- 场景跳转动作；
- OCR、图像匹配、抠图、mask、阈值和其它识别参数；
- 业务参数配置。

Shape 的版面嵌套只表达当前场景帧内部的局部结构，不生成场景识别图的边。场景帧之间的识别关系只由图模型计算，跳转关系只由真实动作落点频次表达。

### 场景地图

所有场景帧和 Shape 动作的后继场景共同构成功能逻辑“场景地图”：

- 场景帧是节点；
- 可操作 Shape 是动作；
- `sceneJumpTarget` 是动作到真实后继场景的观测频次。

资产树的一级业务目录统一为 `日常 / 周常 / 资源 / 日程 / 活动`，其分类语义以[凡修 data-annotation 命名约定](./凡修data-annotation命名约定.md)为准。目录只用于人工组织和业务归档，不生成识别边，也不等同于 Scheduler 触发频率。

场景地图可以人工标注，也可以由 AI 在保存真实证据、原节点摘要和备份并完成真实验证的前提下自主新增、修改、移动或删除。

场景地图只回答两个问题：当前直播帧最像哪个 scene，以及从当前 scene 到目标 view 下一步应点击哪个 Shape。它不保存作业进度，也不解释上一次动作意图。作业被打断或失败后，由仍然到期的 `next_time` 自然触发下一次完整运行；新一轮只重新观察当前 scene，并用 `go_scene` / `goto_view` 到达本轮目标。

## 二、识别分层

分层只决定本轮按什么顺序检索候选，不表达父子场景、资产目录层级或继承关系。

1. **Layer 0**：动态业务候选。由当前步骤预设的场景清单产生；没有业务上下文时跳过。一次等待的前 `min(wait_seconds / 2, 5)` 秒只匹配业务候选，之后才把守护弹窗候选加入同一次识别图裁决；`wait_seconds=0` 时立即加入。
2. **Layer 1**：关键帧。交通枢纽和 App 的典型主菜单页面。
3. **Layer 2**：其余具有场景标识的场景帧。
4. **Layer 3**：没有场景标识的辅助参考帧；只有资产编号，不具备可供业务或导航消费的场景 ID 语义。

Layer 0～2 只处理具有场景标识的候选。Layer 3 不参加场景标识图匹配，只在前面各层无法确定结果时，使用参考画面的全图相似度提供“当前 unknown 更像哪张参考帧”的诊断信息。无论相似度多高，Layer 3 都不得输出 scene id、成为导航节点、记录为真实动作落点或打断连续 unknown。

## 三、识别图

### 建图规则

设场景帧节点为 `a`、`b`。若 `b` 的参考图满足 `a` 的全部场景标识 Shape，则建立有向边：

```text
a -> b
```

场景身份 Shape 可以使用 OCR、图像匹配、抠图和 mask 等能力。一个场景帧存在多个 required 场景标识时按 AND 聚合。

资产目录、frame children、Shape 继承、文件名、业务编号和人工分类均不得直接生成识别边。

### 直播帧识别

对于直播帧 `x`：

1. 在当前 Layer 的候选中，计算哪些候选的场景标识满足 `x`，即得到所有具有 `candidate -> x` 的节点集合 `S`。
2. 取 `S` 内节点及它们之间已有的全部识别边，构成匹配子图 `G`。
3. 按“就近原则”选择最具体节点。若 `a -> b -> x` 且 `a -> x`，则 `b` 比 `a` 更接近 `x`，结果为 `b`。
4. 图距离仍并列时，使用候选参考图与直播帧的全图相似度裁决。
5. 仍无法稳定区分时返回 `ambiguous`，不得按资产顺序、编号、目录或业务类型任选一个。

默认 Layer 1/2、动态 Layer 0 和弹窗候选必须调用同一个评分、建图、子图求解和歧义判定实现，不能保留第二套识别器或后置改判逻辑。

### OCR 使用边界

凡修禁止业务层、守护层、导航层和诊断层直接消费整张直播帧的 OCR 结果。OCR 只能作为 scene/shape 图模型中的空间证据：先由统一识别图确定 scene，再只向业务返回与该 scene 已标注 Shape 相交的文字或 token。底层 OCR 引擎可以为性能对同一直播帧只检测一次，但共享缓存必须经过 Shape 空间查询后才能离开识别层；“缓存里是全帧结果”不构成业务层读取全帧 OCR 的授权。

以下做法一律禁止：

- 整帧 OCR 命中文案后覆盖图模型给出的 scene id；
- 用整帧 OCR 搜索按钮并直接取文字框中心点击；
- scene/shape 缺失时把裁剪 OCR 悄悄回退为整帧 OCR；
- 弹窗守护、登录维护、断线恢复、unknown 证据或 debug Cell 另建全帧 OCR 旁路。

缺少正式 scene、身份 Shape 或动作 Shape 时必须安全失败、保存原始帧并补资产；不得以提高兼容性为理由猜场景或猜坐标。

### 整体识别等待

Layer 1～2 是单帧场景身份识别管线，不在层与层之间固定等待。每张直播帧先执行
Layer 1 → Layer 2；任一层得到可靠结果便立即结束本轮。两层均无可靠 scene id 时，
Layer 3 只追加辅助相似信息，完整结果仍为 `unknown`。调用方随后进入可配置的整体等待窗口，并在窗口内
持续获取新直播帧、从 Layer 1 重新执行完整管线：

- `wait=0`：使用当前帧的完整管线结果；
- `wait=5`：完整管线失败后，在 5 秒内用新直播帧重新识别；
- `wait=300`：完整管线失败后，在 5 分钟内耐心等待稳定画面。

`go_scene` 把 unknown 视为观察结果，不视为可导航节点。稳定的 Layer 1/2 场景
在首次命中时立即返回；每次未命中后显式等待 0.5 秒、获取新直播帧，并从
Layer 1 重新执行完整管线。只有 Layer 0/1/2 产生的可靠 scene id 才能结束 unknown
观察并从该 id 重新规划；Layer 3 相似分数、identity 层弱分数和没有 scene id 的
`ambiguous` 都仍属于 unknown。连续 60 秒没有可靠 scene id，且第 60 秒当前帧仍无
可靠 scene id，才产生一次 `#424` 恢复资格。

连续计时从本次观察已经持有的首张直播帧开始。整体观察上限与连续 unknown 门槛
可以同为 60 秒，但不得等第一次识别计算结束后才启动连续计时，否则整体上限会
稳定地先到期，使 #424 永远无法获得资格。

业务动作已经声明预期落点时，Layer 0 使用独立的高置信等待窗口，默认 30 秒。
窗口内同样每 0.5 秒显式等待并获取新帧，不依赖外部行为树 tick 的偶然节奏；
Layer 0 窗口耗尽后才允许回到通用分层识别和重新规划。

Runtime 的 `layer0_wait_seconds` 默认值为 30 秒。只有业务明确存在长加载、长动画或长战斗过场时，才在该动作边上显式覆盖为 180 秒；不能为了某一条长路径提高全局默认值。长过场的 Layer 0 只放当前阶段的合法目标，例如镇邪 `#63[前往]` 后只等待 `#271`，不能把后续内部页或通用离场页混进同一候选域。

等待期间必须持续获取新直播帧，不能反复计算旧截图。业务窗口或明确过渡截止时间可以覆盖普通等待值。

## 四、Layer 3 与 unknown

Layer 3 通过全图相似度比较没有场景标识的参考帧。它可以保存最相似参考帧的资产编号、分数和诊断阈值，用于 unknown 归并、补标和复盘；这些字段始终是辅助证据，不是 scene id。即使达到 `layer3SimilarityThreshold`，结果仍为 unknown，不得把相似布局提升为确定场景。

unknown 的处理策略由业务配置决定：

- 保存直播帧、候选分数、OCR、裁剪和稳定性证据；
- AI 自动生成新的场景帧/Shape 候选，或在明确允许的工作流中新增正式标注；
- 使用一个兜底 frame 的通用低风险处理策略。

普通业务 `wait_view / wait_scene` 超时属于一次有明确候选范围的等待失败，
其同步诊断只能比较“本次期望节点 + 最后已识别节点”，不得在抛出超时前
遍历整棵资产树、逐帧做全图相似度。全树 unknown 归类是显式诊断/探索流程，
必须与业务等待的截止时间和 Kernel 执行预算解耦，不能把 12 秒等待放大成
数分钟计算和数 GB 内存占用。

凡修使用 `#424` 作为通用导航兜底动作宿主。它不参与场景识别，也不把当前画面识别为 `#424`；只有连续 60 秒没有 Layer 0/1/2 的可靠 scene id 时，导航层才可以把 `#424` 的低风险动作投影到第 60 秒这张当前帧。Layer 3 辅助参考编号不能阻断或替代该资格。识别到任何可靠 scene id 都必须从该 id 重新规划；已知场景缺路属于场景图缺陷，不得冒充 unknown 使用 `#424`。每次动作后必须重新开始连续 unknown 计时，并从 Layer 0 开始识别、从真实落点重新规划；动作保留次数上限和总时长上限。不得使用 Android Back 或 Esc。

AI 可以自主修正已有 scene、Shape 和识别关系。自动探索只修改本次证据能证明的最小节点集合；修改前保留原节点和树版本，修改后必须用当前帧与相邻负样本回放，不能借探索批量整理无关资产。

## 五、弹窗是插入流程

不定期弹窗场景帧统一收录在“弹窗”目录。业务 Layer 0 等待的前 `min(wait_seconds / 2, 5)` 秒不注入守护弹窗；之后业务候选与弹窗候选进入同一识别图，避免相似画面被分两次识别后互相推翻。业务显式声明的弹窗仍属于业务候选，前段照常参与。

进入中断候选集还必须满足一个前提：节点同时具备场景标识和可执行的后继动作。仅仅位于“弹窗”目录、却没有关闭、确认、返回等可执行动作的 frame，只是待补全资产，不能注入 Layer 0 抢占业务场景识别。

中断处理必须执行候选索引时已经选定的那一个标注动作，不得在执行阶段再调用另一套关闭规划器重新选择。“确定”和“确认”都是可用的确认动作命名；是否允许自动点击，以该节点是否被明确收录到“弹窗”目录并声明为后继动作为准。

识别图选择弹窗节点后：

1. 执行该弹窗节点声明的后继操作；
2. 获取新的直播帧；
3. 回到完全相同的业务 Layer 0 + 弹窗候选重新识别。

弹窗操作是对主业务流程的“插入”，不是“替换”。弹窗代码不得保存另一套当前业务场景，不得在图裁决后按编号、分数或业务类型二次否决结果。

“弹窗”目录表示该节点默认具备中断处理动作，不表示它永远只能当中断。同一个节点若被当前业务步骤显式列为预期状态，例如确认框本身就是业务流程的一步，则统一图仍返回同一个 scene id，但由当前业务消费该节点，不执行默认中断动作。这是图裁决后的动作归属，不是对场景身份二次改判；调用方不得把整批弹窗节点顺手声明成业务候选。

## 六、通用场景移动

`go_scene(target)` 是所有业务共享的场景移动原语。每一步固定执行：

```text
识别当前场景
  -> 根据场景地图和后继频次选择动作
  -> 执行 Shape
  -> 等待并识别真实落点
  -> 累计真实落点频次
  -> 从真实落点重新规划
```

`sceneJumpTarget` 记录一个 Shape 的真实后继场景及频次，例如 `282(6),20(1)`。一个 Shape 的后继不保证唯一；新落点和自环都必须按一次真实动作记录一次。

`#34` 是常用导航锚点，不是强制初始状态。作业可以为了降低风险显式先回 `#34`，但这只是该作业自己的导航选择；规划器本身以“当前识别到哪里”为起点，已知场景按图规划，unknown 只走有界兜底探索。

路径规划将频次归一化为动作后的条件概率先验，并结合“到目标的图距离、失败边、连续自环和动作风险”选择下一步。频次是贝叶斯先验，不是允许落点白名单；观察到此前没有的新落点时应新增频次并从真实落点重规划。

规划器遵循动态单步原则，不预先锁定完整路径。它只计算“当前执行哪个 Shape，下一真实落点更接近目标”的后验概率：先在安全场景图上计算各节点到目标的最短层数，再把 Shape 的 `sceneJumpTarget` 频次通过带一个 unknown 桶的 Dirichlet 后验折算为落点百分比；只有距离严格缩短或直接到达目标的落点计入该 Shape 的本轮进展权重。执行后必须读取真实落点，再从新场景重新计算下一步。

候选安全 Shape 按单步进展权重随机选择，因此不会固定死一种走法；例如权重 10% 与 50% 的两个动作，选择比例为 1:5。历史频次会持续修正后验：大量稳定成功记录会稳压只有一次的偶发落点，脏数据不会被删除，但其选择概率会随正确数据积累迅速降低。不得因为某落点在静态图上“最终仍可达目标”，就把该落点的全部历史频次算成本步成功；否则 `A -> B -> A` 循环会借一个极小概率出口错误放大。

场景移动只消费统一识别图输出和场景地图，不复制 OCR 文案、业务场景判断或私有返回链。凡修可稳定停留并交互的场景原则上都有返回、关闭、取消、离开或等价的安全离场逻辑；场景图没有记录这条逻辑，表示资产或工程知识不完整，不表示游戏存在“死胡同”。静态图无路时可以有界尝试当前已知场景自身已标注的低风险导航动作；当前节点没有此类动作或全部耗尽后，应保留现场并把缺失的离场动作交给 AI 取证、补标和真实验收，不得把已知场景降级成 unknown，也不得据此暂停其它工程作业。只有连续 60 秒完整识别始终为 unknown 时，才有界投影一次 `#424` 通用返回动作；动作后重新开始一分钟观察。

Layer 1 关键帧属于稳定导航枢纽。若已经可靠识别为 Layer 1，但场景图没有到目标
的路径，必须直接保留现场并报告缺路径；禁止把“空白”或 `#424` 投影到枢纽上
猜测点击。`#424` 通用返回只用于真正 unknown；已知场景缺少返回边时修复该场景自己的正式资产。

### 导航停滞与人工复盘

导航停滞不能只用“scene id 多久没变”判断。当前框架采用组合证据：

- 同一 `go_scene` 目标；
- 同一可靠识别场景；
- 同一语义 Shape 动作重复执行；
- 真实落点仍为源场景，没有向目标推进；
- 动作前后直播帧主体相似度不低于 95%。

同一稳定画面上的同一边连续 2 次无效后，本状态淘汰该边；同一语义边跨动态画面累计 3 次无效后，本轮全局淘汰该边。`#424[返回]` 每次只消费一段完整的连续 60 秒 unknown；点击后重新计时，本次导航最多尝试 4 次。一次活跃导航累计 10 分钟或达到 24 个重规划步骤时，无论此前是否仍有动作候选，都必须结束本次恢复。

下列任一事实会创建持久化“导航停滞事件”：稳定自环成立、连续一分钟 unknown 后开始使用 `#424`、有界恢复耗尽、10 分钟硬上限或 24 步上限。事件一旦触发立即写入当前 entry 的 `recognition-ops/navigation-incidents/<事件编号>/`，随后增量追加动作和结果；Cell 中断也不能丢失已写证据。

每个事件至少保存：

- 任务、Cell 对应的 task id、Kernel generation、目标场景、触发阈值和最终返回状态；
- 动作前后真实帧、识别 scene/score、Shape、动作选择理由、真实落点、画面相似度；
- 候选场景、各场景身份 Shape 分数、OCR 文本和身份区域裁剪图；
- 资产树路径、修改时间、SHA-256 与事件涉及场景的当时标注快照；
- 完整动作时间线和 `#424` 是否参与恢复。

事件的 `review_status` 默认始终为 `pending`。即使业务后来成功并得到 `recovered_with_fallback` 或 `recovered_after_stall`，事件也保留在“识别运维 / 运行停滞”问题集中，不能因业务成功而删除。

## 七、模块边界

- **标注层**：保存 scene/frame、Shape、局部结构、匹配参数和后继频次。
- **识别层**：负责整体等待、评分、识别图、最近节点、相似度和 unknown。
- **导航层**：负责基于场景地图与概率先验逐步重规划。
- **行为树**：只表达“当前应做什么”和业务完成判据。
- **Scheduler**：只决定何时提交哪个 Cell，不识别画面、不点击、不保存业务步骤。

业务代码不得用专用 OCR、编号优先级、目录身份或直接复用其它场景 Shape 来修补统一识别结果。发现统一能力不足时，应修识别层、导航层或标注模型，并用真实业务场景回归。
