# CodeYun 模块说明

[English](modules.md)

本文整理 CodeYun 中适合公开介绍的通用模块。主 README 负责快速概览；本文进一步说明每个模块的功能边界、适用场景，以及本地安装使用方式。

## 安装与启动

CodeYun 是一个 Python + Vue 的 monorepo。所有命令默认在仓库根目录执行。

```bash
uv sync
npm install --prefix frontend
uv run dev.py
```

启动后访问：

- Frontend: http://localhost:5173
- Backend API docs: http://localhost:8000/docs
- 公开官网：https://code4101.com/

常用检查命令：

```bash
uv run pytest
npm run check --prefix frontend
uv run python scripts/check_prod.py
```

## 星图笔记

![星图笔记日历视图](assets/星图笔记.png)

星图笔记不是普通文本存储，而是面向结构化知识工作的笔记系统。

核心能力：

- 将笔记作为实体、关系和类别来管理。
- 用统一的规则程序在不同视图中筛选数据。
- 区分后端筛选和前端可见性筛选。
- 支持日历、图谱、列表等不同工作流。
- 每个 tab 保留自己的视图状态，同时共享实体缓存。

适用场景：

- 个人知识管理。
- 项目日记和工作日志。
- 代码、文档、周期性工作流的主题地图。
- 基于日历回顾重要笔记和活动聚类。

## 表格工作流

CodeYun 包含面向表格数据的导入、重建、校验和 API 访问能力。

核心能力：

- 将结构化表格数据导入后端管理的数据存储。
- 通过可重复脚本重建派生工作簿或数据集。
- 用测试覆盖访问规则和表格行为。
- 通过 API 和前端页面暴露表格驱动的数据能力。
- 将可复用数据操作沉淀为脚本，而不是一次性手工编辑。

适用场景：

- 小型内部数据工具。
- 可重复的工作簿生成。
- 数据迁移与校验。
- 将表格操作转化成可维护的后端工作流。

相关实现主要分布在 `scripts/`、`backend/api/`、`backend/core/` 和 `docs/` 中的表格相关文档。

## 集群与任务管理

![集群与任务管理面板](assets/集群管理.png)

集群模块提供一个统一界面，用于管理本地和远程进程。

核心能力：

- 注册本地和远程设备。
- 在统一 UI 中启动、停止和检查任务。
- 持续查看 CPU、内存等资源使用情况。
- 收集任务状态和日志。
- 将长驻服务与开发服务器生命周期分离。
- 定义周期作业，同时避免把本机个人调度直接写死进源码。

适用场景：

- 管理工作站或小型 homelab 上的自托管服务。
- 监督后台 Python 脚本、同步工具、Web 服务和实用进程。
- 在不引入大型监控系统的前提下获得基础运维可见性。

## 作业系统

作业系统面向可复用作业类型，而不是写死的个人定时任务。

核心能力：

- 将可复用作业类型加入目录。
- 将执行逻辑保存在源码中。
- 将是否启用、定时策略和下次触发时间保存在本地数据配置中。
- 保持新机器部署时的清爽状态，不继承个人机器上的作业清单。

适用场景：

- 周期清理。
- 数据同步。
- 报告生成。
- 维护检查。

## 可视化与实用工具

![可视化生产规划工具](assets/戴森球.png)

CodeYun 可以在同一个前端壳中承载专用工具页面。

核心能力：

- 添加领域专用计算器和规划器。
- 复用统一布局、路由、权限和部署约定。
- 让独立工具可以从平台导航中发现和使用。
- 按需要将可视化界面与后端 API、本地数据文件结合。

适用场景：

- 可视化规划工具。
- PDF/文件处理助手。
- AI 辅助工具页面。
- 诊断和开发效率工具。

## 项目结构

```text
codeyun/
├── backend/          # FastAPI 后端、API、服务和标准模块
├── frontend/         # Vue/Vite 前端
├── docs/             # 设计文档和模块说明
├── docs/assets/      # README 和文档图片
├── scripts/          # 维护脚本与数据工作流脚本
├── tests/            # 后端测试
├── dev.py            # 集成开发监督进程
├── pyproject.toml
└── AGENTS.md
```

## 开发说明

- 日常开发使用 `uv run dev.py`。
- 后端变更提交前运行 `uv run pytest`。
- 前端发布前运行 `npm run check --prefix frontend`。
- 生产式本地检查使用 `uv run python scripts/check_prod.py`。
- 公开文档优先描述通用模块，避免写入环境密钥、私有路径或个人账号数据。
