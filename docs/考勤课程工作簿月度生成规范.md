# 考勤课程工作簿月度生成规范

## 目标

考勤课程工作簿按月生成时，要继承上一套真实使用过的同类课程工作簿，再做目标月份适配。这里的“模板”不是固定静态模板，而是运营过程中持续迭代后的最近同类工作簿。

典型例子：

- 2026 年 8 月念住，应以 2026 年 7 月念住为模板，而不是固定回退到 2026 年 6 月念住。
- 2026 年 8 月觉观，应以 2026 年 7 月觉观为模板。

## 工作簿结构

一套课程工作簿通常包含：

- 考勤表
- 报名表
- 视频配置
- 视频数据
- 打卡配置
- 打卡数据

处理时必须以整套 workbook 为单位检查和修复，不能只根据用户指出的某一张表单点补丁。

## 模板选择规则

新月份生成时，模板来源按以下规则选择：

1. 只在同课程类型内选择模板，例如念住只继承念住，觉观只继承觉观。
2. 只选择目标月份之前已经存在的课程。
3. 在候选中选择开始日期最接近目标月份的一套。
4. 如果同一天存在多个候选，选择课程汇总表中更靠前或当前逻辑定义的稳定候选，不能随机选择。

这条规则保证后续运营中对 7 月做过的字段、权限、样式、隐藏列、按钮行、自定义配置等优化，8 月会自然继承。

## 继承与重置

应该继承：

- workbook 和 sheet 权限
- 报名表字段、标准字段样式、隐藏字段、按钮行
- 考勤表表头结构、样式、列宽、备注说明、通用超链接
- 视频配置、打卡配置的结构
- 自定义字段和业务配置

应该按目标月份重置或覆盖：

- 日期表头
- 课程届数和课程名称
- 视频 URL、视频课次数据
- 打卡 URL、打卡配置数据
- 运行时字段，例如当前应返款、最近运行更新时间、空数据行
- 由目标月份真实数据源决定的行数据

### 报名表导入字段规则

报名表导入时，标准字段和源表备注要分清：

- 源表如果有明确的 `备注`、`说明` 等备注语义字段，应导入到报名表 `备注`。
- 报名表标准字段包含 `海外`，用于标识海外/时差学员；建议填 `是` 或留空。
- 备注内容包括退课、退款、人工提醒等运营备注。源表写了海外/国外/国际学员/时差时，应同步到 `海外=是`，不要作为普通备注保留。
- 源表没有备注字段时，不强行生成备注，也不把普通可选字段猜测塞进 `备注`。
- 海外/时差学员不是分组标题，也不是普通可选字段；后续视频返款计算如果需要“回放天数前移/补返款”，由报名表 `海外` 标准字段、独立名单或课程规则显式处理，不能在报名导入阶段隐式改金额。
- 源表存在额外可选字段时，按导入表格动态增量生成可选字段；新 workbook 模板默认不预置这些可选字段。
- 订单字段必须按语义拆开：`微信支付订单号` 存微信交易单号，`商户订单号` 存商户侧订单号。源表表头写 `微信支付订单号` 但值是 `MA...` 时，应按值形态归入 `商户订单号`。

### 报名表到考勤表的标准同步

固定开班课程必须把报名表作为考勤名单权威来源，通过报名表标准动作形成闭环：

```text
报名导入 -> 更新订单匹配 -> 更新用户匹配 -> 综合更新 -> 考勤名单
```

`综合更新` 不是三个按钮的便捷组合，而是正式的一致性入口。它应使用 `backend/api/note_sheets.py` 中的订单匹配、用户匹配和 `_sync_registration_rows_to_attendance_document(...)`，统一保证：

- 报名表当前有效且未退课的身份行进入考勤表；
- `备注` 明确包含“退课”的行不进入考勤表，无论尚未退款、已经退款、无促学金或没有本期订单；
- 固定课程的早报名学员不套用滚动追踪表的“两个月过期”规则；
- 模板遗留、已不在当前报名表的考勤行被清除；
- `序号` 映射为考勤表 `学号`，按组号和组内号排序；
- 考勤表身份区至少覆盖 `分组 / 学号 / 姓名 / 昵称`，同组同色、不同组使用稳定浅色区分；返款和进度区保留自己的状态色。

同步完成后必须核对：

```text
考勤人数 = 报名表有效身份行数 - 退课行数
考勤身份集合 = 报名表当前有效且未退课的身份集合
```

复学学员没有本期支付订单可以是合理状态，不能因为订单为空把仍在读的复学学员排除。一次性数据库脚本只允许修复旧坏数据；同类规则必须进入标准同步函数和测试，避免下次综合更新再次破坏名单。

### 海外/时差学员视频返款规则

旧考勤脚本中存在 `shift_international_students(df2, user_list)` 规则，例如 `courses/d260501第46届觉观.py` 保留了“处理国外学生”的调用点。迁移到 CodeYun 后，这类逻辑应沉淀为课程级显式配置：

- 配置位置：优先使用报名表标准字段 `海外`；高级显式名单可写在 `视频配置.source_meta.international_student_user_ids`，并兼容 `overseas_student_user_ids`、`time_shift_student_user_ids`。
- 生效阶段：只在考勤表重建时对展示进度和视频返款计算生效，不改写原始 `视频数据`。
- 转换规则：`第1天回放` 视为 `当堂完成`；`第N天回放` 视为 `第N-1天回放`。
- 导入阶段应把源表里的海外/时差信息标准化到 `海外` 字段；考勤重建只读取 `海外` 字段或显式课程配置，不再依赖 `备注=海外` 推断。

### 课程类型差异

运行时 URL 和配置数据不是所有课程都用同一套继承规则。

- 念住、觉观：视频 URL、打卡 URL 必须来自目标月份真实数据源。旧库或真实导入源查不到时，应保留结构并清空配置，不能从上一月模板继承 URL。
- 禅宗、修道班：视频配置比较特殊，很多情况下可以继承上一套配置。后续实现这类课程时，应显式建立课程类型策略，而不是复用念住、觉观的“强制清空运行时 URL”规则。

因此代码里不能把“配置数据是否继承”写成全局固定规则；必须按课程类型解析优先级。

### 打卡活动选择规则

从小鹅通后台发现打卡活动时，必须把活动选择作为标准工程组件处理，不能临时手工拼 URL。

统一规则：

1. 先按目标月份、课程名、届数筛选候选打卡活动。
2. 如果候选里同时存在 `【中心教室】` 和 `【旁听教室】`，考勤只取 `【中心教室】`。
3. `【旁听教室】` 默认属于旁听/审阅用途，不进入打卡配置、打卡数据和返款统计。
4. 如果只发现 `【旁听教室】`，不能自动拿来替代中心教室，应返回空选择并报告告警。
5. 如果没有中心/旁听标识，且目标条件只匹配到唯一普通活动，可以使用该活动。

当前标准组件在 `backend/core/attendance/clockin_link_detector.py`：

- `detect_xiaoe_attendance_clockin_activities_browser(...)`：在小鹅通打卡后台采集活动列表并应用考勤选择规则。
- `choose_attendance_clockin_activities(...)`：纯规则函数，负责中心教室优先、旁听排除。
- `build_xiaoe_diary_list_url(...)`：根据 `activity_id/app_id/mini_middle_url` 生成导出可用的 `diaryList` URL。

## 历史月份原则

已结束月份默认视为静态历史数据，不参与未来自动更新。

例如 6 月念住结束后，不应因为 8 月生成逻辑变化而反复改写 6 月数据。历史数据可以做一次性修复，但自动生成流程不能依赖“持续维护旧月份”。

## 标准化检查清单

每次生成或修复课程工作簿后，至少检查：

- 考勤表：第 21 课仍属于正课区，附加课颜色从结营/分享课开始。
- 考勤表：不应残留重复的纯 `第01课` 这类废课次列。
- 考勤表：返款区表头样式、运行时字段、问题解答链接一致。
- 考勤表：人数等于报名表有效身份行数减退课行数；没有退课学员、模板遗留行或因早报名被误排除的学员。
- 考勤表：身份区按组稳定高亮，至少覆盖 `分组 / 学号 / 姓名 / 昵称`，返款和进度区不被分组色覆盖。
- 报名表：无错误合并表头，`关联用户ID` 是标准字段样式。
- 视频配置：目标月份正课有真实 URL，无 URL 的附加课不应强行生成。
- 打卡配置：使用目标月份真实打卡 URL。
- 权限：继承模板 workbook/sheet 权限。

## 代码边界

后续代码应保持这些职责边界：

- 模板选择：找到同类型、目标月份之前、最近的一套工作簿。
- 模板克隆：复制整套 workbook、sheet、权限和结构。
- 月份适配：平移日期、更新届数、重置运行时字段。
- 数据物化：从目标月份真实数据源导入视频/打卡数据。
- 规范化审计：整套 workbook 统一检查，避免单点修复。

不要把“固定某个月模板”写死在生成逻辑里。
