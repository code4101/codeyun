# 凡修行为树业务能力约定

本文面向后续 AI 和任务实现者，说明凡修行为树已经或应当提供哪些可复用业务能力、适合解决什么问题。这里不描述底层 safe area、截图哈希、tick 推进等实现细节；任务代码只需要理解这些行为树能力能用来完成什么。

## 使用原则

- 业务任务优先调用已有行为树能力，不在单个任务里手写固定坐标、固定滚动次数或固定页面位置。
- 如果能力缺失，任务应报告“缺少行为树能力或标注”，而不是在任务代码里临时补一套不可复用逻辑。
- 拜谒、日常任务、活动列表、商店、背包、排行榜等都应复用同一类滚动窗口能力，而不是各自发明查找方式。

## 通用能力

### 场景移动

用于从当前已识别场景移动到目标场景。

任务只需要声明目标场景；Runtime 根据资产树里的场景身份、shape 和 `sceneJumpTarget` 规划并验证跳转。若跳转落点未声明或场景无法识别，应中断并交给人工补标。

### 弹窗与遮挡处理

用于处理公告、活动提示、确认框、空白遮罩关闭区和其他会阻塞主任务的浮层。

业务任务不应自行连续点击关闭按钮；应依赖行为树守护或已声明的弹窗处理能力，并在处理后复核当前场景。

### 滚动窗口安全查找与安全点击

用于在滚动容器中查找目标条目，并在确认可操作后点击。

适用范围包括日常任务列表、活动列表、商店、背包、排行榜、邮件列表、弹窗内滚动区域等。业务任务只应描述要找的目标、可接受的 OCR/图像匹配条件、需要读取的字段和点击意图。

该能力应保证：

- 不把固定遮挡区里的 OCR 污染文本当作稳定业务事实。
- 命中目标但条目处于不安全位置时，只作为候选，不直接点击。
- 候选条目需要复核为同一目标后，才输出可点击结果。
- 滚动查找基于容器和条目结构，不依赖目标在第几屏或屏幕哪个固定位置。
- 未额外说明时，所有滚动窗口统一使用行为树默认滚动逻辑：50% 手势比例，`duration` 1-1.5 秒。任务代码不要临时计算自定义比例或时长；只有用户明确要求、标注备注声明，或已有真实验证证明该窗口需要专项参数时，才允许覆盖默认滚动参数。
- 滚动容器和识别区可以分开声明：手势在容器内执行，识别/OCR/签名只在用户标注的安全区域内进行，用来避开弹窗遮挡、顶部提示和底部半露条目。
- 目标靠近边缘、遮挡区或安全点击区之外时，应使用候选命中后的“小幅复位/复核”步骤处理，不改变通用滚动默认值。

### 局部结构读取

用于读取一个重复条目内部的标题、状态、进度、价格、按钮、奖励等字段。

行为树应使用“容器 + 条目模板 + 锚点 + 字段”的模型。字段读取结果需要带证据，方便后续复盘 OCR 错字、遮挡、错位或误点。

### 局部 OCR 与精细点击

用于处理相邻短标签、旋转目标、窄文字或同一行多个可点对象被 OCR 合并的场景。

任务默认继续使用 line 级 OCR；只有需要按具体字词计算点击点时，才启用词/字级 OCR 结果。典型场景是拜谒 `#265` 中 `魔道` 与相邻法则名可能被识别成同一行，点击不能取整行中心，而应优先使用 `ocr_words_in_shapes()` 返回的 word/char box。

该能力应保证：

- 调用方只在指定识别区启用精细 OCR，不全局开启 `return_word_box`。
- 命中子串时优先使用词/字级 box；没有词/字级 box 时，才退回到行内字符串比例估算。
- 计算出的点击点必须服务于业务对象本身，例如图标左侧、按钮中心或文本锚点相对位置，不能直接把合并 OCR 行中心当作目标。
- OCR options 只能通过 Runtime 支持的白名单参数透传，避免任务代码绕过 OCR 服务配置。

## 任务实现要求

- 任务代码只写业务意图，例如“找到进行一次拜谒并进入”“查找某个活动条目”“点击某个商店商品”。
- 滚动、复位、候选复核、安全点击等通用流程应沉到行为树能力中。
- 如果当前能力还没有实现，先登记能力缺口，再做可复用实现；不要只为当前任务写死特例。
