# CodeYun 表格 API 与 mf/mi15 考勤协作

> Last Updated: 2026-05-10

## 背景

本文先说明 CodeYun 星云表格的通用远程 API，再说明当前 `codepc_mf / codepc_mi15` 考勤流程如何使用这套 API。不要把当前部署关系理解成 API 限制。

通用概念：

- **表格数据主机**：持有 CodeYun 星云表格数据的 CodeYun 实例，对外提供 `/api/note-sheets/.../table`。
- **可信调用设备**：持有有效设备 token 的任意设备，可以远程读取或回写表格数据。
- **业务执行设备**：负责运行具体业务脚本的设备，可以是 `codepc_mi15`，也可以是以后其他机器。

当前考勤部署示例：

当前考勤流程涉及两台机器：

- `codepc_mf`：星云表格数据主机。主要运行 CodeYun、调度器和星云表格；报名表、考勤表、课程汇总页等结构化数据都存放在 `codepc_mf`。
- `codepc_mi15`：业务执行主机。运行同源镜像代码，但有小鹅通、微信支付、浏览器登录态和考勤 PG 等实际业务环境。

阅读视角约定：

- 如果 Agent 正运行在 `codepc_mf`：调用小鹅通/考勤 PG 相关动作时，目标业务执行设备通常是 `codepc_mi15`。
- 如果 Agent 正运行在 `codepc_mi15`：读取或回写星云表格时，目标表格数据主机通常是 `codepc_mf`。
- 不要把“本机”理解为固定职责。多台设备的源码通常同步，但运行实例、登录态、数据库和浏览器环境不同。

以前 WPS/JSA 方案复杂，主要是两个原因：

1. JSA 只能调用远端预先写好的函数，不能自然发送自定义 Python/JS 逻辑过去执行。
2. Excel/WPS 表格本身偏非结构化，脚本要先靠大量工具函数猜表头、定位数据区、处理合并单元格和隐藏列。

现在这两个约束都可以放松：

- 设备之间通过设备 token 鉴权；当前 `codepc_mf` 和 `codepc_mi15` 都是可信设备。
- CodeYun 星云表格已经区分 `columns / grid_rows / rows / data_start_row / field_row_index`，数据区是结构化的。
- `codepc_mi15` 不是不可改黑盒 API，而是同源代码的远端运行实例。`codepc_mf` 修改源码后，代码同步到 `codepc_mi15`，再由 `codepc_mi15` 作为实际执行环境运行即可。

## 总体方案

不要继续为每个考勤步骤堆专门业务接口，例如：

```text
/attendance/fanbei/step1
/attendance/fanbei/step2
/attendance/fanbei/step3
...
```

推荐拆成两类基础能力：

1. **可信远端执行 API**：调用某台业务执行设备执行一段 Python 脚本，或调用某个 Python 模块函数。当前考勤中常见方向是 `codepc_mf -> codepc_mi15`。
2. **结构化表格 API**：任意可信调用设备按字段名、数据行、A1 坐标读取和回写某台表格数据主机上的星云表格。当前考勤中常见方向是 `codepc_mi15 -> codepc_mf`。

这样课程脚本可以放回 `D:\home\chenkunze\slns\kq5034\courses`，保持“一个课程一个可读脚本”的业务层表达；脚本内部不再操作 WPS，而是调用目标表格数据主机的表格 API。当前考勤部署中，目标表格数据主机是 `codepc_mf`。

## 可信 Python 执行 API

接口由“执行业务动作的设备”提供。当前考勤场景中，通常由 `codepc_mi15` 提供，因为小鹅通登录态、微信支付环境和考勤 PG 都在 `codepc_mi15`。

当前考勤示例调用方向：

```text
codepc_mf 调度器 -> codepc_mi15 /api/device-control/python-runs
```

路径是：

```text
POST /api/device-control/python-runs
GET  /api/device-control/python-runs/{run_id}
```

鉴权沿用设备 token：

```http
X-Device-Token: <device-token>
```

或：

```http
Authorization: Bearer <device-token>
```

### 调用模块函数

```python
import requests

mi15 = "http://codepc-mi15:8000"  # 目标：codepc_mi15
token = "..."

resp = requests.post(
    f"{mi15}/api/device-control/python-runs",
    headers={"X-Device-Token": token},
    json={
        "mode": "module_call",
        "module": "kq5034.attendance_api",
        "callable": "sync_fanbei_attendance_step1",
        "kwargs": {
            "course_name": "d260509梵呗初阶",
            "shop_id": 1,
            "update_lessons": True,
            "update_clockins": True,
            "clockin_pattern": "d260509梵呗初阶-*",
            "close_browser": True
        },
        "timeout": 3600
    },
    timeout=3700,
)
resp.raise_for_status()
print(resp.json())
```

### 执行临时脚本

```python
resp = requests.post(
    f"{mi15}/api/device-control/python-runs",
    headers={"X-Device-Token": token},
    json={
        "mode": "script",
        "script": """
from kq5034.attendance_api import sync_fanbei_attendance_step1
result = sync_fanbei_attendance_step1(
    course_name="d260509梵呗初阶",
    shop_id=1,
    update_lessons=True,
    update_clockins=False,
    close_browser=True,
)
""",
        "timeout": 3600
    },
)
```

返回值包含：

- `status`: `running / completed / failed / timeout`
- `result`: Python 返回值，尽量 JSON 化
- `stdout / stderr`: 运行日志尾部
- `run_id`: 异步任务后续查询用

如果传 `"async": true`，接口会立即返回 `run_id`，后续用 `GET /api/device-control/python-runs/{run_id}` 轮询。

## 结构化 Sheet Table API

表格接口由“持有星云表格数据的 CodeYun 实例”提供。任何可信调用设备只要持有有效设备 token，就可以远程读取或回写该实例上的表格。

当前考勤示例调用方向：

```text
codepc_mi15 课程脚本 -> codepc_mf /api/note-sheets/sheets/{sheet_id}/table
```

路径是：

```text
GET   /api/note-sheets/sheets/{sheet_id}/table
PATCH /api/note-sheets/sheets/{sheet_id}/table
```

同样支持设备 token。对可信设备，这个接口按 manager 权限处理，适合自动化脚本远程读取和回写表格。当前考勤中主要用于 `codepc_mi15` 课程脚本回写 `codepc_mf` 的表格。

当前考勤示例中，`codepc_mf` 上的前端页面：

```text
http://localhost:5173/notes/sheets?workbook=2&sheet=4
```

对应 `codepc_mf` 后端调用：

```text
GET /api/note-sheets/sheets/4/table?workbook_id=2
PATCH /api/note-sheets/sheets/4/table?workbook_id=2
```

### 读取 workbook=2 sheet=4

```python
import requests

mf = "http://codepc-mf:8000"  # 目标：codepc_mf
token = "..."

s = requests.Session()
s.trust_env = False  # 局域网互调时避免走系统代理

resp = s.get(
    f"{mf}/api/note-sheets/sheets/4/table",
    params={"workbook_id": 2},
    headers={"X-Device-Token": token},
    timeout=30,
)
resp.raise_for_status()
table = resp.json()

print(table["columns"])
for row in table["rows"]:
    print(row["_sheet_row"], row.get("课程类型"), row.get("在线考勤表"))
```

读取接口默认使用 `value_mode=text`，也就是返回前端表格里“显示出来”的值；常规脚本应使用默认值。名称管理器里的公式会在 `defined_name_values` 中返回计算后的值，供 step4 这类业务脚本生成返款参数。

调试或迁移公式本身时可以显式读取原始值：

```python
resp = s.get(
    f"{mf}/api/note-sheets/sheets/6/table",
    params={"workbook_id": 3, "value_mode": "raw", "include_grid": True},
    headers={"X-Device-Token": token},
    timeout=30,
)
```

`value_mode` 取值：

- `text`：默认，返回显示/计算值。适合 step4 这类业务脚本直接消费。
- `raw`：返回数据库原始值，公式单元格会保留 `=...`。适合排查公式和模板。

返回结构：

```json
{
  "id": 4,
  "workbook_id": 2,
  "title": "课程",
  "version": 12,
  "value_mode": "text",
  "columns": ["课程类型", "在线考勤表", "..."],
  "defined_name_values": {
    "返款说明": "念住闯关每日返款",
    "返款id后缀": "_day502"
  },
  "rows": [
    {
      "_row_index": 0,
      "_sheet_row": 2,
      "课程类型": "梵呗初阶",
      "在线考勤表": "20260509梵呗初阶"
    }
  ],
  "data_start_row": 1,
  "field_row_index": 0
}
```

`_row_index` 是数据区 0 基下标，`_sheet_row` 是表格可见行号。课程脚本一般优先使用字段名和 `_row_index`，只有和用户界面沟通时才使用 `_sheet_row`。

### 回写字段

按某个 key 字段匹配行，适合把课程脚本算出来的状态写回指定课程：

```python
resp = s.patch(
    f"{mf}/api/note-sheets/sheets/4/table",
    params={"workbook_id": 2},
    headers={"X-Device-Token": token},
    json={
        "expected_version": table["version"],
        "operations": [
            {
                "type": "write_fields",
                "key_field": "在线考勤表",
                "fields": ["课次链接", "打卡链接"],
                "rows": [
                    {
                        "在线考勤表": "20260509梵呗初阶",
                        "课次链接": 11,
                        "打卡链接": 9
                    }
                ]
            }
        ]
    },
    timeout=30,
)
resp.raise_for_status()
```

`expected_version` 用来防止脚本基于旧表覆盖新数据。冲突时接口返回 `409`，调用方应重新读取后再写。

### 回写考勤表课次列

考勤明细表有很多类似 `19:30~20:49 第01课` 的列。调用时可以传简写字段 `第1课` 或 `第01课`，后端会尝试匹配包含同一课号的真实列名：

```python
resp = s.patch(
    f"{mf}/api/note-sheets/sheets/6/table",
    params={"workbook_id": 3},
    headers={"X-Device-Token": token},
    json={
        "operations": [
            {
                "type": "write_fields",
                "key_field": "用户ID",
                "fields": ["第1课"],
                "rows": [
                    {"用户ID": "u_xxx", "第1课": 1},
                    {"用户ID": "u_yyy", "第1课": 0}
                ]
            }
        ]
    },
)
```

### 写备注/状态行

星云表格的 `rows` 只表示真实数据区；表头、说明行、按钮行属于 `grid_rows`。如果要写第 3 行这种说明/状态行，用 `set_note_cell`：

```python
resp = s.patch(
    f"{mf}/api/note-sheets/sheets/6/table",
    params={"workbook_id": 3},
    headers={"X-Device-Token": token},
    json={
        "operations": [
            {
                "type": "set_note_cell",
                "field": "当前应返款",
                "value": "最近运行更新时间: 2026/05/10 07:10"
            }
        ]
    },
)
```

默认写到 `field_row_index + 1`，也就是字段名下一行。需要精确坐标时可以传 `sheet_row`。

### 触发当前表格实例的梵呗 step3

当前梵呗流程里，step2 通常由业务执行设备写回打卡/课次数据；写回后需要让表格数据主机刷新静态派生结果。这个动作由持有目标考勤表的 CodeYun 实例执行：

```text

```

当前考勤部署示例：

```python
resp = s.post(
    f"{mf}/api/device-control/attendance/fanbei/step3",
    headers={"X-Device-Token": token},

        "sheet_id": 6,

resp.raise_for_status()
print(resp.json()["message"])
```

当前版本的 step3 只做两件事：

- 静态计算 `视频应返款` 列。
- 渲染课次进度列的背景色。

它不会覆盖 `G/H/J/K/N/O` 等动态公式列。默认参数就是当前梵呗考勤表：

```json
{
  "sheet_id": 6,
  "course_name": "d260509梵呗初阶"
}
```

### A1 坐标写入

如果脚本已经知道可见表格坐标：

```python
resp = s.patch(
    f"{mf}/api/note-sheets/sheets/6/table",
    params={"workbook_id": 3},
    headers={"X-Device-Token": token},
    json={
        "operations": [
            {
                "type": "write_range",
                "cell": "Q4",
                "values": [[1], [0], [1]]
            }
        ]
    },
)
```

当 `cell` 落在数据区之前，会写 `grid_rows`；落在数据区之后，会写 `rows` 并自动同步 `grid_rows` 的数据区。

## workbook=2 sheet=4 的本次操作建议

`workbook=2&sheet=4` 是 `codepc_mf` 上的课程汇总/入口页。`codepc_mi15` 侧脚本不应该直接理解 `codepc_mf` 前端页面 DOM，而是按下面流程处理：

1. `codepc_mf` 调度器到点后，通过 `POST http://codepc-mi15:8000/api/device-control/python-runs` 调用 `codepc_mi15` 上的课程脚本。
2. `codepc_mi15` 脚本读取 `GET http://codepc-mf:8000/api/note-sheets/sheets/4/table?workbook_id=2`，找到 `在线考勤表 == 20260509梵呗初阶` 的课程行。
3. `codepc_mi15` 脚本根据这行配置确定课程名、课次链接数、打卡链接数、负责人等信息。
4. `codepc_mi15` 在自己的运行环境中执行小鹅通/考勤 PG 读取或下载逻辑。
5. `codepc_mi15` 把统计结果回写 `codepc_mf`：
   - 课程汇总页：回写 `课次链接 / 打卡链接 / 备注` 等状态。
   - 具体考勤表：回写用户打卡列、退款统计列、状态说明行。

这样业务脚本仍保留在 `kq5034/courses`，但数据源从 WPS 改为 CodeYun sheet table API。

## 分层约束

- `codeyun` 负责设备鉴权、远端运行入口、星云表格读写接口；同一份源码会在 `codepc_mf` 和 `codepc_mi15` 上运行，但承担的运行职责不同。
- `kq5034` 负责小鹅通、考勤 PG、课程脚本和业务步骤编排；实际依赖登录态/PG 的动作通常在 `codepc_mi15` 执行。
- `pyxllib` 只沉淀跨项目通用工具；不要让 `codeyun` 依赖 `D:\home\chenkunze\slns\kq5034` 的业务实现。
- 如果某段逻辑只服务某个课程步骤，放在 `kq5034/courses` 或 `kq5034` 功能层；不要放进 CodeYun API。

## 注意事项

- 局域网互调建议 `requests.Session().trust_env = False`，避免系统代理影响 `codepc_mf/codepc_mi15`。
- `PATCH /table` 支持多操作一次提交，能减少中途失败导致的半更新。
- 长耗时爬虫应使用 `POST /python-runs` 的 `"async": true`，前端或调度器轮询 `run_id`。
- 表格写入应优先使用字段名和 key 字段匹配，不要依赖 UI 滚动位置。
- 如果 `codepc_mi15` 表现为旧逻辑，先确认源码是否同步，再确认 `codepc_mi15` 的 CodeYun 服务是否热加载或重启。
