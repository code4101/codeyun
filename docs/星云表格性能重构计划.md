# 星云表格性能重构计划

更新时间：2026-07-05

## 结论

当前卡顿主要不是接口慢，也不是单纯 Handsontable 框架不可用，而是 CodeYun 表格页把 Handsontable 推入了多次重配置和重渲染路径。Handsontable 的 DOM 渲染模型会放大这个问题；WPS、金山文档、腾讯表格、Google Sheets 这类产品通常使用更底层的自研表格渲染引擎，长期上限确实不同。

短中期优先修 CodeYun 自身实现，目标是把 sheet 切换从“重建组件 + 重配插件 + 多轮 render”收敛为“稳定实例 + 单次数据加载 + 必要局部更新”。长期如果要接近 WPS 级丝滑，再评估自研 canvas/虚拟表格引擎。

### P4：长期引擎路线

目标：判断 Handsontable 是否仍满足 CodeYun 星云表格的长期定位。

判断口径：

- 如果 P0-P3 后仍存在 500ms 以上的常态 render 长任务，开始调研 canvas/虚拟表格引擎。
- 若主要场景只是中小表格管理，继续保留 Handsontable，但限制重插件和复杂 renderer。
- 若目标是 WPS/KDocs 级连续滚动、切 sheet 和超大表体验，需要规划自研轻量表格渲染层。
