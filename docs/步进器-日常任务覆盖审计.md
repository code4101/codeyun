# 步进器-日常任务覆盖审计

本文记录新版 `游戏窗口3` 日常定位预设对旧版凡修日常入口逻辑的覆盖情况。它不是任务执行方案，而是用于审查“日常查找”这层是否已经掌握旧版入口参数、状态语义和特殊风险。

## 通用入口

旧版核心入口是 `基础功能.py::日常_查找(task_name, not_found_status=2, timeout_seconds=90)`：

- 先进入日常页。
- OCR 在 `日常/日常` 外层视图查标题锚点。
- 拖拽只作用于 `日常/日常/任务清单`。
- 命中标题后用 `create_sub_view("任务块", "标题", anchor)` 生成动态任务块。
- 读取 `任务状态` 与 `日常_任务块进度(task_view)`。
- 状态码语义：`0` 待执行，`1` 闻道中，`2` 已完成/已结束/可购买或进度已满。

旧版还有 `日常_任务需要执行` 作为通用二次判断：

- 进度存在且未满时，即使状态码大于 0，也按待执行处理。
- 状态为 0 但需要进度且没读到进度时，短时间重试，不排到次日。
- 状态为 2 且进度已满时才确认完成。

## 状态词

定位层集中维护三类状态词：

- 完成态：`已结束`、`已完成`、`可购买`。
- 进行态：`闻道中`。
- 候选态：`未占领`、`领取`、`已领取`、`前往`、`挑战`、`参与`、`进行`、`扫荡`、`报名`、`已报名`、`可挑战`、`可参与` 等。

候选态只表示“这是任务状态字段里可能出现的词”，不直接等于完成。最终判断必须结合进度。

## 当前缺口

新版日常定位已覆盖通用入口、模板浮动、行文本合并、状态/进度解析、默认 50% 滚动、靠顶部/底部时的 18% 小幅复核、参数化 `candidate_rows / bidirectional` 扫描，以及挑战仙缘的完成行兜底。仍未完全覆盖的旧版特化逻辑包括：

- 拜谒方向扫描与顶部/底部小幅复核已经参数化接入，但还缺实机专项验证。
- 挑战仙缘找不到入口时的长扫已参数化接入；仍缺实机专项验证，确认不会误命中 `仙缘斗法`。
- 妖族、每日副本、首领等任务进入后的业务状态机。

这些缺口不属于“日常定位”本身必须全部吞掉的逻辑，但要在后续 `日常进入` 或具体业务任务中逐步接入，避免把入口定位结果误当成最终业务结果。
