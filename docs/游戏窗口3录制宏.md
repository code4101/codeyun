# 游戏窗口3录制宏

## 数据流

录制宏是面向游戏窗口3文件树的场景录制能力，不写裸坐标脚本。

每次用户在交互模式中点击或拖拽时：

1. 先捕捉操作前的当前画面。
2. 用现有场景匹配逻辑识别当前画面是否已属于某个截图场景。
3. 如果没有匹配场景，则保存当前画面为新的截图帧，并加入文件树。
4. 在对应截图帧上创建 shape。
5. 上一次录制动作创建的 shape，会在本次操作确定当前帧后，延迟补写 `场景跳转` 到本次帧编号。

延迟补跳转是必要的：当前操作发生时只能知道“操作前所在帧”，下一次操作前才知道上一次操作实际跳到了哪个帧。

## 标注策略

默认使用纯工程保底策略：

- 单击：以点击位置为中心创建默认尺寸矩形，默认 `50x50`。
- 拖拽：根据首尾点生成覆盖拖拽路径的矩形，并写入方向 `up / down / left / right`。
- 场景标识：如果当前帧还没有场景标识，且配置允许，则把本次创建的第一个 shape 标记为场景标识。
- 拖拽耗时：配置为“真实耗时”时记录用户这次拖拽的实际耗时；配置为“固定耗时”时记录固定耗时，默认 `1500ms`。这个值只进入录制出的 shape 说明和 AI 标注上下文，不改变真实用户输入。

AnLib / PyAutoGUI 风格里要区分“拖拽动作 duration”和“一次自动化操作总耗时”。当前环境里 `pyautogui.PAUSE` 默认是 `0.1s`；`wxautox.uiautomation` 里的 `OPERATION_WAIT_TIME` 默认是 `0.5s`，`MAX_MOVE_SECOND` 默认是 `1s`，`DragDrop()` 会叠加按下、移动和释放后的等待。因此 `300ms` 只适合作为低层接口的快速 swipe duration，不适合作为 AnLib 风格的默认总耗时口径。这里的录制宏配置不直接改全局暂停，而是记录拖拽动作本身的耗时策略，后续生成脚本时再决定是否映射到默认暂停或拖拽 duration。

AI 辅助标注模式不会替代主流程：录制时仍然先创建工程保底 shape，并继续下发用户输入；随后异步调用“游戏窗口录制标注”AI 应用（默认 Codex CLI `gpt-5.5`）根据截图、点击点、拖拽方向、PaddleOCR 可扩展上下文和保底框修正 shape 范围。AI 失败、超时或结果不可用时，保留工程保底框。

这条链路的约束是：

- AI 只优化按钮、图标、菜单项、滑块或可拖拽控件的 bbox。
- AI 不负责判断是否新建截图帧，也不负责决定场景跳转。
- 录制宏检测已有场景、创建新帧和延迟补跳转，始终走游戏窗口3实际运行使用的场景匹配底层。
- PaddleOCR 结果作为 AI 请求上下文的一部分，但不能因此拆出另一套“只供调试”的标注接口。
