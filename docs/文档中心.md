# CodeYun 文档中心

本目录按“当前事实、操作方法、工作过程、历史追溯”分层管理。阅读文档时，先判断文档所处层级，不要把计划、研究记录或自动化增量日志当成当前实现。

## 项目边界

CodeYun 是个人工具集成与运行控制平台，主体由 Python 后端和 Vue 前端组成。仓库内代码并不总是完整运行边界：考勤、凡修行为树及其他被托管脚本可能运行在外部同源仓库中。任务涉及这些运行单元时，应同时检查 CodeYun 的编排入口和外部运行时的公共接口、真实入口及状态文件。

实现事实以代码、测试、配置、类型和公共接口为准；仓库运行方式、安全边界和文档读取规则以根目录 `AGENTS.md` 为准。本文只负责提供统一文档入口，不重复维护容易过期的模块清单。

## 目录层级

| 目录 | 层级 | 内容 | 是否可作为当前事实 |
| --- | --- | --- | --- |
| `平台/` | L1 | 跨业务的平台架构与开发约定 | 是 |
| `领域/` | L1-L2 | 各业务域的架构、指南、标准作业与研究 | 以域内索引为准 |
| `运维/` | L2 | 启动、部署、恢复和排障手册 | 是 |
| `自动化/` | L2-L3 | 自动化设计、游标、候选队列和增量上下文 | 仅设计正文可作为事实 |
| `研究/` | L3 | 尚未固化为系统约定的研究材料 | 否 |
| `归档/` | L4 | 已停用方案、完成计划和恢复档案 | 否 |
| `参考/` | 参考 | 面向读者的能力概览与参考资料 | 不定义实现 |
| `资源/` | 资源 | 文档使用的图片等静态资源 | 不适用 |

## 文档类型和优先级

发生冲突时，按以下顺序判断：

1. `AGENTS.md` 中的强约束。
2. `平台/架构`、`平台/约定` 或业务域 `架构` 中明确声明的唯一权威正文。
3. `指南`、`作业`、`运行手册` 中的当前操作方法。
4. `规划`、`研究` 和 `自动化/上下文` 中的工作记录。
5. `归档` 中仅供追溯的历史材料。

文件名包含“设计”并不自动代表它是当前架构；文件所在层级和正文中的状态声明共同决定其权威性。

## 新文档放置规则

- 描述系统现在如何工作：放入平台或业务域的 `架构`。
- 描述必须遵守的开发规则：放入 `平台/约定`，业务专用规则放入相应业务域。
- 描述如何执行、恢复或排障：放入 `指南` 或 `运维/运行手册`。
- 描述一个可选业务作业：放入相应业务域的 `作业`。
- 尚未实施的方案、任务清单：放入 `规划`。
- 探索、测量、抓包观察和方案比较：放入 `研究`。
- 自动化游标、候选队列和增量记忆：放入 `自动化/上下文` 或业务域 `上下文`。
- 已失效但仍有追溯价值：移入 `归档`，并在正文顶部标明失效原因和替代入口。
- 考勤与凡修的领域知识统一归入各自技能，`docs/` 不再维护第二套 Markdown；跨领域平台文档可以引用技能中的具体契约。

`docs/` 根目录只保留本文。新增文档不得继续堆在根目录。
