# 股票功能系列规划

## 背景与目标

当前目标是先在 CodeYun 中建立股票功能的第一阶段基础：能打开东方财富、保留人工登录态，并提供后续页面探查和数据抓取的最小脚手架。

第一阶段不追求完整股票系统，也不绕过登录、验证码或权限控制。登录、扫码、验证码统一由人工在有头浏览器里完成，程序只复用本机浏览器用户数据目录。

## 第一阶段范围

已落地或计划落地的最小能力：

- 打开东方财富首页并让用户手动登录。
- 使用独立 Chromium 用户数据目录保存登录态，避免污染用户日常浏览器配置。
- 复用同一套路径和浏览器配置封装，后续脚本不重复维护登录态目录。
- 提供页面状态探查入口，输出 `title`、`url`、登录提示信号和 HTML 片段。
- 暂不写数据库表、前端页面、菜单权限、定时任务和自动交易能力。

## 模块边界

归属：业务项目 / 功能层。

理由：东方财富登录态、页面探查、股票数据采集都属于 CodeYun 当前业务内能力，不是跨项目通用工具；DrissionPage 的通用用法也不需要下沉到 `pyxllib`。

当前边界：

| 层级 | 位置 | 职责 |
| --- | --- | --- |
| 功能层 | `backend/core/stock/` | 东方财富浏览器路径、配置、页面状态快照、后续采集通用能力 |
| 业务入口 | `scripts/eastmoney_login.py` | 最简单的人工登录入口 |
| 业务入口 | `scripts/eastmoney_probe.py` | 打开目标页并输出页面状态，辅助后续决定抓取点 |
| 文档 | `docs/股票功能系列规划.md` | 阶段规划、边界和运行约定 |

不放到功能层的内容：

- 用户经常调整的股票池、关注列表、回测参数。
- 一次性调试脚本里的临时输出。
- 未来前端页面里的展示状态和筛选条件。

不放到 `pyxllib` 的内容：

- 东方财富域名、页面路径、登录状态判断。
- CodeYun 的数据目录、任务调度、权限控制。
- 个人使用习惯相关的业务配置。

## 当前运行命令

最简单登录：

```powershell
uv run python scripts/eastmoney_login.py
```

页面探查：

```powershell
uv run python scripts/eastmoney_probe.py
uv run python scripts/eastmoney_probe.py "https://quote.eastmoney.com/" --keep-open
```

登录态目录：

```text
<CODEYUN_DATA_DIR>/eastmoney/chromium-user-data
```

该目录在仓库外的数据目录下，不进入版本库。

## 后续阶段建议

### 阶段二：确认数据来源

先用 `scripts/eastmoney_probe.py` 和浏览器网络监听确认目标数据来源：

- 行情：优先找稳定公开接口，其次 DOM 提取。
- 自选股：大概率依赖登录态，先确认页面和接口权限。
- 交易、资产、持仓：如果涉及更高安全等级，默认只做只读展示，不做自动下单。

### 阶段三：后端服务化

在 `backend/core/stock/` 内增加项目内服务对象，例如：

- `EastmoneySession`：管理登录态和页面打开。
- `StockQuoteProvider`：读取行情。
- `WatchlistProvider`：读取自选股。
- `StockSnapshotStore`：保存定期快照。

只有当数据结构稳定后，再考虑新增数据库表和 `/api/stock/*` 接口。

### 阶段四：前端页面

如果需要在侧边栏可见，必须同步检查：

- `frontend/src/standard/**/index.ts`
- `frontend/src/features/access/permissionRegistry.json`
- `frontend/src/layout/MainLayout.vue`

前端第一版建议只做只读工作台：股票池、最新行情、持仓观察、采集状态，不做交易动作。

## 风险与约束

- 东方财富页面结构和接口可能变化，采集逻辑要先通过单页探查证明稳定，再批量化。
- 登录、扫码、验证码是人工边界，不在程序中绕过。
- 涉及账号、资产、交易信息时，默认本地保存，避免写入仓库或外发。
- 后续如接定时任务，需要先确认采集频率，避免对站点造成不必要压力。
