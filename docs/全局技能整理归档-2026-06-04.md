# 全局技能整理归档（2026-06-04）

本文记录 `D:\home\chenkunze\slns\skills` 的一次主动瘦身。目标是减少全局 skill 数量，避免和 CodeYun 项目内 docs、插件自带技能、以及更高层通用技能重复。

## 原则

- 全局 skill 只保留跨项目稳定成立的工作法和高频操作入口。
- CodeYun 业务事实、接口约定、Fanxiu 架构、表格 API、页面继承、standard/plugins 结构，优先放在 `codeyun/docs`。
- 被合并的技能不再作为 Codex 自动触发规则使用；本文只保留历史线索，方便以后检索。
- 删除活跃目录前，先把有价值规则并入保留技能。

## 合并结果

### `项目审计` -> `项目优化`

`项目审计` 的结构审计、命名审计、冗余审计已经并入 `项目优化`。

新边界：

- 用户只想盘点问题时，`项目优化` 使用只读审计模式。
- 用户要求推进实施时，`项目优化` 使用实施优化模式。
- 复杂方案仍先转 `仅分析`。

### `Python脚手架` + `优化Python代码` + `Pytest规范` -> `Python工程规范`

三者合并为一个 Python 工程入口，覆盖：

- `src/` 布局、`hatchling`、作者、许可证。
- reST 风格 docstring、doctest、文件头说明、大文件 part 组织。
- pytest 命名、测试目录镜像、fixture、回归测试和孤儿测试清理。

### `极简示例` -> `仅分析`

`极简示例` 的“最小 demo / 最小复现”规则已并入 `仅分析` 的极简示例模式。

新边界：

- 分析阶段只给代码块或命令草案。
- 如果 demo 需要写入仓库文件或变成正式测试，等用户同意实施后再操作。

### `服务验证` 与 `凡修Runtime真实自检` 分离

`服务验证` 恢复为通用验证技能，只保留：

- 静态层、服务层、远端实例层、真实入口层。
- CodeYun 通用自检和汇报标准。

Fanxiu 标注页、Runtime、Scheduler、行为树、场景移动、MuMu/ADB 画面流、OCR/匹配等专项规则迁入 `凡修Runtime真实自检`。

## 归档移除的低频工具技能

### `遍历目录`

原因：更像 `pyxllib` 工具用法说明，不是高频协作策略。日常文件检索优先直接用 `rg` / `rg --files`；复杂目录遍历时可回到 `pyxllib` 文档或源码。

历史能力：使用 `DirWalker` 做复杂筛选、正则/通配符匹配、链式规则和 ZIP 打包。

### `调研对象`

原因：偏专用工具说明，低频触发。需要深入分析 Python 对象结构时，优先直接查 `pyxllib.prog.view_obj.py` 或在当前任务中临时阅读对象。

历史能力：分析对象继承链、成员变量、成员函数并生成可视化报告。

### `智能待办`

原因：待办管理应优先进入具体项目的 `TODO.md`、CodeYun 任务体系或用户指定位置，不需要全局自动触发技能常驻。

历史能力：整理、分类、去重、拆解任务，并写入根目录 `TODO.md`。

### `codex-primary-runtime`

原因：本地 `codex-primary-runtime` 下的 spreadsheets/slides 技能与当前插件提供的 Spreadsheets/Presentations/Documents 能力重复。后续优先使用插件自带技能。

## 保留但收窄的技能

- `技术设计文档`：保留给正式系统级设计文档和架构审查；CodeYun 具体接口约定优先读项目 docs。
- `API架构师`：保留给 SDK、库、服务接口或类方法 API 形状讨论；不要代替 CodeYun 项目内接口文档。
- `设计品味`：保留为跨 UI、API、工作流、抽象和代码结构的通用判断。
- `前端UI规范`：保留为前端和 CodeYun UI 专项规范。

## 后续维护建议

- 新增 skill 前先判断是否能并入现有高层 skill。
- 项目专属知识默认进项目 docs，不进全局 skills。
- 低频工具说明默认进 docs 或源码注释，不长期占用活跃 skill。
- 每次“AI请学习”都要优先更新现有技能，而不是新建。
