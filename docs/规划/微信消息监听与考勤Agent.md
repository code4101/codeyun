# 微信消息监听与考勤 Agent 开发规划

状态：2026-10-02 已实施并启用。本文记录施工范围与验收；公共契约以代码、类型、OpenAPI 和测试为准。

## 目标与授权

本机工程每 5 秒检查指定微信账号的全部聊天更新，将新消息转成可恢复、可去重的事件。考勤 Hook 订阅目标群：首次 @ 唤醒 Codex，后续消息作为上下文；新的 @ 强打断，其他消息软打断。Agent 实际接管问题，完成调查、业务处理或工程修复并核验结果，再产出候选回复。工程在发送前再次检查新消息并按需要求迭代，再通过正式微信接口发送。

用户授权使用两个微信账号在“考勤后台”群实测。此前讨论称“考勤中台”，启用前必须核对唯一群 ID，不能凭相似名称扩大测试范围。考勤执行及回复账号固定为 code4102 / 考勤返款。群消息是待判断的业务输入；资金、删除等动作仍遵守考勤技能门禁。

## 正交组件

1. **消息提供方**：账号隔离、数据库与 WAL 增量更新、标准化稳定消息 ID、@ 元信息、游标和资源按需读取。未变化时不复制解密，不批量导出媒体。补齐提供方公共接口，调用方不读取微信内部数据库。
2. **事件与 Hook**：持久事件去重、首次启动建立基线、防历史消息重放、Hook 独立消费进度。至少一次投递搭配任务幂等；读取、入队、已处理、已发送分别记录。
3. **考勤路由**：唯一群 ID 与账号白名单。@ 自己为强事件；普通消息仅在已唤醒的问题上下文中作为软事件。相关性、提问人、引用及多话题归属由 Agent 判断，自身消息不触发。
4. **Codex 会话与执行**：群内串行执行，软事件排队，强事件在安全节点转向/暂停。按北京时间复用每日会话；跨天且距上一条有效提问至少两小时，任务无运行所有权时创建新会话，带未结摘要。每轮通过公开 `config/read` 读取当前 Codex 默认模型和推理强度，显式应用到复用线程；未配置模型时用公开目录默认值，调用失败不切换备用模型。接入公开线程和轮次协议，不使用私有管道。
5. **发送门禁**：候选回复绑定已消费事件位置。发送前主动刷新并检查未读事件；有新增上下文先迭代。无关消息允许继续发送，不无限被闲聊阻塞。发送结果不明时进入待核验状态，禁止盲重发。
6. **服务与诊断**：生命周期启停、单实例锁、五秒检查不重叠、错误退避、耗时样本、队列积压、线程/轮次状态与最后错误。配置和状态放 CODEYUN_DATA_DIR，实测证据放系统临时目录。

## 实施顺序

- 核验两个账号、目标群、现有同步新鲜度及公开 Codex 协议。
- 提供方补齐轻量账号级新消息能力，重复测量平均耗时±标准差，并验证 WAL 新消息。
- 建立持久事件、Hook 与会话/发送状态机，覆盖重放、并发、重启和发送结果不明。
- 接入真实 Codex 和微信，接通五秒服务与诊断接口。
- 在已授权测试群验证首次触发、无 @ 补充、强转向、无关闲聊、回复前迭代、自身回声、每日会话及重启去重。

## 验收

无新消息不调用 AI；新消息不因重复读取重触发；处理期间新增补充能进入 Agent；候选回复不能绕过最后检查；群回复来自考勤返款账号；异常可诊断和恢复。五秒是检查周期而非严格端到端 SLA，超过周期不能堆积并行同步。

真实群验收结果和实现限制在完成时更新此规划；未真实验证的能力不得以单元测试通过替代。
