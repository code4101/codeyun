# 考勤课程 ABC 独立体系约定

> 本文定义考勤系统中三套独立课程体系的统一交流代号。A/B/C 不是同一套算法的参数分支，也不是可以互换模板的轻量分类。涉及 CodeYun 工作簿、`codepc_mf`、PG、`xlproject/kq5034`、Step 1–6、课程配置迁移和故障排查时，必须先确定所属体系。

## 当前运行主机

`codepc_mf` 是唯一考勤生产执行主机：行为树、全部小鹅通采集、工作簿读写、计算和核验都在 mf 完成。`codepc_mi15` 已退出考勤生产运行，不再作为远程执行设备或失败回退。Step 6 同样归 mf，但必须在微信发送链路单独验收完成后再启用整棵行为树。

## 总原则

A、B、C 是三套差异很大的业务体系。每套体系独立定义课程配置、数据采集、完成判定、更新时间、返款计算、工作簿结构、调度节奏和验收标准。不得先设计一套“通用课程逻辑”，再把三类差异处理成少量条件分支。

只有设备通信、表格读写、订单查询、任务执行等与课程语义无关的基础设施可以默认复用。任何业务层逻辑若要跨体系复用，必须逐项证明语义一致。

## 分类

| 代号 | 课程范围 | 视频完成规则 | `video_duration` | 典型配置节奏 |
| --- | --- | --- | --- | --- |
| A 类课程 | 普通觉观、念住的每月网课 | 普通时长/进度规则 | 必需 | 通常按日更新 |
| B 类课程 | 禅宗、修道班 | Zen Stage 规则：实际进度达到 100% 或小鹅通标记“已完成”；再按完成时间判断准时或延迟周次 | 不需要 | 按周更新；同阶课程常复用上一期资源配置并平移时间 |
| C 类课程 | 闯关课程 | 闯关进度/遍数规则 | 按闯关规则处理，不得套用 B 类口径 | 独立闯关节奏 |

## 使用规则

1. 讨论新课程前先确认 A/B/C 体系，再进入该体系自己的模板、配置迁移、完成算法、`next_update` 和校验流程。
2. A 类的 `video_duration` 必填校验不得套到 B 类。
3. B 类同阶新一期默认复用最近一期的 `lesson_id2 / shop_id / video_duration（通常为空）/课程结构`，按新开课日和课次周数重算 `start_date / next_update / end_date`；视频链接通常不会每期重找。
4. C 类使用独立的闯关进度/遍数语义；B 类观看 30 分钟也不等于完成。
5. “念住”一词可能同时出现在普通月课与闯关课程中：普通念住月课归 A 类；明确的念住闯关归 C 类。

B 类继承后仍必须在正式采集点做资源体检：统计已开课课次的导出用户、本期名单交集和实际有进度人数。覆盖率与开课时长、业务反馈明显冲突时，阻断 Step 2–4；只有同时发现新圈子、新课程容器或资源身份冲突等证据，才进入重新查找 `communityId / course_id / p_id / resource_id` 的例外流程。未到采集点不得因低覆盖率提前换源。

## B 类不是一套统一返款规则

B 类只定义独立的处理体系，不定义统一金额。不同阶次可以有不同的计费课数、单课金额、视频上限、延期规则和打卡规则。不得设置“B 类默认每课 N 元”，也不得回退到 A 类公共视频规则。

B 类不存在局部视频返款：不足 100% 的观看进度一律返款 0，累计观看时长不能替代完整看完。未完成进度统一四舍五入为整数百分比显示，单元格不着色；只有准时完整看完才返该课完整单课金额。

B 类视频返款以考勤表第 3 行“视频应返款”备注为业务事实来源，标准写法例如：

```text
39课×18元=702元
```

Step 3 必须解析并验证三项信息：计费课数、单课金额、视频返款上限。随后校验：

- `计费课数 × 单课金额 = 视频返款上限`；
- 计费课数等于视频配置中实际参与返款的课次数；
- 解析失败、数值不自洽或课次数不一致时，阻断返款计算；
- 禁止静默使用 0、20 元或其他课程的默认金额继续执行。

第 3 行备注不是仅供展示的说明文字，而是业务规则配置。表头展示、Step 3 标量结果、单元格公式和付款前预检都应引用同一解析结果。

B 类打卡返款同样逐列读取第 3 行备注。共学可使用 `9次×每次10元=90元`，各共修项可使用 `1次20元，3次40元`。Step 3 根据实际存在的共学/共修列逐项生成公式并汇总上限；缺列、空备注、无法解析或金额不自洽时阻断，不使用通用打卡默认规则代替。

## 当前实现映射

- A 类：`VIDEO_RULE_SYSTEM_REGULAR`
- B 类：`VIDEO_RULE_SYSTEM_ZEN_STAGE`
- C 类：`VIDEO_RULE_SYSTEM_CHALLENGE`

代码判断与业务代号必须保持一致，但不能因为当前代码使用同一个模块或枚举，就推断三类共享业务模型。业务文档和日常交流优先说 A/B/C 体系，避免只凭课程名称猜算法。

## 回归探针

- `d260701第42届念住` 缺少 `video_duration`：开课前校验应失败（A 类）。
- `d260705禅宗11期3阶` 的 `video_duration` 为空但 `lesson_id2` 完整：开课前校验应通过（B 类）。
- B 类 `progress=18.94` 且累计观看超过 30 分钟、平台未完成：显示无底色的 `进度19%`，返款 0。
- 名称包含“念住闯关”：必须命中 C 类，不得按普通念住 A 类处理。

## 本约定来源

在修道班 11 期 3 阶配置检查中，曾把 A 类课程的时长必填规则误套到 B 类，进而把 B 类正常为空的 `video_duration` 误报为运行阻塞项。该案例说明：课程类型必须先于字段完整性判断，不能先套通用字段清单再按名称补例外。
