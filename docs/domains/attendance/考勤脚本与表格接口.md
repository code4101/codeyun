# CodeYun 考勤公共接口

> Last Updated: 2026-08-30

本文只说明考勤能力边界与公共入口。请求字段、默认值、响应、错误码和示例由 OpenAPI schema、Python docstring 或 CLI `--help` 维护，不在本文复制。

## 运行边界

- 考勤生产统一运行在 `codepc_mf`；它同时承担 CodeYun、行为树、星云表格和小鹅通/微信支付自动化。
- `codepc_mi15` 已退出考勤生产，不是执行设备、数据源或失败回退。
- 课程业务编排位于 `xlproject/src/xlsln/kq5034`；CodeYun 提供鉴权、运行、表格和考勤业务接口。
- 日常调用只使用公共 API 或课程对象的公开方法，不调用 `backend.*` 私有函数、爬虫内部对象或存储实现。

## 公共能力

| 能力 | 公共入口 |
| --- | --- |
| 可信 Python 任务提交与状态 | `POST /api/device-control/python-runs`、`GET /api/device-control/python-runs/{run_id}` |
| 结构化表格读写 | `GET/PATCH /api/note-sheets/sheets/{sheet_id}/table` |
| 考勤主数据导入与状态 | `POST /api/device-control/attendance/master-data/import`、`GET /api/device-control/attendance/master-data/status` |
| 订单核验或退款动作 | `POST /api/attendance/order-execute` |
| 退款明细与历史 | `POST /api/attendance/order-refund-details`、`GET /api/attendance/order-refund-history` |

表格上的订单匹配、用户匹配、综合更新和课程 Step 应优先使用页面动作或相应高层业务入口。新增业务能力时先扩展这些契约，不为 Agent 编写“先读表、再拼参数、再写多个位置”的替代流程。

## 服务端责任

公共接口必须在内部承担：

- 鉴权、目标设备选择与正式运行环境加载；
- 业务 ID 解析、默认值和输入校验；
- 幂等、并发版本、事务、备份及失败语义；
- 原始文件归档、解析、去重和规范化存储；
- 订单/用户匹配与报名表到考勤表的一致性更新；
- 长任务状态、结果查询和安全重试所需的执行事实。

调用方只表达业务对象和动作。若现有接口迫使调用方理解 token 加载、数据库表、内部函数、浏览器状态机或多步落盘，应把能力收回服务端，而不是把步骤补进 skill/doc。

## 数据事实

- 用户与支付主数据由 mf 采集并保存在 mf 的 CodeYun 数据工作区；旧 PG 表只在迁移观察期只读核对。
- 小鹅通、支付和微信登录态以 mf 的真实环境为准。
- 表格 API 提供结构化字段、行和并发版本；调用方不依赖前端 DOM 或滚动位置。
- 长耗时动作使用服务端任务状态；写操作必须能够区分校验失败、冲突、已执行、执行中和内部失败。

## 验收

- OpenAPI 能独立说明每个公共入口的参数与副作用。
- 聚焦测试覆盖成功、校验失败、冲突、重复调用和超时后查询。
- 真实 mf 入口验证数据写入、页面投影与业务结果一致。
- 全库搜索不再让 skill/doc 引用考勤私有函数、内部表或 mi15 生产路径。
