# 凡修兽魂研究与自动配置

> 状态：研究中  
> 建立时间：2026-08-08  
> 最后更新：2026-08-09  
> 目标入口：`/fanxiu/calculator`

## 1. 最终目标

在不影响凡修工程 Scheduler 到期作业的前提下，完成一条可验证、可停止、可恢复的兽魂闭环：

1. 读取当前兽魂库存、等阶、战力、形状和上阵状态。
2. 计算形状约束下的最高总战力摆法。
3. 求出为保留最优摆法候选所需的最小安全前缀，而不是机械固定“只留前 7 个”。
4. 在保护清单之外，计算快捷合成的最优策略与期望收益。
5. 仅在失败损失、材料选择和停止条件确定后执行真实合成。
6. 合成后重新读取库存、重新计算并调整阵容。
7. 将真实数据、保护清单、合成建议和最终摆法接入 `/fanxiu/calculator`。
8. 最终形成一个单独的标准作业“兽魂更新”，每周二 00:30 触发，一次运行完成观察、保护、自动合并、重新计算和最高战力摆放。

## 2. 强约束与动作门卫

- 工程 Scheduler 的到期作业始终优先；研究 Cell 只能在足够空闲窗口内运行，并可被抢占。
- 动态插桩严格只读：只允许进程外读取进程内存、映射、已保存数据包和数据库快照；禁止注入、Hook、调用游戏 Lua 或发送游戏命令。
- 未确认合成失败损失规则、快捷合成实际选材规则、保护清单和停止条件前，不点击真实合成。
- 未确认新方案总战力不低于当前方案前，不改动当前阵容。
- 最高价值候选不能只按等阶保护；必须按真实战力、形状、当前上阵状态和最优解敏感性共同判断。
- 任何一次真实副作用前保存库存快照、当前阵容、计算结果和动作参数；动作后重新读取事实，不按动画或按钮响应推断成功。
- 不确定时安全停止并保留现场。

## 5. 当前已知事实

1. 当前计算器使用浏览器 LocalStorage 键 `soul_backpack_v7_vue`。
2. 当前算法把每个兽魂视为“形状 + 评分”的一次性物件，在 5×6 棋盘上最大化评分和。
3. 当前算法接受用户预先旋转/翻转后的形状，但尚未在搜索内部自动枚举所有朝向。
4. 当前页面没有游戏库存 API、兽魂稳定 ID、等阶、锁定/上阵状态、数据来源或合成策略模型。
5. 用户截图中的快捷合成页面显示：目标为“随机二级魂晶”、材料为“消耗所有一级魂晶”、每次消耗 2、成功率 55%。这只证明当前 UI 展示，不证明后台失败结算和期望最优性。
6. 正确 UI 入口已真实验证：`#34[打开下方菜单] -> #35 菜单内“灵兽”图标 -> 灵兽页底部“兽魂”`。在 #35 中点击“灵兽”文字中心无响应，点击文字上方对应图标后成功进入。
7. 灵兽首页底部有五个页签：灵兽、圣兽、拟态、灵阵、兽魂；“兽魂”位于最右下角。
8. 兽魂主页真实显示 5×6 槽位盘、当前占用 `魂·胎光（29/30）`、下方魂晶候选卡片与锁定标记，并提供“总加成”“共鸣”“词条预览”“合成魂晶”入口。
9. 兽魂主页已正式标注为 `#478`，并以“兽魂 / 魂胎光 / 合成魂晶”等稳定身份 shape 识别；Runtime 不再把旧的 `current_scene=35` 当作兽魂页身份真值。
10. “总加成”是无损信息弹窗，当前阵容展示：魂元、气血加成、灵蕴、命源、御甲、锋锐、四象魂元、御兽神资、兽神无双，以及四条特殊词条。优化目标因此不能只使用单一面板分数。
11. “共鸣”是按已装配魂晶的“共鸣道资”总值触发的阈值系统；当前总值 141，已达到 125 档，下一档为 165，并明确“同类型效果只生效最高阶”。
12. “词条预览”展示等级化战斗词条及对应属性/触发机制，进一步证明组合价值可能非线性。
13. “合成魂晶”进入独立弹层，底部有“合成 / 快捷合成”两个页签；普通合成页有目标等级下拉、材料列表、“一键放入”和最终“合成”，至少放入 2 个魂晶。
14. 快捷合成材料等级下拉覆盖一级至五级，语义为消耗背包内所有相应等级魂晶；每次消耗数量可选 2/3/4/5，对应 UI 成功率依次为 55%/70%/85%/100%。探索后已恢复默认 2，未执行合成。
15. 候选魂晶卡片单击只打开详情，不会直接镶嵌；详情明确区分“收藏”和“锁定”。锁定状态会进入 `V_ExcludesList`，快捷合成请求 `CM_JadeOneKey` 显式携带排除表。
16. 候选卡片单击进入详情；详情“镶嵌”会由 `CheckEmbedJade` 按服务端 row 1→5、column 1→6 找首个合法位置并调用装配，已上阵详情则显示“卸下”。正式自动摆阵因此采用“卸下 + 计算可达镶嵌顺序”，不依赖不稳定的长按拖拽。
17. 快捷合成响应 `SM_JadeOneKey` 含 `success / failure / critical / successItem / costResults`；客户端按服务端返回的 `costResults` 删除材料并加入 `successItem`。客户端代码可证明实际损耗由服务端逐次返回，但尚不能仅凭静态代码证明每种失败情形固定保留哪一个材料。
18. 当前只读内存库存共 886 件：一级 474、二级 258、三级 140、四级 4、五级 0、六级 3、七级 4、八级 3；四级及以上共 14 件。当前上阵 8 件，棋盘占用 29/30，与 GUI 一致。
19. 当前运行态可从 `BeastSpiritMgr` 读取上阵/形状/概率/属性/技能配置，从 `BackpackMgr._BeastSpiritItemDic` 读取库存，从 `DBMgr.ConfigDic` 读取已加载 Pet 配置。读取严格采用模拟器进程外内存解析，不调用游戏 Lua，不注入、不 Hook。
20. `Pet.PetJadeShape` 的形状字符串已确认可直接转为格坐标，例如 `1|1,2|1_2`；运行态单件扩展字段包含 level、rows、grids、viceEntries、mainEntries、embed、cell、configId、itemId，可覆盖库存、形状、词条和上阵状态建模。
21. 合成期望的鲁棒结论：若失败保留一件，则每成功升一级的期望同级材料消耗为 `(n-1+p)/p`，2/3/4/5 件依次约为 2.818/3.857/4.529/5；即使悲观假设两件失败全部损失，2 件成本 3.636 仍低于三件在“失败保留一件”假设下的 3.857。因此在现有概率表下，每次 2 件不依赖尚未证实的失败保留规则也最优。
22. 运行态棋盘空格使用长整数哨兵 `1`，不是 `0`；只有同时出现在 `serverData.jades` 的稳定 ID 才能视为占用。按此规则当前占用为 29/30，与 GUI 一致。
23. `ext.cell=6` 不是魂晶形状格数；真实格数必须由 `Pet.PetJadeShape.shape` 坐标计数。当前高分魂晶均为四格，一级填充魂晶为一格。
24. 真实详情样本“神品二星魂晶”稳定 ID 为 `24082878064165187`，等级 7、形状 403。其总评分 1,377,500 精确等于副属性分数 827,250 + 161,450 与两条技能分数 194,400 + 194,400；主属性配置的 score 为空，不参与该总评分。由此已反校 `PetJadeAttr` 第 8 列和 `PetJadeSkill` 第 9 列的评分语义。
25. 当前固定形状全库存精确优化结果为 11,367,050，和现阵评分相同。最优解使用评分排名 1、2、3、4、5、7、8，第 6 名因形状未入选，因此安全保护前缀为 `K=8`。

## 7. 决策记录

### 2026-08-08：先建模型，后做副作用

- 0点前只做离线审计，不进入兽魂页面。
- 不把“55%”或“两材料最好”直接固化成策略。
- 先求保护集合，再讨论可消耗集合；顺序不能颠倒。
- 真实验证以最低价值非保护材料开始，并要求前后库存对账。

### 2026-08-08：先 UI、后逆向、再数学、最后业务闭环

- 第一阶段先建立真实 UI 功能地图，理解控件如何来回切换以及哪些动作有副作用。
- 第二阶段才把 UI 控件映射到客户端逆向代码、只读 Manager 数据和服务端交互。
- 第三阶段分析合成期望、保护前缀和形状装箱问题。
- 最后实现独立手动作业“兽魂更新”；它包含自动合并和最高战力摆放，但不设置自动触发时间。

### 2026-08-09：#35 按覆盖层操作，不强制走普通 goto

- `goto(35)` 首次真实尝试超时，未形成可靠菜单展开证据。
- 下一次改为复用邮件作业已经验证的底层片段：在 #34 点击“打开下方菜单”，短等待后从 #35 的“菜单” envelope 读取直播 OCR。
- 只有 OCR 唯一命中“灵兽”且点击点位于菜单 envelope 内时，才允许点击；不使用历史截图固定坐标直接猜。

### 2026-08-09：兽魂 UI 正式归档到 `资源/兽魂`

- 用户已明确授权本次兽魂 scene/shape 和目录调整。真实帧建立 #478～#483，并统一归档到一级目录 `资源` 的 `兽魂` 子目录。
- 入口、弹层切换、关闭、锁定、镶嵌/卸下、材料下拉均使用正式 shape；背包和棋盘的动态位置由资产网格锚点推导，不保存业务固定坐标。

### 2026-08-09：合成默认每次 2 件，但真实动作继续受保护集合门卫约束

- 2 件方案在已验证概率下具有严格的期望材料优势；即使失败保留机制取对它不利的边界，仍优于 3/4/5 件。
- 该结论只决定“每次消耗数量”，不授权真实合成。真实动作仍要先完成稳定 ID、评分、锁定真值、上阵集合和最优保护前缀核对。
- 快捷合成的“消耗所有某等级”必须逐等级执行并在每批后重新读取、重算；禁止从一级一路无检查连锁到高阶。

### 2026-08-09：正式布局使用固定形状；当前不重摆

- 客户端没有发现旋转/翻转操作，拖拽始终使用 `configId` 的固定形状，因此正式求解 `allow_transform=False`。
- 当前布局已达到固定形状全局最优评分，执行重摆没有收益，只会引入拖拽和覆盖风险；本轮不动阵容。
- 保护集合按排名前缀而非仅按实际入选：当前 `K=8`。执行合成前必须把第 3 名未锁魂晶补锁，并验证 `top8 ⊆ locked`。

### 2026-08-09：高阶规则分档，完整批次不足即停止

- 一级至三级使用 2 件/55%；真实批次证明失败会损失两件，因此单位成功成本为 3.636 件，仍优于其它低阶数量选项。
- 四级及以上的真实快捷页固定为 3 件/100%，不能复用低阶概率表。
- 每批后重新读取并精确求解；只统计未上阵、未锁定、未被服务端排除的材料。可消耗数不足一个完整批次时正常结束，绝不解锁保护项。
- 手动作业当前可安全完成盘点、深层背包保护项锁定和固定形状重排；任何身份指纹并列、可见场景异常或首次适配落点偏离规划都会失败关闭。逐级合成还须补齐结果弹层正式资产后才算 UI 闭环完成。

### 2026-08-09：正式摆阵使用原生首次适配，不使用拖拽

- 逆向确认详情“镶嵌”会调用游戏自身 `CheckEmbedJade`；真实一级样本也准确落入首个合法格 `(5,4)`。
