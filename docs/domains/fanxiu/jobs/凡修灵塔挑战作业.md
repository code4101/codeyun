# 凡修灵塔挑战作业

## 今日完成口径

- 每日上限：游戏出现“每天可挑战20层，已达上限”，确认今日完成，退出后安排明日 07:00。
- 战力极限：未满 20 层也可能在任意一层失败；出现已标注的 `#365`“变强/退出”即确认今日已打到极限，哪怕本轮 0 层通过也属于正常完成，退出后安排明日 07:00。
- 未见过的新失败汇总或结算样式不类推点击：保留防重复执行标记和真实帧，补充最小资产后再收口，禁止重复点击“挑战”。

## 目标与边界

`灵塔_挑战` 与 `日常_灵塔` 是两个不同业务：

- `日常_助手` 已包含灵塔扫荡，领取昨天最高层对应的扫荡奖励。
- `灵塔_挑战` 每天 07:00 后进入混沌灵塔，尝试提升历史最高层，直到战力极限、当日 20 层上限或已经没有下一层。
- 一层都无法通过是正常业务结果，不应记成 Scheduler 执行错误。
- 作业只在工程 Scheduler 空档研究和验收；正式上线后由唯一 Scheduler 在工程模式派发普通 Cell。

本作业额外要求按以下顺序取证：

1. 先读取 Scheduler 状态和近期到期作业；只有空档才切到 AI 运行权并发送普通调试 Cell。
2. 通过 #34「日常」进入 #69，在列表中查找“灵塔”，复用已有 #193/#194 路线。
3. 进入 #194 后保存当前真实帧、资产树 SHA-256、待修改节点摘要和回滚备份。
4. 用严格只读动态探针读取 `CapacityTowerDungeonMgr.Model.curTowerMsg`，记录点击前后的 `curTowerId`，不得调用 `Inst_get`、`CM_SyncCapacityTower` 或任何主动刷新方法。
5. 对当前塔卡片、详情页开始按钮、胜利自动续层页、胜利静态 `下一层` 等级门槛页、普通/灵塔专用失败页、20 层终止页和离场按钮逐帧标注。动态列表项优先标注稳定容器或 OCR 关系，不把某次塔名、层数或固定坐标误当成永久事实。
6. 修改资产后回读唯一路径，并验证当前正样本、相邻负样本、重复 ID/文件名与图模型分数；执行 shape 还要用真实 Runtime 动作验证落点和 `sceneJumpTarget`。
7. 正式作业采用点击前防重复执行标记。进入自动连战后只观察，不重复点击开始；未知战斗/加载帧保留现场，避免错误导航。

防重复执行标记不只在 Job 单测中模拟：外部 Scheduler 提交 Cell 前持有的 task 对象可能早于运行中标记。正式写回链会在 Cell 结束后重新读取磁盘上的最新 task，再写入本次 attempt 的 terminal 字段；回归测试模拟 Cell 运行中加入 `lingta_auto_chain_started`、随后异常返回，确认 10 分钟错误重试时间写回后标记和原 payload 都仍保留。禁止把 terminal 写回改回提交前的旧整行快照。

启动标记不能只保存“已经允许过一次挑战点击”。自动链每观察到更大的完整只读 `chanllenge` 值时，还会原子更新同一标记的 `max_chain_pass_count`、`last_tower_id` 和 `last_observed_at`。因此未知结算页触发 error 后，即使客户端在十分钟重试前自动回到世界并卸载或清空 CapacityTower 模型，已真实观察到的胜利次数仍有持久证据；下一次完整 Job Cell 可据此收口，不能因为内存模型已经不可读就永久卡住，也不能再次点击挑战。

普通 Scheduler `attempt_failed` incident 只保存运行状态和近期日志，不会替业务自动截取当前游戏帧。因此作业在等级门槛、专用失败汇总、全塔终态、`已通关`、点击后仍停留 #532 以及自动链监控超时等未知终点抛错前，必须显式调用统一 unknown-evidence 管线，把当帧 PNG 和诊断 JSON 写入 `%TEMP%/codeyun/fanxiu_unknown/`，并把两条路径追加到错误消息。只有防重复执行标记与这份真实帧同时落盘，文档和日志才能称“进度和现场已保留”。

错误重试也不能永久卡死：若首次 Cell 保留防重复执行标记时游戏仍处在未知结算页，但重试前客户端已经自行回到 #34/#194，作业可读取标记的 `start_tower_id` 与当前只读快照。只有“当前配置主键确实变化”或“本轮连续胜利计数大于零”才能证明那一次获准点击已经推进并结束；此时清标记、回到世界并写次日 07:00，同时明确记录为“已由当前事实证明收口”。若只是回到稳定页面而主键和计数都没有变化，证据不足，继续保留标记并拒绝第二次点击。
