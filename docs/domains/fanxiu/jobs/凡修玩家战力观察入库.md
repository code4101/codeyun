# 凡修玩家战力观察入库

## 统一入口

生产代码统一调用：

```python
from backend.core.fanxiu.player_profiles import ingest_fanxiu_player_battle_observation
```

最小本体战力观察字段为：

- `observation_id`：来源内稳定、可幂等的事件标识。
- `source_kind`：明确的数据来源。
- `role_id` / `role_id_text`：权威角色身份，不能只靠昵称。
- `battle_score`：正数本体战力。
- `observed_at`：该战力实际被观察到的时间。

`attack_value` / `attack_text` 可缺省。历史表的物理唯一列仍名为 `packet_id`，统一入口把来源中立的 `observation_id` 投影进去，避免破坏历史数据库。

仙侣队观察只公开 `xianlv_team_fight_score_max` 与 `xianlv_team_observed_at`，表示当前能找到的该玩家最高仙侣队战力。本体与仙侣指标可以分属不同事件，互不覆盖。队号不是图鉴维度；来源若能严格证明队号，只能把它作为内部 `evidence` 保存，不得进入图鉴字段、排序或合并规则。

## 摘要规则

- 本体：同一角色同一天先取最高 `battle_score`；同分优先带攻击的完整记录，再取较新观测。
- 仙侣：同一角色同一天先取最高 `xianlv_team_fight_score_max`，同分取较新观测。
- “最新玩家”先确定最新日期，再使用该日代表记录，不能用较早日期的历史峰值冒充当前值。

## 当前接入与后续清单

本轮已接历史玩家面板适配器，`SM_ShowOther` / `SM_SyncPlayer` 即使没有攻击字段，只要本体战力事实完整也会进入统一入口。图鉴 API 同时提供本体每日/最新与仙侣每日/最新投影；底层保留两项指标各自的精确观测时间，每人每天分别只投影最高一条。页面以本体战力排序，只展示战力与仙侣战力；指标来自当天时保留彩色强调，不是当天时显示为灰色。攻击仍可作为底层观察附属事实保存，但不进入玩家面板主表。

后续生产者按各自真实证据逐项接入，不做全仓机械写库：

- `instrumentation/role_progression.py`：自身本体战力。
- `instrumentation/seat_runtime.py`：席位角色本体战力。
- `instrumentation/dongtian.py`：洞天席位角色本体战力；守卫仙侣队只写可证明的最大观测战力。队号如有，只作为生产者内部证据。
- 论道、灵脉、道法和仙缘斗法：只在已有读取结果同时具备角色 id、时间与稳定事件 id 时调用统一入口。

业务选择器不应自行写 SQL；它们只提交观察事实。写入失败不得影响原玩法的只读判断或动作闭环。
