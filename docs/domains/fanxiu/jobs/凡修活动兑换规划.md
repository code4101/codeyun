# 凡修活动兑换规划

各类活动虽然使用不同的兑币、挑战方式和运行态数据，但产品问题一致：根据最近批次的真实收益，判断为了兑换目标资源还需要挑战多少次。

## 能力边界

通用层只负责：

1. 接收按时间排列的累计兑币测量；
2. 选取最近一段“挑战次数大于 0、兑币增量大于 0”的有效样本；
3. 保留整数比率，按向上取整计算每个累计兑币目标的剩余挑战数；
4. 已达成目标、无限兑换项或没有可靠样本时返回空值。

活动适配层负责：

- 从游戏运行态取得积分、兑币、挑战次数和活动特有结果；
- 校验一次测量确实属于当前活动和当前批次；
- 把测量追加到该活动的数据库历史；
- 根据优先级、锁定和限购规则生成累计兑币目标；
- 处理胜负收益不同、门票消耗、每日上限、多种兑币或阶段奖励等特殊机制。

因此，共享的是“规划问题”，不是不同活动的插桩字段或收益假设。公共层把一次活动执行称为 `attempt`；云梦可展示为“挑战”，兽渊可展示为“探索”。新活动只需把自己的测量记录规范化为 `ExchangeMeasurement`，再调用 `latest_exchange_yield_rate` 和 `estimate_remaining_attempts`。

## 当前策略与演进

当前速度采用最近一个有效批次，最贴近玩家刚才的实际配置与胜率。后续若样本增多，可在通用层新增明确的速率策略，例如最近批次、最近若干批加权或保守分位数；活动仍可选择适合自身机制的策略，而不改变前端“还需挑战”的业务语义。

云梦试剑是首个接入活动。2026/8/2 的真实样本为 100 次挑战获得 27,984 兑币，即 279.84 兑币/次；从 43,910 兑币达到 482,100 兑币需要 1,566 次。
