# 凡修活动答题作业

> Last Updated: 2026-08-02
> 面向后续 AI/开发者的功能上下文；运行前必须阅读。

## 业务事实与启动授权

- `活动_答题` 每天只有一次机会，共 15 题，按 5 题一批分三批进行；当天完成后不能为了调试或验收重跑。
- 只有用户明确发出“开始/启动活动_答题”等肯定执行命令时，Agent 才能提交 `activity-quiz` Scheduler Cell。
- “现在启动活动_答题？”、“能不能跑”、“先看看状态”等带问号或讨论性表达只授权只读检查，不授权启动。无法确定时等待用户明确说“开始”。
- 启动授权只覆盖当次运行，不覆盖补跑、重跑或下一天。
- Agent/命令行使用 `scheduler-task activity-quiz` 或 `task activity_quiz` 时还必须显式追加 `--confirm-one-shot`；缺少该参数会拒绝启动。该参数只表示“已确认用户明确授权”，不能替代授权本身。

## 时间预算

真实画面包含约 3 秒读题阶段和约 10 秒选择阶段。业务链的优先级固定为：

1. 作业等待首题时非阻塞预热游戏 Runtime 题单；题目阶段用 OCR 题号与题面双重校验动态配置答案，再降级匹配 CodeYun 内存题库。
2. 动态配置或题库已知时不请求 AI；未知题只在状态中标记，不能在选项出现前提交不完整问题。
3. 选项出现后，动态配置/题库命中立即用固定位置点击；未知题首次 OCR 出三个选项后异步请求 AI 只返回 A/B/C。
4. 点击后优先捕捉游戏给出的正确/错误标记。
5. 每五题批量落库，避免点击前同步写数据库。

倒计时期间禁止从其它进程执行以下操作：

- `doctor --screenshot` 或 ADB 全量截图；
- 全资产树场景识别、OCR 调研或视觉诊断；
- 会争用模拟器、画面流、OCR 或 Kernel 的其它 Cell。

运行中监督只读轻量 Runtime/Kernel 状态。开始前可保存一张起点帧，Cell 结束后再保存终点帧；实时证据由主 Cell 自己记录题号、点击来源、游戏真值和耗时。

## 答案优先级

```text
游戏明确对错（权威真值）
  > 当前活动 Runtime 配置答案（题号 + 题面校验）
  > 已验证题库答案
  > gpt-5.3-codex-spark 暂定答案
```

- 作业启动后先在后台读取 `CampAnswerMgr` 已下发的题单。静态逆向显示 `CampAnswerVO.questions` 在请求下一题前已经持有每题 `configId`，客户端用该 id 查询 `CampAnswer.CampAnswer`，其中直接包含题干、三个 option id 和正确 `answer` id；显示对错也使用同一客户端配置比较。
- 动态答案只有在清单题号与 OCR 题号一致、配置题干与 OCR 题面达到 82 分模糊阈值时才获得点击权。普通答题客户端按配置顺序显示三个选项，没有决赛的随机打乱步骤，因此正确 option id 可直接换算为固定 A/B/C 位置。
- 动态答案命中并经游戏真值确认后，题库落库使用 Runtime 配置中的标准题目和三个标准选项；只有动态数据不可用时才保留 OCR 文本，OCR 选项入库前统一删除标点符号。逆向导入会在题目近似且正确答案一致时合并旧 OCR 重复题。
- 动态快照不可用、过期或校验不一致时，原题库与 AI 路径保持不变；游戏明确对错仍覆盖所有来源并写入题库。
- 未知题等三个选项首次出现后，后台线程把“题干 + A/B/C 三个选项”提交给本机 Codex CLI 的 `gpt-5.3-codex-spark`；模型只返回结构化字母，省掉自由文本答案到选项的二次模糊匹配，主抓帧循环不能等待它。
- AI 在本题仍处于可答状态时返回，主循环可以点击它给出的选项。
- 游戏已经给出对错后，迟到的 AI 结果直接丢弃，禁止覆盖真值。
- 题目已经结束且没有捕捉到游戏真值时，AI 结果可异步写入题库，但必须标记为 `activity_quiz_ai:<model>` 暂定来源；后续真实结果会覆盖三个选项状态与来源。
- 2026-08-02 旧版“只发题干、返回答案短语”的本机冷启动探针约 16.3 秒，慢于一次 10 秒选择窗口。新版 A/B/C 请求尚未经过下一次真实活动计时，因此 AI 仍只能视为机会型兜底和事后知识补全，不能先宣称实时提速已经通过。

## 实现地图

- `backend/core/fanxiu/data_annotation/tasks/activity_quiz.py`：15 题单 Cell 流程、点击、真值采集、异步任务编排和来源统计。
- `backend/core/fanxiu/instrumentation/camp_answer.py`：非阻塞读取普通活动题单、配置选项和正确位置；当前仅完成静态逆向与离线测试，等待下一次活动窗口真实验收。
- `backend/core/fanxiu/choice_knowledge/activity_quiz.py`：选项面板快速检测、固定点击点、题库答案映射。
- `backend/core/fanxiu/choice_knowledge/activity_quiz_ai.py`：Codex Spark 请求与结构化结果解析。
- `backend/core/fanxiu/choice_knowledge/store.py`：真实结果与 AI 暂定结果的持久化优先级。
- `backend/tests/test_fanxiu_activity_quiz_ai.py`：迟到 AI 丢弃、AI 暂定答案、游戏真值覆盖。
- `backend/tests/test_fanxiu_activity_quiz_state.py`：题号单调推进、三批状态、来源统计和 Scheduler 标准作业契约。

## 活动_答题决赛预备功能

- 决赛是独立手动作业：`task_type=activity_quiz_final`、Scheduler id `activity-quiz-final`、显示名“活动_答题决赛”。只有用户明确说“启动活动_答题决赛”后才能追加 `--confirm-one-shot` 提交。
- 2026-08-02 预备阶段只知道核心场景 `#61 问道巅峰`，尚不知道入口、过渡页和结束页。因此 Job 只在一个 Cell 中有界等待并循环处理 #61，不猜导航；离开核心场景或长时间无新题后安全结束。
- #61 正式资产树已有 `题目 / 选项 / 正确题数` 三个 shape。本功能只读取这些既有标注，没有修改资产树。
- 决赛选项位置不保证固定。每道新题都必须重新 OCR 当前四个选项、按纵向视觉位置形成 A/B/C/D，并保留每一行在当前帧上的真实中心；题库命中后也只能按答案文本匹配本题选项再点击，禁止读取历史 `position`。
- 决赛采用严格题库白名单，但允许 OCR 容错模糊匹配：题干按现有 82 分阈值匹配既有题库记录，题库答案必须来自人工或游戏真值（AI 暂定知识不算已知），并且答案文本能唯一模糊匹配本帧四个选项时才允许点击真实选项。没有题库记录、低分或选项匹配歧义时，AI 只能使用右侧 `[外框]` 做旁路行提示，不能点击真实选项；同时继续等待用户作答并采集游戏真值。
- 当前只完成静态资产核对、纯函数测试和 Scheduler 契约测试。由于决赛未开放，尚未验证 #61 的真实 OCR token、点击坐标、换题时序、结束判定和总耗时；首次启动应视为真实验收，同时禁止并行截图或重型 doctor。

### 2026-08-02 首次真实运行复盘

- 本轮题库没有命中；Spark 从请求到“准备点击”的可见样本约为 27 秒、18 秒、8 秒、8 秒，均没有证据证明抢在用户手动作答前生效。用户实际完成答题，因此本轮自动答题效果应判定为失败，不能用点击调用数冒充完成题数。
- 初版没有识别 #61 结果页的绿色正确标记，也没有保存本轮题干、四个选项和正确位置；现有日志不足以事后恢复整套答案。
- 已修正规则：每帧先检查当前四行右侧的绿色正确标记。无论答案由用户、题库还是 AI 点击，只要游戏给出标记，就把“题干 + 本帧四个选项 + 正确位置”按 `activity_quiz_final` 上下文写入共享题库，并明确保持 `options_order_fixed=false`；绿色标记出现后迟到 AI 不得再点击。
- 统计改为 `click_attempts` 与 `confirmed_answers` 分离；只有检测到游戏真值才计入 `answered/confirmed_answers`。本轮 `run_status=error` 曾触发通用十分钟重试，已立即把手动作业 `next_time` 清回 `None`，禁止未经再次授权重跑。
- 用户复盘确认决赛中 AI 曾答错、操作迟缓并干扰人工选择，因此 Spark 永久没有决赛真实选项的点击权。后来在 `#61` 右侧新增 `[外框]`：未知、低分或选项歧义题可在四个选项完整出现后异步请求 Spark；结果返回后，只按当前 OCR 选项行的实时 `y`，每秒点击一次 `[外框]` 的横向中心作为视觉旁路提示。该落点不属于真实选项，因此不会抢占或修改用户选择。为避免结束窗口和持续触点干扰，每题默认最多提示 3 次；任一当前帧识别不到题面后永久停止该题提示，题目切换、游戏出现绿色正确标记或任务结束后也立即停止。若捕捉到游戏真值则丢弃 AI 结论，否则 AI 选择仅按暂定知识保存。

### 动态插桩答案源（待下次决赛窗口实测）

- 静态逆向已确认：服务端刷新包把当前 `questId / progress / startTime` 写入 `FinalCampAnswerMgr.Model.FinalCampAnswerData._questInfo`；客户端再查 `CampAnswer.CampAnswer` 得到题干、四个 option id 和正确 `answer` id，并查 `CampAnswer.CampOptions` 得到答案文本。界面会随机打乱 option 配置后再显示，因此配置顺序不能直接当作 A/B/C/D。
- 决赛循环现在优先请求非阻塞 Runtime 快照。只有快照新鲜、内存题干与当前 OCR 题面模糊一致、正确 id 属于当前题四个配置项，并且正确答案文本能唯一映射到本帧重新 OCR 的某一行时，动态插桩才有真实选项点击权。最终点击仍使用当前行中心，不使用历史位置或配置序号。
- 作业一启动就在等待 #61 的阶段非阻塞预热动态插桩，避免模拟器重启后的首次管理器扫描占用第一题窗口；每道新题仍最多等待 `1.2s` 获取本题新鲜快照，画面循环不阻塞。超时、旧题缓存、字段缺失、题面不一致或选项映射歧义都会拒绝插桩点击，然后依次降级到权威题库真实点击、Spark `[外框]` 旁路提示。
- 日志记录 `questId / progress / answerId / 快照 age / 最终 OCR 行`，结果统计增加 `native_snapshot_reads / native_clicks / native_fallbacks`，便于下次按题核查准确率与时延。游戏绿色正确标记仍是最高真值并负责入库。
- 当前只完成静态逆向、离线快照解析测试和动态乱序行点击测试。决赛窗口已经结束，尚未证明管理器根地址、字段形状、刷新时序在真实运行中稳定；因此保留题库与 AI 降级分支。下次真实运行验收通过后，再讨论删除 AI 分支。
