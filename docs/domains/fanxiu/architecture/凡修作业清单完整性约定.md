# 凡修作业清单完整性约定

## 当前目标

- Scheduler 作业更新按 `id` 做 upsert，未出现在请求中的作业必须保留。
- 默认作业读取时继续自修复；自定义作业不能因为其它作业的保存操作被删除。
- 删除作业必须使用独立、显式的删除动作，不能以“提交的清单里省略该项”表达。

## 根因记录

旧更新逻辑用“传入条目数是否小于现有条目数”猜测请求是局部更新还是整表替换。陈旧页面提交的列表如果与当前列表数量相同，但内容集合不同，会误走整表替换并删除未提交作业。默认作业随后可能被修复逻辑重建，造成前端观察到作业消失、配置丢失后又重新出现。

## 验收

- [x] 单条更新不删除其它作业。
- [x] 等长但 id 集合不同的更新不删除其它作业。
- [x] 空更新不清空作业。
- [x] 真实 Scheduler 读取仍返回 `legacy-daily-lingmai-clear`。
- [x] 真实行为树页面刷新后显示“灵脉_清体力”。
