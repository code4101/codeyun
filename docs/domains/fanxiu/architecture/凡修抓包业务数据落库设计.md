# 凡修抓包业务写入契约

抓包解析结果只有经过业务归一化后才能成为 CodeYun 当前事实。

## 写入模型

- 原始协议事实保持可追溯，不直接作为前端业务模型。
- 业务写入器使用稳定业务键、来源时间、packet 顺序和 schema 版本。
- 全量消息建立基线；增量消息只更新自己拥有的字段。
- 截断、乱序、旧水位和未知 schema 不得污染已确认的完整当前状态。
- 当前事实与历史事件分离；删除、领取、过期等终态不能反向证明不存在另一条同类实体。

## 完整性

每类投影必须明确：

- 幂等键与去重规则；
- 全量基线何时成立；
- 增量事件如何合并；
- 完整性、新鲜度和来源怎样对外表达；
- 未知消息、部分解码和迟到数据怎样失败关闭。

精确表名、字段和迁移由模型及测试维护，不在本文复制。
