# 凡修活动标准事实与兑换评估

## 边界

活动页面不直接读取游戏进程，也不把 PID、设备序列号、Lua 地址或采集缓存当作业务数据。

统一链路是：

1. 运行实例层动态识别当前正在运行凡修的设备与 PID。
2. 采集层从游戏结构化消息或只读 Runtime 获得原始事实。
3. 归一化层按稳定业务键写入数据库当前事实。
4. 活动适配层只声明本活动使用的游戏 ID，并把标准事实组合成一次活动观测。
5. 页面读取活动、观测历史和评估结果，不直接依赖游戏是否在线。

## 标准事实

### 资源当前值

- 数据库域：`resource_state`
- 稳定键：`currency:<resource_type>`
- 字段：`amount`、`borrow`、`available=amount-borrow`、`history`、`captured_at`
- 全量来源：`SM_Wallet`
- 增量后的绝对值来源：`SM_RewardResult`、`SM_CostResult` 中的 `ResourceVo`

活动不能为“论剑玉”“兽晶”等分别实现钱包读取器；它们只需要声明各自的 `resource_type`。

### 活动榜当前值

- 数据库域：`activity_rank`
- 稳定身份：游戏 `activity_id` 与榜单分组
- 字段：个人积分、个人排名、已加载名次、榜单人数、区服昵称和采集时间

活动只声明 `rank_activity_id`。奖励守门名次由该活动的奖励配置决定，不写死成 1/2/4/8/16/32。

## 活动观测声明

`ActivityObservationSpec` 当前包含：

- `rank_activity_id`
- `currency_type`

`collect_standard_activity_observation` 只从数据库标准事实组合观测。云梦试剑只是第一个调用方；后续活动复用同一入口，再在各自适配层增加特有的挑战批次、收益速度或奖励规则。

## 当前值与历史

- `FanxiuPacketBusinessRecord` 保存可覆盖的标准当前事实，拒绝旧封包回放覆盖新事实。
- 活动测量表保存不可变历史，用于计算最近批次速度。
- 页面“更新”把新的标准事实落成一次活动测量；没有新事实时不重复入库。
- 采集时间必须随事实保存。旧事实不能因为按钮刚刚点击就伪装成最新游戏状态。

## 性能与安全

- HTTP 请求不进行全进程内存扫描。
- 设备与 PID 动态识别；默认地址只可作为连接候选，不可作为账号身份。
- 多设备在线时优先选择真正运行凡修进程的设备。
- 运行实例变化只使采集层重新绑定，不改变活动、资源类型或数据库历史身份。
