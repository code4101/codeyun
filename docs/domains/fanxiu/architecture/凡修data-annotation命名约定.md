# 凡修 data-annotation 命名约定

> Last Updated: 2026-08-09

本文档是凡修 data-annotation / Runtime / Scheduler 的术语入口。GUI 场景、识别分层和图算法以
[凡修 GUI 场景地图与图模型约定](./凡修GUI场景地图与图模型约定.md) 为准。

## 术语约定

### scene / frame / view

- `scene/frame` 表示资产树中可识别、可操作的场景帧节点，例如 `#34 世界`、`#121 邮件`。业务代码、公开 API 和日志优先使用 `scene`；资产标注和识别算法可以使用 `frame`。
- 运行时刚取得的画面称为“直播帧”或 `live frame x`；`frame_data_url`、OCR 输入和匹配输入都属于直播帧数据。不得把资产 frame 与直播帧混为同一对象。
- view 是旧版兼容：保留 `View` 类、`wait_view()`、`goto_view()` 等历史入口，避免破坏旧代码和测试。新增业务代码不要继续扩散 `view` 术语。

### 资产树 / 识别图

- 资产树 `asset tree` 是标注资产的数据容器：目录/分组、scene 数据、shape 数据、OCR/图像匹配配置、`sceneJumpTarget`、人工归档事实都放在这里。目录嵌套只表示人工组织方式，不天然等于运行时 sub scene 关系。
- 识别图 `recognition graph` 的节点是场景帧。若场景帧 `b` 的参考图满足 `a` 的场景标识，则建立 `a -> b`。
- 对直播帧 `x`，命中的候选及候选之间已有的边构成匹配子图；按图距离选离 `x` 最近的节点，同距离时再用参考图与直播帧的全图相似度决胜。
- 识别图没有资产父子、目录祖先或 Shape 继承语义。资产目录嵌套和版面 Shape 嵌套不能生成识别边、扩展候选或参与去歧义。

### 一级业务分组

资产树中的业务目录统一使用 `日常 / 周常 / 资源 / 日程 / 活动` 五组。它们表达任务的主要业务生命周期和入口语义，不直接决定 Scheduler 的触发规则：

- `日常`：每天固定要完成的任务。
- `周常`：每周固定要完成的任务。
- `资源`：以领取资源或奖励点击为核心、通常可随时领取的任务。它不强制每天触发；即使工程上每天检查一次，也仍可归入资源。
- `日程`：`#66 日程`中的常规轮询活动。包括玩法榜的云梦、虚天、兽渊、魔道、下棋、仙盟等，资源榜的炼丹、淬体、灵兽、洗灵、仙花等，以及仙宴等有周期规律的内容。通常一个时段会同时存在一项玩法榜和一项资源榜，但具体活动会轮换，不保证每天或每周固定出现。
- `活动`：更长周期的游戏官方活动，例如节假日、新版本专题、灵石或付费抽奖道具活动、闯关和比赛等。

分类按主要原则判断，不机械只看执行频率。边界任务以主要入口、结算周期和用户理解为准；例如“奇袭魔界”每周累计七次，放入日常或周常都可能合理。新业务如果来自 `#66 日程`的轮询位，默认优先归入 `日程`；不要因为某次恰好连续开放数日就归入日常，也不要因为工程每天轮询资源奖励就改归日常。

### layer / layer0

- `layer` 只用于按顺序选择候选批次，不构成图层级，也不表达场景父子关系。
- `layer0` 是某次 Runtime 动作产生的动态业务候选集，可以来自当前步骤预设场景、当前点击 Shape 的后继先验或调用方显式目标。它不是资产图片的静态 `layer` 字段。
- `layer1` 是交通枢纽和典型菜单关键帧；`layer2` 是其余有场景标识的场景帧；`layer3` 是无场景标识、只用于全图相似辅助诊断的参考帧，不具备业务可消费的 scene id 语义。
- `layer0_wait_seconds` 是 `layer0` 的优先等待窗口。默认 30 秒；长过场入口可显式调大，例如仙府进入 `#171` 可用 60 秒。

## 主 API

- `current_scene()`：识别当前场景。
- `wait_scene()`：等待一个或多个目标场景出现。
- `go_scene()`：移动到目标场景，背后使用场景图和 `sceneJumpTarget` 做路径规划。

历史入口：

- `wait_view()`、`goto_view()` 和 `View` 仅是现存历史命名；新代码使用 scene API。

## 判断规则

- 写业务流程时，说“进入/等待/返回/跳转某页面”，用 `scene`。
- 写实时截图、OCR、匹配、裁剪、缓存输入时，用“直播帧”；写资产标注节点时可以用 `scene/frame`。
- 只有解释现存历史代码时才使用 `view`。

## 不要做的事

- 不要新增以 `frame` 命名的业务页面 API；业务 API 继续使用 `scene`。
- 不要新增 `current_view()`、`detect_view()` 这类新业务 API。
- 不要从资产目录、图片 children 或人工父字段生成任何识别关系。
