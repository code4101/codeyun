# 凡修逆向增量更新契约

逆向更新的目标是吸收版本变化，不是重复生成整套历史材料。

## 稳定流程

1. 识别输入版本并建立不可变 manifest。
2. 对 APK、热更新 Lua、配置和资源分别计算内容差异。
3. 只重建受影响的派生产物。
4. 用 schema、数量不变量、代表性样本和既有回归验证结果。
5. 只有新结构无法归类时升级 Agent；解决后把差异并回 parser、adapter、fixture 和测试。

## 数据边界

- 原始输入、派生输出和缓存位于 `D:\home\chenkunze\data\m2606凡修逆向`。
- 版本身份、业务身份和用户整理状态分离；更新不得覆盖人工策展字段。
- 生成物可重建，不进入 CodeYun 数据库充当权威配置。
- 已见差异进入 profile/adapter；未知差异必须失败关闭，不能用最相似旧版本强行解析。
