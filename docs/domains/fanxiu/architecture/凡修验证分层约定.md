# 凡修验证分层约定

凡修离线测试只负责能够脱离游戏本体确定证明的工程契约；GUI、Runtime-GUI 对齐和业务完成必须操作真实游戏验收。

## 离线门禁

仅保留以下测试：

- Python 语法、导入和前端构建。
- 纯函数算法、时间计算和数据转换。
- 基于真实最小样本的稳定解析器。
- 代币白名单、幂等、原子写入、锁、attempt/CAS 和运行权互斥等安全不变量。

离线测试应围绕公共契约，小而直接；同一规则的输入组合优先参数化，不为实现分支复制大段夹具。

## 禁止模式

- 用 Fake Runtime、Fake Context 或 mock 场景复刻完整游戏流程。
- 模拟 OCR、点击、滑轨、等待和终态后宣称 Task 可用。
- 读取源码并断言变量名、文案或实现片段存在。
- 把逆向调查、全库搜索、一次性探针或历史样本盘点包装成 pytest。
- 把 pytest 通过写成“功能完成”或“真实验收通过”。

不符合边界的旧测试直接删除，由 Git 历史承担追溯；不迁入源码、文档归档或兼容目录。

## 真实游戏验收

涉及画面、动态数据、场景识别、点击落点、交互时序或业务完成判据时，使用正式 Job/Task 入口。验收同时核对 Cell 终态、Job 业务结果、`next_time`、真实画面或 Runtime 事实，以及运行权是否归还。

如果当前活动窗口、资源或游戏状态不具备验收条件，应明确记录“尚未真实验收”，不能补写离线剧本代替。
