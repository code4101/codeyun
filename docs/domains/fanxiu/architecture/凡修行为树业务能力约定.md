# 凡修行为树公共能力契约

业务 Task 组合公共语义动作，不重复实现坐标、滚动、OCR、场景判断和恢复算法。

## 公共能力

- `go_scene()`：从当前可靠 scene 出发，逐动作执行并按真实落点重规划。
- `wait_scene(scenes: list[int], wait=5)`：`scenes` 是当前业务明确指定的 Layer 0 场景列表，例如 `wait_scene([34, 251], wait=60)`。它作为一个完整业务参数传入。`wait` 预算内持续获取新帧，只等待这些业务候选，并在同一 Layer 0 图中插入处理可执行弹窗。预算结束后才让最后一帧回落到 Layer 1/2 做全局识别；全局识别结果不算指定 Layer 0 等待成功，只保留在 `SceneWaitTimeout.last_match` 供诊断或安全恢复。`wait=0` 表示当前 tick 只识别一次就回落全局层，空 `scenes` 非法。
- `sample_scene_once()`：小众、底层的单帧只读采样，不等待、不处理弹窗。仅供诊断探针，或外层已经持有持续等待循环、且单帧 miss 本身是合法样本的识别算法使用。Task 起始准入、动作就绪确认、点击落点、导航恢复和终态等待禁止依赖它，统一使用 `wait_scene(scenes, wait=...)`。
- `wait_click()`：在 scene/Shape 语义下等待、定位、点击并验证直接结果。
- 局部 OCR/结构读取：只能在已标注 Shape 范围内消费文字和 token。
- 滚动查找：每次滚动后读取新帧、判断是否移动、去重已见内容，并以边界/循环/超时结束。

## 业务实现要求

- Task 只表达业务目标、准入、完成判据和动作顺序。
- 不写死坐标、滚动次数、私有 OCR 规则或借用其它 scene 的 Shape。
- 公共能力不足时修底座并增加回归，不在单个 Task 旁路实现。
- 不可逆动作前验证身份、资源、次数和授权；动作后用业务事实复验。

函数签名、选项和返回类型以运行时代码、类型和测试为准。
