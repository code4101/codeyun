# 凡修日常经验 Job 契约

`daily_experience` 是 Scheduler 管理的完整 Job。每个新 attempt 都从稳定世界场景 `#34` 开始，重新读取当前游戏事实；payload 不携带步骤、页码、次数或跨 attempt 恢复游标。

同一 attempt 内的正式路径为：

1. `#34 → #20 → #405`，打开修炼页；
2. 从 `#405` 打开经验书，合法后继为 `#406` 或遗留结算层 `#413`；
3. 局部观察按 `#413 > #408 > #407 > #406 > #405` 判定，防止背景页覆盖浮层事实；
4. `#413` 只通过经验书层的已验证隐藏返回热区关闭，再确认落到 `#405/#406`，并在同一 attempt 的有界循环内重开；
5. 购买潜修真悟后，只有观察到结算落点或业务文本变化，才允许下一次购买；provider 不可用或没有业务 delta 时失败关闭，不继续点击；
6. 连续多帧同时确认全帧与区域 OCR 均无可处理项后，先把 Scheduler `next_time` 置空，随后 best-effort 返回 `#34`。离场失败不得抹掉已经成立的业务完成事实，也不得触发重复消耗。

默认 Job wrapper 只在开始时执行一次通用 `goto #34`，不在业务实现返回后再次导航。未知稳定页面、无法消歧的转场或 provider 契约失败才升级诊断；运动/战斗过渡帧由通用 Runtime 处理，不写入本 Job 的业务分支。
