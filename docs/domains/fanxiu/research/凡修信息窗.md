# 凡修信息窗

“凡修信息窗”是凡修智能辅助层的 Windows 显示载体。它是覆盖在 MuMu 游戏画面上的透明、鼠标透传窗口，只负责渲染，不负责截图、OCR、场景判断、行为树或 Scheduler。


## 第一版

- 左上角显示已识别节点在资产树中的父目录链、编号、分数和结果年龄，例如 `日程/玩法榜/魔道入侵 #510 89% 2s`；年龄按当前时间减画面采集时间 `captured_at` 动态计算，不按稍后的采信或发布时间计算；不足一分钟显示整数秒，满一分钟显示整数分钟；不再统一添加“场景”前缀，也不重复显示图片节点自身标题。
- 识别出具体场景后，以透明白色矩形轮廓标出该场景的身份 Shape；不显示 Shape 名称、分数、填充或其它装饰。
- 方框直接消费本轮识别结果对应场景的既有标注坐标，不触发第二遍场景识别，也不修改资产树。
- Windows 窗口不激活、不获取焦点并完全透传鼠标，不影响游戏操作。
- 图层自动跟随 MuMu 的位置、尺寸和 DPI；MuMu 最小化或关闭时自动隐藏，重新出现后自动恢复。
- Runtime 页按 CodeYun 用户持久化总开关及各显示项；用户进入页面时，其偏好同步为这台机器当前渲染配置。
- 任意工程、AI 或人工 Cell 已有的场景识别统一发布到信息窗。
- 信息窗主标题只接收行为树当前步骤**最终采信并用于决策**的场景观察（`scope=decision`）。全图扫描、Layer 0 候选、`preferred_scene_ids`、路径排序等只是不同的候选求值策略，本身都不具备发布权。
- 局部候选未命中只表示“本次候选域没有目标”，不等于当前真实场景是 `unknown`；它不得覆盖已经提交的场景。复合导航也必须等最终落点被接受后再发布，中间命中或未命中均不得污染标题。
- 发布快照携带 `entry_id / asset_generation / frame_id / captured_at / committed_at / source / scope / revision`：`captured_at` 是 ADB 画面采集时刻，`committed_at` 是行为树最终采信并发布时间；同一轮各层复用同一个 frame 时共享同一 `frame_id` 与 `captured_at`。renderer 仍不自行识别或裁决。
- 信息窗始终被动消费工程、AI 或人工 Cell 已经产生的最近识别结果，不主动触发截图、OCR 或场景识别。结果年龄继续按原始 `captured_at` 展示；旧字段 `observed_at` 仅作为兼容别名。
- 信息窗 renderer 不拥有第二套 ADB/OCR，Kernel 内也不为显示功能启动常驻观察线程。没有 Cell 产生新观察时，信息窗保留并标明上一结果的真实年龄。
- 行为树把最新识别结果原子写入轻量 JSON 快照；Windows renderer 每秒读取一次，仅在 revision 变化时重绘，不通过 ADB 获取或推送信息窗数据。



## 边界

- 信息窗不是 Job，不登记到 Scheduler，不修改 `next_time`、`run_status` 或 `job_status`。
- 信息窗不处理弹窗、不点击、不导航，也不主动请求行为树做观察。
- Windows 图层只参与桌面合成，不进入模拟器内部的 ADB 截图；识别器和保存帧继续获得原始 Android 图像。
- “场景标识框”只显示已识别场景中标记为 `isSceneIdentity` 的全部 Shape；它不等于显示该场景的所有可点击 Shape。
- “全部 Shape”显示已识别场景中继承生效的全部非分组 Shape，其中已经包含场景标识框；开启时不重复绘制场景标识框。
- 仓库仍保留 Android APK 试验代码，但它会进入 ADB 截图，不作为默认运行方案。



## 启动和停止

启动 Windows 信息窗：

```powershell
uv run python scripts/fanxiu_windows_info_window.py
```

停止已经运行的信息窗：

```powershell
uv run python scripts/fanxiu_windows_info_window.py --stop
```

仓库中的 Android APK 仅保留为历史试验代码，不接入当前信息窗运行链路。
