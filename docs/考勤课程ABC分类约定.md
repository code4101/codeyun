# 考勤课程 ABC 独立体系约定

> 本文定义考勤系统中三套独立课程体系的统一交流代号。A/B/C 不是同一套算法的参数分支，也不是可以互换模板的轻量分类。涉及 CodeYun 工作簿、mi15、PG、`xlproject/kq5034`、Step 1–6、课程配置迁移和故障排查时，必须先确定所属体系。

## 总原则

A、B、C 是三套差异很大的业务体系。每套体系独立定义课程配置、数据采集、完成判定、更新时间、返款计算、工作簿结构、调度节奏和验收标准。不得先设计一套“通用课程逻辑”，再把三类差异处理成少量条件分支。

只有设备通信、表格读写、订单查询、任务执行等与课程语义无关的基础设施可以默认复用。任何业务层逻辑若要跨体系复用，必须逐项证明语义一致。

## 分类

| 代号 | 课程范围 | 视频完成规则 | `video_duration` | 典型配置节奏 |
| --- | --- | --- | --- | --- |
| A 类课程 | 普通觉观、念住的每月网课 | 普通时长/进度规则 | 必需 | 通常按日更新 |
| B 类课程 | 禅宗、修道班 | Zen Stage 规则：累计观看满 30 分钟或小鹅通标记“已完成”；再按完成时间判断准时或延迟周次 | 不需要 | 按周更新；同阶课程常复用上一期资源配置并平移时间 |
| C 类课程 | 闯关课程 | 闯关进度/遍数规则 | 按闯关规则处理，不得套用 B 类口径 | 独立闯关节奏 |

## 使用规则

1. 讨论新课程前先确认 A/B/C 体系，再进入该体系自己的模板、配置迁移、完成算法、`next_update` 和校验流程。
2. A 类的 `video_duration` 必填校验不得套到 B 类。
3. B 类配置继承时可以复用 `lesson_id2 / shop_id / video_duration（通常为空）/课程结构`，按新开课日和课次周数重算 `start_date / next_update / end_date`。
4. C 类使用独立的闯关进度/遍数语义，不以 B 类的“观看 30 分钟”判定完成。
5. “念住”一词可能同时出现在普通月课与闯关课程中：普通念住月课归 A 类；明确的念住闯关归 C 类。

## 当前实现映射

- A 类：`VIDEO_RULE_SYSTEM_REGULAR`
- B 类：`VIDEO_RULE_SYSTEM_ZEN_STAGE`
- C 类：`VIDEO_RULE_SYSTEM_CHALLENGE`

代码判断与业务代号必须保持一致，但不能因为当前代码使用同一个模块或枚举，就推断三类共享业务模型。业务文档和日常交流优先说 A/B/C 体系，避免只凭课程名称猜算法。

## 回归探针

- `d260701第42届念住` 缺少 `video_duration`：开课前校验应失败（A 类）。
- `d260705禅宗11期3阶` 的 `video_duration` 为空但 `lesson_id2` 完整：开课前校验应通过（B 类）。
- 名称包含“念住闯关”：必须命中 C 类，不得按普通念住 A 类处理。

## 本约定来源

在修道班 11 期 3 阶配置检查中，曾把 A 类课程的时长必填规则误套到 B 类，进而把 B 类正常为空的 `video_duration` 误报为运行阻塞项。该案例说明：课程类型必须先于字段完整性判断，不能先套通用字段清单再按名称补例外。
