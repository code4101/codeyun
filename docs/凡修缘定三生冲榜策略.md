# 凡修缘定三生冲榜策略

## 业务目标

缘定三生按资源榜处理。目标不是盲目耗尽弟子，而是先估算账号能力上限，再选择低一档的安全奖励区间；执行时统一从低分弟子到高分弟子，每完成一次联姻就刷新实时排名并重新决策。

## 已确认事实

- 客户端 `DiscipleIsWeddingItem.lua` 将单次联姻基础分显示为 `self.score + addScore`。
- 2026-08-08 的真实 `SM_DiscipleMarryUpdate` 中，`addScore` 等于对方弟子评分。因此普通联姻基础分为己方评分加对方评分。
- 实测样本：己方 `1,156,264`，对方 `1,121,154`，基础分 `2,277,418`；活动榜分 `2,505,159`，比值约为 `1.10`。这强烈暗示本期活动存在 10% 加成，但当前只有一个差分样本，暂不把 1.10 写死为通用规则。
- 奖励档位包含 17–32、33–64、65–128 等区间，因此“理论可进前 32，实际目标前 64”是有效的降档策略。
- 自动联姻的己方评分上限只有在对应复选框启用时才生效。输入框有数值不能证明约束已启用。

## 能力估算

若剩余己方弟子总分为 `S`，预期对方/己方评分比为 `r`，活动加成为 `b`，当前活动分为 `C`：

```text
理论总能力 = C + S × (1 + r) × b
保守总能力 = C + (理论增量 × 实现率)
```

对手评分接近己方、且没有活动加成时，增量约为 `2S`。当前单样本若能确认 10% 加成，则约为 `2.2S`。实现率用于折扣匹配失败、评分不完全对齐、可联姻弟子不足以及榜单后续增长。

先找保守能力能够达到的最佳奖励档，再默认向后降一档作为实际目标。冲榜过程不预先硬编码“做到第 50 名”，只在目标档位边界外继续。

## 总分数据边界

当前抓包可重放得到 53 个不同弟子，合计 `14,747,733`；界面显示剩余约 1132 个弟子。53 个只是已捕获下界，不是账号总分，禁止拿它计算最终能力上限。

客户端 `GetDiscipleUnMarryList()` 持有完整未婚列表并支持评分升序，但现有合规的进程外只读快照尚未导出完整列表。后续优先等待自然抓包或实操页面提供完整事实；仍不完整时，用逐次联姻的实际增分、对手比率和剩余数量滚动校准，不强求伪精确总分。

## 执行门卫

1. 操作前读取 Scheduler；只有距离下一到期作业超过 10 分钟，且本次探索能在预算内收尾，才临时实操。
2. 己方弟子队列必须按评分升序。
3. 若使用己方评分上限，必须同时验证“复选框已启用 + 输入值正确”；任一不成立都停止。
4. 每次只联姻一个低分弟子，成功后读取联姻包和实时榜单。
5. 已进入目标档位即停止；排名、分数或页面状态不明确时也停止，不批量猜测。
6. 单次样本计算 `榜单增分 / (己方分 + 对方分)`，积累至少两个独立样本后再确认活动加成。
