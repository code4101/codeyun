# 临时测试产物目录约定

## 背景

近期 Git 自动提交把 `.codex_tmp/`、根目录 `tmp_mumu_*.png`、`.tmp_*.json`、`bc_*.db` 等调试产物带进了提交。问题不在这些文件本身有业务价值，而在它们被放进了源码工作区，导致 Git 无法区分“源码改动”和“临时验收证据”。

这些文件主要来自临时验证和手工探针：

- 为验证 MuMu/ADB 画面而保存的截图，例如 `tmp_mumu_after_enter.png`。
- 为验证凡修行为树跳转、识别和轮询而保存的截图、JSON、探针脚本，例如 `.codex_tmp/fanxiu_go_scene_.../`。
- 为排查页面、表格、OCR、链接等问题而在仓库根目录随手写出的 `.tmp_*` 文件。
- 为后台启动开发服务而在仓库根目录重定向出的 `.codex-dev-*.log`、`.codex-vite-*.log`、`.dev_*.log`。

正式后端代码里多数长期逻辑已经使用 Python `tempfile` 写系统临时目录；污染主要来自一次性脚本、交互式调试命令和 AI 代理临时验收步骤。

## 总原则

源码仓库只保存源码、测试、文档、配置样例和明确需要版本管理的静态资产。临时测试产物默认不允许写入仓库根目录、源码目录或 `.codex_tmp/`。

临时产物包括：

- 截图、录屏、OCR 裁剪图、模板匹配中间图。
- 抓包片段、探针输出、临时 JSON、临时 SQLite/DB。
- 一次性调试脚本、轮询日志、服务启动日志。
- AI/Codex 验收过程中产生的证据文件。

## 推荐位置

Python 代码统一使用系统临时目录：

```python
from backend.core.temp_paths import codeyun_temp_root

out_dir = codeyun_temp_root("fanxiu", "runtime-verify")
image_path = out_dir / "before.png"
```

该路径在 Windows 上通常位于用户临时目录，例如：

```text
C:\Users\<user>\AppData\Local\Temp\codeyun\fanxiu\runtime-verify
```

CodeYun 本机守护、开发服务 stdout/stderr、临时锁文件这类长驻运行产物也默认放在系统临时目录下，例如：

```text
C:\Users\<user>\AppData\Local\Temp\codeyun\codeyun-watchdog
```

## 生命周期和容量边界

写入系统临时目录不等于可以永久保留。持续生产截图、trace、JSONL 或日志的正式代码必须在写入后调用 `backend.core.temp_paths.prune_temp_files(...)`，同时声明：

- 最长保留时间；
- 最大文件数；
- 最大总字节数；
- 触发上限后的低水位，避免每写一个文件就重复裁剪。

三种上限任一先到即裁剪最旧文件。追加型日志还必须使用 `trim_file_tail(...)` 或等价轮转保留最近完整记录。禁止只按文件数控制全分辨率图片，因为单文件大小变化会让容量上限失效。

当前凡修诊断证据的默认基线是 7 天和 1 GiB；动作回溯是 3 天和 2 GiB，索引尾部最多 16 MiB。业务若需更长历史，应将结论或最小夹具转入正式数据/资产层，而不是无限放大 TEMP。

一次性运行目录应在成功后清除；失败证据只能限时保留。无法证明所有权或活跃状态的历史目录只能先报告，不能由全局清理器猜测后整目录删除。

## 数据库恢复点不属于 TEMP

对活动 `codeyun.db` 做整库复制会随数据库增长线性放大磁盘占用。普通修复优先使用数据库事务，并仅保存受影响行的 preimage JSON。确需整库恢复点时：

- 使用 SQLite online backup，不能直接复制正在运行的 DB/WAL；
- 每个维护批次最多创建一份；
- 写入 `CODEYUN_BACKUP_DIR` 指向的归档盘（本机为 D 盘），不能写系统 TEMP 或源码目录；
- 采用“最近 2 份 + 每周 4 份”的代际保留，并受总容量上限约束；
- 自动化不得通过克隆整库来获得隔离环境。需要写运行记录的任务应直接调用 CodeYun 高层 API/worker，让结果进入活动数据库并供前端读取。

一次性 PowerShell 调试也应写入系统临时目录：

```powershell
$outDir = Join-Path $env:TEMP "codeyun\fanxiu-runtime-verify"
New-Item -ItemType Directory -Force -Path $outDir | Out-Null
```

后台启动 `uv run dev.py` 时，stdout/stderr 也必须放到系统临时目录：

```powershell
$logDir = Join-Path $env:TEMP "codeyun\dev-logs"
New-Item -ItemType Directory -Force -Path $logDir | Out-Null
Start-Process uv -ArgumentList "run","dev.py" -RedirectStandardOutput (Join-Path $logDir "dev.out.log") -RedirectStandardError (Join-Path $logDir "dev.err.log") -WindowStyle Hidden
```

## 禁止写入的位置

以下位置不得再作为临时输出目录：

- 仓库根目录：`tmp_*.png`、`.tmp_*.json`、`*.log`、`.codex-dev-*.log`、`.codex-vite-*.log`、`.dev_*.log` 这类文件禁止出现。
- `.codex_tmp/`：历史遗留目录，不再作为新验收证据目录。
- `backend/`、`frontend/`、`scripts/`、`tests/` 下的非测试夹具路径。
- `docs/`：只写结论和必要摘要，不放大体积截图证据。

## 需要保留证据时

如果某次验收证据确实值得长期保留，先判断它是不是“源码级资产”：

- 用于自动化测试的最小夹具，可以放进明确的测试 fixtures 目录，并保持体积小。
- 用于文档说明的图片，必须放进 `docs/assets/` 的具体子目录，并在文档中引用。
- 只用于当次排查的证据，写系统临时目录，在文档中记录关键结论、命令和时间，不提交原始图片。

## Git 防线

仓库已增加两层防线：

- `.gitignore` 忽略 `.codex_tmp/`、`.codex-run*/`、`.codex-logs/`、`.codex-runtime-logs/`、`.tmp_*`、`tmp_*.png`、`bc_*.db`、`*.log` 等常见本地产物。
- Git 提交预检会把 `.codex_tmp/`、Codex 运行目录和根目录临时产物识别为 `local_artifact`，包括根目录开发服务日志；如果被手动暂存会阻断提交。

这只是兜底，不是推荐工作流。正确做法仍然是从源头写到系统临时目录。
