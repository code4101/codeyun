# 行为树运行单元运维约定

## 考勤行为树

考勤行为树的唯一生产执行主机是 `codepc_mf`。CodeYun Runtime 的
`attendance-behavior-tree` 服务只在 mf 暴露，入口为
`xlproject/src/xlsln/kq5034/kqmain.py`；`codepc_mi15` 已退出考勤调度，
不得再把任务远程转发到 mi15。

mf 同时承担考勤行为树、全部小鹅通采集和 CodeYun 工作簿数据职责。
迁移或恢复运行时必须先检查 mf 的调度状态文件；若状态来自旧停机周期，先
`reset`，让所有 `start="next"` 节点从下一个锚点重新计算，避免补跑过期任务。

统一动作语义：

- `inspect`：查看调度摘要，不执行课程任务；
- `restart`：终止旧根进程及其子孙进程，再拉起唯一实例；
- `reset`：只清空状态文件，不补跑错过时段；
- Windows 下一个根 Python 及其 descendant 不代表多棵行为树。

Step 6 微信发送也由 mf 承担，但必须在 mf 的微信发送适配、目标群选择和发送后
验证全部通过后，才允许启动整棵行为树进入真实生产调度。

凡修部分不在本文重复定义。请以 [凡修行为树运行框架约定](../../domains/fanxiu/architecture/凡修行为树运行框架约定.md) 为唯一事实源。

凡修运维只使用以下 Jupyter 语义：

- cell：向当前 Kernel 提交普通 Python Cell。
- interrupt：中断当前 Cell，保留 namespace。
- restart：替换 Kernel，清空 namespace，并重新加载凡修框架。
- shutdown：终止 Kernel。

Runtime 业务状态与 Kernel 的 idle / busy / dead 是两个正交维度。Scheduler 的触发时间、重试、优先级与模拟器仲裁不进入 Kernel。

其他项目的行为树服务若采用不同运行模型，应在其项目专属文档中说明，不得借用凡修的 Kernel / Cell 术语制造第二套凡修执行路径。
