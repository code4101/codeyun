# 私有模块扩展约定

可以。当前仓库已经预留了一套“公开仓库只保留加载器，本地目录放私有实现”的机制。

## 设计目标

- GitHub 开源仓库里只看到通用扩展骨架，看不到你具体写了什么站点能力。
- 你本地保留完整私有代码，开发版和本地部署版都能正常使用。
- 公开版在没有私有模块文件时，不显示对应前端入口，也不会注册对应后端接口。

## 目录约定

后端私有模块放这里：

```text
backend/private_modules/<模块名>/__init__.py
```

前端私有模块放这里：

```text
frontend/src/private/modules/<模块名>/index.ts
```

这两个目录都已经加入 `.gitignore`，所以只要文件从未被 Git 跟踪，就不会被推送到 GitHub。

私有模块对应的测试建议也放在模块目录内：

```text
backend/private_modules/<模块名>/tests/
```

这类测试和站点逻辑、DOM 结构、私有接口路径强绑定，通常也应一并忽略，不要继续放在公开的 `tests/` 目录里。

## 后端模块接口

每个后端私有模块导出一个 `register(app)` 函数，里面自行注册路由、启动任务或挂钩其他能力。

示例：

```python
from fastapi import APIRouter

router = APIRouter()


@router.get("/health")
def health():
    return {"ok": True}


def register(app):
    app.include_router(router, prefix="/api/private-source", tags=["private-source"])
```

建议把真实抓取逻辑、账号配置、反爬策略都放在这个私有包里，不要把站点名、接口名、字段结构泄漏到公开代码里。

## 前端模块接口

每个前端私有模块默认导出一个对象，可注入路由和菜单。

示例：

```ts
import type { PrivateFrontendModule } from '@/private';

const module: PrivateFrontendModule = {
  routes: [
    {
      path: 'private/source-dashboard',
      name: 'PrivateSourceDashboard',
      component: () => import('./DashboardView.vue'),
      meta: { requiresAuth: true },
    },
  ],
  menuSections: [
    {
      key: 'private-tools',
      title: '私有工具',
      items: [
        {
          key: 'private-source-dashboard',
          title: '私有采集面板',
          path: '/private/source-dashboard',
          requiresAuth: true,
        },
      ],
    },
  ],
};

export default module;
```

公开版因为没有这个文件，所以不会显示菜单，也不会产生相关路由。

## 使用建议

- 不要把私有模块的文件名、菜单名、接口路径先写进公开代码里，否则即使实现没提交，也会暴露功能意图。
- 如果某个私有功能特别敏感，建议再进一步拆到单独的私有仓库，然后本地同步到上述忽略目录。
- `.gitignore` 只能忽略“未被跟踪”的文件。只要某个私有文件曾经被提交过，之后再加忽略规则也不算真正隐藏。

## 适合你的场景

像图片站、采集站、需要登录态的抓取模块，就很适合：

- 后端私有模块负责抓取、缓存、下载、鉴权
- 前端私有模块负责页面入口、配置页、任务页
- 私有模块测试负责站点适配、状态机、收编逻辑等本地回归
- 开源版本保持完全无入口、无接口、无功能描述
