# 凡修夜间自主研发总控（2026-08-13）

## 目标与执行模型

本清单覆盖 2026-08-13 夜间至次日 10:00 前的六组研发工作。它是跨 Goal 的总控台，不是一个巨型 Goal。

- 每次只激活一个能够独立闭环的 Goal；完成真实验收后再切换下一项。
- 主 Agent 是唯一游戏操作者，负责工程/AI 运行权交接、真实帧、动作与后继验收。
- 子 Agent 并行承担静态逆向、代码、测试、资产负样本、协议与历史证据审计，不并发操作游戏。
- 工程 Scheduler 有到期作业时优先运行；研发仅在工程空闲窗口切到 AI，静态工作期间恢复工程。
- 工程运行期间主 Agent 不是空等：持续检查 Kernel 状态、Scheduler 动作、行为树日志、真实落点、作业结果与 `next_time`。出现异常时立即把对应故障邻域提升为 P0，暂停夜间研发的游戏操作并协助工程恢复；工程稳定时，子 Agent 的静态逆向、代码和测试继续并行。
- 所有标准作业只由业务内部写自己的绝对 `next_time`；禁止另造触发器。
- 调试截图、探针和动作证据写入 `%TEMP%\codeyun\...`，不写进源码目录。

## 1. #34 下拉菜单标准化

### 已有事实

- 当前 Runtime 权威列表是 `WinMainUINewCanvas.BottomContent.FuncBtnList._BtnDataList`，不是包含隐藏项的 `myFuncDic`。
- 菜单当前为四列、行优先；此前真实顺序为角色、装备、异火、功法书、剑灵、神器、万灵、灵器、家族、宗门、法宝、灵兽、仙缘、邮件、设置。
- 每次必须重读列表；地址缓存只优化根定位，不能缓存菜单成员。
- 点击的是文字上方图标区域，不是文字本身。OCR 只负责几何，Runtime 决定身份和顺序。
- 不为15项逐个新增 Shape。

### 当前缺口

- 当前展开帧可见，但 UIShowMgr 活跃字典中未按旧假设暴露 `BottomContent`，需定位真实 Runtime 根/生命周期。
- 完成菜单加载态的冷/热/字段解码分层耗时实测。
- 封装标准“打开菜单→读Runtime→对齐→点击→验证后继”入口，并迁移灵兽、邮件、设置等现有旁路。
