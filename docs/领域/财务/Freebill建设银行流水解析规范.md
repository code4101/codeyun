# Freebill 建设银行流水解析规范

## 适用文件

建行手机银行导出的“流水打印”邮件附件，解压后得到的 `xls` 文件，以及文件整理层统一转换后的 `xlsx` 文件。

当前标准格式标题为：`中国建设银行个人活期账户全部交易明细`。

## 文件结构

典型工作表结构固定为：

1. 第 1 行：标题。
2. 第 2 行：`卡号/账号`、`客户名称`、`起始日期`、`结束日期`。
3. 第 3 行：`总支出`、`总收入` 汇总。
4. 第 4 行：明细表头。
5. 第 5 行起：流水明细。

明细表头使用以下字段：

```text
序号 / 摘要 / 币别 / 钞汇 / 交易日期 / 交易金额 / 账户余额 / 交易地点/附言 / 对方账号与户名
```

解析器不会依赖固定行号，而是在工作表前 80 行中查找同时包含 `序号`、`交易日期`、`交易金额` 的表头行。

## 字段映射

| 建行字段 | Freebill 字段 | 说明 |
| --- | --- | --- |
| 序号 | `raw_sequence`、`merchant_order_no` | 文件内流水序号 |
| 摘要 | `type` | 原始分类 |
| 币别 | `currency` | 例如人民币元 |
| 钞汇 | `cash_type` | 例如钞 |
| 交易日期 | `create_time`、`pay_time`、`modify_time` | 规范化为 `YYYY-MM-DD 00:00:00` |
| 交易金额 | `amount`、`direction` | 金额入库取绝对值，正数为收入，负数为支出 |
| 账户余额 | `account_balance` | 交易后余额 |
| 交易地点/附言 | `product_name`、`remark` | 优先作为商品/备注文本 |
| 对方账号与户名 | `counterparty` | 交易对方 |
| 卡号/账号 | `account_no` | 从表头元信息提取 |

## 去重规则

建行文件没有稳定交易单号，所以程序生成 `trade_no`：

```text
ccb:{账号}:{交易日期}:{序号}:{digest}
```

`digest` 由账号、交易日期、序号、摘要、带符号交易金额、账户余额、附言、对方账号与户名共同计算。这样同一份文件重复导入会跳过，后续重建数据库也能稳定合并。

## 校验规则

如果表头元信息包含 `总支出` 和 `总收入`，解析器会用明细合计进行校验：

- 明细支出合计必须等于表头总支出。
- 明细收入合计必须等于表头总收入。
- 允许 0.01 元以内的浮点误差。

校验失败时，本文件导入失败并记录原始文件解析错误，避免把截断或错位的流水写入数据库。
