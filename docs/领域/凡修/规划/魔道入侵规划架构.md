# 魔道入侵规划架构

> 本文描述魔道入侵自动化的理想完成态，是研发与验收使用的设计稿，不代表当前代码已经完整实现。

魔道入侵与兽渊探秘共用同一个玩法榜主体结构。魔道的主要差异只有两个：本期通常按“服内 → 跨服”连续形成两个独立实例，具体运行时使用魔道自己的玩法策略。

```mermaid
flowchart TB
    A["玩法榜"] --> B["魔道本期实例化与数据采集<br/>服内,跨服是两个不同实例"]

    B --> H["00:30<br/>生命周期维护"]
    B --> E["12:00<br/>邮件领取"]
    B --> I["19:00<br/>正式运行"]
    B --> U["20:45 / 21:50<br/>清理体力"]

    H --> K["今日新开实例<br/>首日初始化<br/>采集兑换宝阁与奖励档次"]
    H --> J["已结束旧实例<br/>兑换宝阁尾日收尾<br/>保留锁定商品<br/>剩余兑币按优先级兑换至无可执行项<br/>最后更新同步榜单数据"]

    E --> F["查找今日是否有“美杜莎宝库馈赠”邮件<br/>有则领取，无则跳过"]

    I --> L["进入当前魔道挑战页"]
    L --> Q{"点开道具栏<br/>检查天眼符是否少于 2000 张？"}
    Q -->|是| R["进入储物袋兑换天眼符<br/>确保至少有 3000 张"]
    Q -->|否| N["执行三批基础探查<br/>每批 500 次"]
    R --> N
    N --> O["处理探查产生的挑战事件"]
    O --> P["领取任务奖励<br/>采集榜单与资源结果"]

    U --> W["进入当前魔道实例<br/>清理自动恢复的体力"]

```

进入挑战页的接口内部兼容弹窗、普通大地图和天南大陆详情等可选过渡画面，不在主流程中展开。

图中的服内、跨服表示两个连续但独立的业务任务。通常服内结束后紧接跨服，但实际起止时间仍以运行时日程为准，不能依靠固定日期或固定间隔推算。

服内和跨服只是顺序执行的两个活动实例。两者不共享探查进度、任务奖励、排行榜、钱包、商店购买次数或完成状态，但主体流程完全相同。
