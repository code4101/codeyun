# 凡修 Kernel、Cell 与运行权契约

## 唯一模型

- 凡修只有一个长期存活的真实 Jupyter/Python Kernel。
- Kernel 启动后加载 `context`、`ctx`、OCR、ADB、shape、scene、tasks、guards 等行为树能力；行为树执行上下文不得使用 `runtime` 命名。
- 外部唯一执行原语是普通 Python Cell；正式 Job 也只是包含 `run_task(...)` 的 Cell，`kernel.task(...)` 只能构造这种 Cell，不能形成第二协议或第二执行器。
- Scheduler/Dispatch Arbiter 位于 Kernel 外；Kernel 内不得存在 manual queue、来源锁、调度轮询或跨 restart 重放。
- Task 内部由行为树组织局部观察—行动循环。
- 用户要求“发一个 Cell”时，从已有业务代码抽取最小片段提交当前 Kernel；不得为此新增调试 API、注册临时作业或写内部队列。

## Kernel API

- submit：向当前 Kernel 提交一个 Cell。
- interrupt：精确停止当前目标 Cell，保留 namespace。
- restart：替换 Kernel、清空变量并重新加载凡修框架。
- shutdown：终止 Kernel。

旧 Cell 未确认终止前，不得提交抢占者或把 GUI 交给另一个所有者。restart 后旧客户端不得向新 Kernel 重放未完成 Cell。

## 运行权

- 工程调度和 AI 调试共用同一个 Kernel，运行权互斥。
- AI Cell 只能在取得运行权后操作游戏；只读代码审查、测试和静态分析不占模拟器。
- 交还运行权前确认 Kernel idle、游戏处于稳定可识别场景，且没有遗留输入或后台控制器。

## Job 边界

- Job Cell 启动后读取当前事实并整单运行。
- Cell 结束后不保存 generator、步骤、scene cursor 或中间选择意图。
- 中断、错误和业务未满足必须分别表达；具体时间语义见 [Job 状态与时间](凡修作业调度语义.md)。

## 验收

测试应证明唯一 Kernel、Cell 串行、精确 interrupt、restart 代际隔离、attempt 所有权和运行权互斥。真实操作还需证明最终画面与工程模式已经恢复。
