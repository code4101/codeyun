# 凡修内核调度器契约

## 命名边界

“Kernel 调度器”是凡修调度层的宏观控制面，统一呈现和控制 Kernel、Cell、运行权、守护、顶层 Job、attempt、`next_time` 与 Scheduler。页面、路由、API、类型和控制模块必须统一使用 Kernel 调度器术语。

以下两个相邻概念仍各自保留原名：

- 逆向层 `Runtime`：读取正在运行的游戏进程及其已加载对象，提供当前账号和业务事实；
- `BehaviorTreeContext`：单个 Task/Cell 内部执行观察、选择、动作、再观察的局部循环。

Kernel 调度器可以观测二者，也可以把顶层 Task 提交给行为树执行，但不拥有逆向 Runtime 的命名，也不等同于行为树执行器。

## 调度器职责

Scheduler 位于 Kernel 外，只负责：

- 根据 `next_time` 和优先级选择到期 Job；
- 领取 attempt 并以 CAS 写回终态；
- 仲裁唯一 Kernel 和模拟器运行权；
- 按静态配置处理技术错误重试。

Scheduler 不读取 OCR、scene、业务消息或 `job_status`，也不保存业务步骤。

## 内核与执行单元

- 唯一长期 Kernel 串行执行普通 Python Cell，并保留 namespace；
- 工程调度把到期 Job 构造成 Job Cell，AI 调度提交研发或排查 Cell；
- Kernel 不决定何时派发作业，也不在内部维护第二套 Scheduler；
- 行为树状态只属于当前 Task/Cell，不能跨 attempt 恢复旧步骤。

## 作业定义

- 作业类型由代码注册表定义；实例配置保存在本地数据层。
- 新作业类型默认不自动加入或启用当前机器清单。
- 顶层 Job 对外可调度；子 Task 和公共动作不成为平级作业。
- 注册表是作业身份和前端目录的事实源，不维护手写 Markdown 清单。

## 验收

Kernel 调度器页面是观测和控制入口，不是第二执行器。测试需覆盖注册、attempt、终态、interrupt、时间写回、权限和命名边界；真实 GUI 动作需另做设备验收。
