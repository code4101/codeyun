## 2. 脱敏原则

本档案只保留“可恢复所需的结构、命名和关键逻辑”，不保留任何真实敏感信息。

- 服务器地址、用户名、目录、域名、证书路径全部改为占位符
- SSH 私钥不入库，只保留 Secret 名称
- 应用运行时 `.env` 中的真实业务配置不在本文档展开

恢复时，所有形如 `<...>` 的值都需要按当前环境重新填写。

## 3. 原自动部署链路概览

当时的真实链路是：

1. push 到 `main`
2. GitHub Actions 触发 workflow
3. workflow 用 `appleboy/ssh-action` 连接服务器
4. 服务器仓库执行更新脚本
5. 更新脚本做 `git fetch/reset`、`uv sync`、按需前端构建、`systemctl restart codeyun-backend`

## 4. 恢复时需要重新准备的外部信息

### 4.1 GitHub Actions Secrets

| Secret | 说明 |
| --- | --- |
| `DEPLOY_SSH_HOST` | 服务器 SSH 地址 |
| `DEPLOY_SSH_PORT` | SSH 端口 |
| `DEPLOY_SSH_USER` | SSH 用户 |
| `DEPLOY_SSH_PRIVATE_KEY` | 部署私钥全文，多行粘贴 |
| `DEPLOY_APP_DIR` | 服务器上的仓库目录 |

### 4.2 服务器侧前置条件

- 已安装 `git`
- 已安装 `uv`
- 已安装 `npm`
- 仓库已 clone 到 `<DEPLOY_APP_DIR>`
- 服务器上存在项目运行所需的 `.env`
- SSH 登录用户具备无密码执行以下命令的 sudo 权限：

```bash
sudo -n /usr/bin/systemctl restart codeyun-backend
```

## 5. 关键代码备份

### 5.1 GitHub Actions workflow 模板

文件路径：`.github/workflows/deploy-ubuntu24.yml`

```yaml
name: Deploy to Ubuntu 24

on:
  push:
    branches:
      - main

concurrency:
  group: deploy-ubuntu24-${{ github.ref }}
  cancel-in-progress: true

jobs:
  deploy:
    runs-on: ubuntu-latest
    permissions:
      contents: read
    steps:
      - uses: actions/checkout@v4

      - name: Execute remote commands
        uses: appleboy/ssh-action@v1.0.3
        with:
          host: ${{ secrets.DEPLOY_SSH_HOST }}
          username: ${{ secrets.DEPLOY_SSH_USER }}
          port: ${{ secrets.DEPLOY_SSH_PORT }}
          key: ${{ secrets.DEPLOY_SSH_PRIVATE_KEY }}
          command_timeout: 30m
          script: |
            set -e

            if [ ! -d "${{ secrets.DEPLOY_APP_DIR }}" ]; then
              echo ">>> Target directory not found. Creating..."
              mkdir -p "${{ secrets.DEPLOY_APP_DIR }}"
            fi

            cd "${{ secrets.DEPLOY_APP_DIR }}"

            if [ ! -d ".git" ]; then
              echo ">>> Git repository not found. Clone the repo first."
              exit 1
            fi

            if [ -f "deploy/update.sh" ]; then
              chmod +x deploy/update.sh
              ./deploy/update.sh
            else
              echo "deploy/update.sh not found"
              exit 1
            fi
```

### 5.2 远端更新脚本模板

文件路径：`deploy/update.sh`

```bash
#!/bin/bash
set -e

PROJECT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)"

echo ">>> Starting update process in $PROJECT_DIR..."
cd "$PROJECT_DIR"

echo ">>> Pulling latest code..."
git fetch origin main
git reset --hard origin/main
CURRENT_HEAD="$(git rev-parse HEAD)"

if command -v uv >/dev/null 2>&1; then
  echo ">>> Syncing dependencies with uv..."
  uv sync
else
  echo ">>> uv not found, skipping dependency sync."
fi

echo ">>> Checking frontend..."
cd "$PROJECT_DIR/frontend"
BUILD_MARKER="dist/.codeyun-build-commit"
BUILT_HEAD=""
REBUILD_FRONTEND=0

if [ -f "$BUILD_MARKER" ]; then
  BUILT_HEAD="$(tr -d '\r\n' < "$BUILD_MARKER")"
fi

if [ ! -d "dist" ] || [ -z "$BUILT_HEAD" ]; then
  REBUILD_FRONTEND=1
elif [ "$BUILT_HEAD" = "$CURRENT_HEAD" ]; then
  REBUILD_FRONTEND=0
elif git cat-file -e "${BUILT_HEAD}^{commit}" 2>/dev/null; then
  if git diff --name-only "$BUILT_HEAD" "$CURRENT_HEAD" | grep -q "^frontend[/]"; then
    REBUILD_FRONTEND=1
  fi
else
  REBUILD_FRONTEND=1
fi

if [ "$REBUILD_FRONTEND" -eq 1 ]; then
  echo ">>> Rebuilding frontend..."
  npm install
  npm run build
  printf '%s\n' "$CURRENT_HEAD" > "$BUILD_MARKER"
else
  echo ">>> Frontend up to date."
fi

echo ">>> Restarting backend service..."
sudo -n /usr/bin/systemctl restart codeyun-backend

if systemctl is-active --quiet codeyun-backend; then
  echo ">>> Backend service restarted successfully."
else
  echo ">>> Backend service failed to become active."
  exit 1
fi
```

### 5.3 systemd 服务模板

文件路径：`deploy/systemd/codeyun-backend.service`

```ini
[Unit]
Description=CodeYun Backend Service
After=network.target

[Service]
User=<DEPLOY_USER>
Group=<DEPLOY_USER>
WorkingDirectory=<DEPLOY_APP_DIR>
Environment=CODEYUN_ENV=production
EnvironmentFile=<DEPLOY_APP_DIR>/.env
ExecStart=<UV_BIN> run uvicorn backend.app:app --host 127.0.0.1 --port 8000
Restart=always

[Install]
WantedBy=multi-user.target
```

说明：

- `<UV_BIN>` 常见值是 `/home/<DEPLOY_USER>/.local/bin/uv`
- 如果要继续沿用旧口径，服务名保持 `codeyun-backend`

### 5.4 nginx 模板

文件路径：`deploy/nginx/codeyun.conf`

```nginx
server {
    listen 80;
    server_name <YOUR_DOMAIN>;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl;
    server_name <YOUR_DOMAIN>;

    ssl_certificate <SSL_CERT_PATH>;
    ssl_certificate_key <SSL_KEY_PATH>;
    ssl_session_timeout 5m;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers ECDHE-RSA-AES128-GCM-SHA256:HIGH:!aNULL:!MD5:!RC4:!DHE;
    ssl_prefer_server_ciphers on;

    root <DEPLOY_APP_DIR>/frontend/dist;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location /api {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location /docs {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location /openapi.json {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

### 5.5 初始化脚本关键逻辑

文件路径：`deploy/setup_server.sh`

原脚本职责如下：

1. 检查 `uv`、`npm`、Node 版本
2. 在项目根目录执行 `uv sync`
3. 在 `frontend/` 执行 `npm install` 和 `npm run build`
4. 若根目录 `.env` 不存在，则从 `.env.example` 复制并生成随机 `CODEYUN_SECRET_KEY`
5. 生成并安装 `codeyun-backend.service`
6. 复制 nginx 模板、替换项目目录占位符、`nginx -t` 后 reload

如果要恢复该脚本，建议不要逐字照搬旧文件，而是按上面的职责重新整理一版更短、更可审计的脚本。

## 6. 恢复步骤建议

1. 先按本档案恢复 `.github/workflows/deploy-ubuntu24.yml`
2. 再恢复 `deploy/` 目录中的 `update.sh`、systemd、nginx 模板
3. 根据当前服务器环境，重新决定是否还需要 `setup_server.sh`
4. 在 GitHub 仓库重新配置 Actions Secrets
5. 在服务器上确认：
   - 仓库已 clone 到 `<DEPLOY_APP_DIR>`
   - `.env` 已存在且是正确的生产配置
   - `codeyun-backend` 服务存在
   - SSH 用户有对应 `sudo systemctl restart codeyun-backend` 权限
6. 手动在服务器执行一次 `deploy/update.sh`，确认无误后再依赖 GitHub Actions

## 7. 恢复后的验收清单

- `systemctl is-active codeyun-backend` 返回 active
- `curl -I http://127.0.0.1:8000/` 可响应
- 如果前端启用静态托管：
  - `frontend/dist/index.html` 存在
  - 历史部署脚本生成的 `.codeyun-build-commit` marker 与当前部署提交一致
- GitHub Actions 在一次推送后可以成功连到服务器并完成重启

## 8. 为什么不直接保留旧文件

保留旧 workflow 和脚本，即使暂时不用，也会让仓库继续具备“提交即触发线上变更”的能力。

这次调整的目标是：

- 仓库内不再存在可直接触发的自动部署入口
- 仍然保留足够详细的恢复资料
- 不在仓库中留下任何明文敏感信息
