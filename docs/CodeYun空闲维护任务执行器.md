# CodeYun 空闲维护任务执行器

## 定位

CodeYun 空闲维护任务执行器是一个后台维护任务调度组件。

它不是单个 skill，也不是固定流水线。它在后台空闲时，从维护任务池里选择一个低风险、可验证、可独立执行的任务运行。

## 组件边界

- `Idle Detector`：判断后台队列是否空闲。
- `Task Pool`：注册可执行维护任务。
- `Task Selector`：根据当前状态选择一个任务。
- `Task Runner`：执行任务并写机器可读报告。
- `Skill Manual`：描述任务执行规则、禁止事项和验收标准。
- `Guard`：阻止队列忙、风险过高或缺少验收指标的任务。

## 当前实现

后台任务 key：

```text
idle_maintenance_runner
```

队列任务名：

```text
idle_maintenance
```

默认调度策略：

```text
每 5 分钟检查一次，失败后 10 分钟重试
```

默认不自动启用，需要在后台任务配置中显式开启。

## 当前任务池

### auto_commit_dirty_worktree

GitHub 项目脏工作区自动提交。

这是一个独立维护任务，不是其他维护任务的收尾步骤。当前实现会检查已配置的 GitHub 项目仓库，默认覆盖 `pyxllib`、`xlproject`、`codeyun`；任一仓库存在变更时，复用现有 `auto_git_commit` 流程，让既有 Git 预检、AI 提交信息生成和提交逻辑继续作为唯一提交入口。

相比原本每天一次的固定提交调度，空闲维护器更适合做高频机会触发：它先判断后台队列是否空闲，再把提交交给 AI 自动提交流水线处理。固定夜间任务仍可保留为兜底，但不需要承担主要提交频率。

### docs_sync_scan

文档事实对齐扫描。

当前只读扫描文档中引用的仓库路径，输出不存在的路径引用候选。后续可扩展到命令 dry-run、配置项对齐、API/路由文档对齐。

### code_slimming_scan

代码瘦身候选扫描。

当前只读扫描较大的代码文件，输出候选清单。后续可扩展到重复 helper、零引用文件、不可达路由和低风险删除候选。

## 报告位置

每次运行都会写 JSON 报告：

```text
{CODEYUN_DATA_DIR}/idle-maintenance/*.json
```

报告包含：

- 运行状态
- 被选择的任务
- 任务风险等级
- success metric
- 结果或跳过原因
- 开始/结束时间

## 安全策略

- 队列中有其他任务运行时跳过。
- 一轮只选择一个任务。
- 已配置 GitHub 项目仓库任一存在脏工作区时，优先委托自动提交；默认项目都干净时，在只读扫描任务之间轮换，避免单一扫描长期占用空闲窗口。
- 扫描类任务默认只读。
- 自动提交委托现有 `auto_git_commit`，不直接在维护器里执行 `git commit`。
- 没有 success metric 的任务不得自动执行。
- 需要产品判断、UI 审美、真实账号操作、GUI 自动化或大规模重构的任务不得自动执行。

## 长期代码健康上下文

`CodeYun 代码健康优化` 自动化不是一次性轻量扫描。长期候选队列、已完成切片、下一步验证命令和已知扫描噪声记录在：

```text
docs/CodeYun代码健康长期优化上下文.md
```

后续自动化触发时，应优先读取该文档，选择一个具体对象继续推进，并在完成有累积价值的结果后更新它。
