# 凡修 data-annotation 自动探索标注数据

本文记录凡修 data-annotation 在标注不足、标注过期或出现新界面状态时，AI 如何通过截图、OCR、拖拽观察和人工确认补齐可供行为树复用的标注数据。

自动探索标注只负责获得可靠的场景、shape、滚动容器和局部结构数据，不承载正式任务状态机。正式执行由 Runtime/行为树使用已确认的标注完成。

## 适用场景

- 目标场景、按钮、弹窗、滚动容器或列表条目在资产树中不存在。
- 已有 shape 无法匹配当前画面，且截图证据显示可能是新状态、遮挡、缩放变化或标注过期。
- 现有标注的标题、OCR 规则、跳转目标或父子结构互相冲突。
- 任务需要新增状态分支，例如成功、失败、重复领取、冷却提示或未知落点。

如果已有标注已经能表达要做的事，应直接交给 Runtime/行为树使用，不要重新猜坐标或临时写像素比例。

## 数据边界

自动探索标注的产物包括：

- 场景帧：保存当前画面为可追溯的帧树图片节点。
- 稳定场景锚点：例如页头、固定外框、不会随列表滚动变化的标题。
- 可操作 shape：按钮、页签、入口、确认/取消、返回、可点击任务块。
- 滚动容器 shape：限定搜索、拖拽、截图和 OCR 边界，不作为场景身份。
- 局部结构模板：滚动列表里的单个重复项，以及条目内部的标题、状态、次数、价格、按钮、奖励等相对字段。
- OCR/图像规则：用于匹配、区分、解释和复核的规则。

自动探索不直接决定任务策略。稳定结论应进入资产树标注或行为树业务能力约定；临时坐标只能用于一次性验证，不能沉淀为长期任务逻辑。

## 滚动窗口与局部结构

凡修 GUI 中的任务列表、活动列表、背包、商店、排行榜和弹窗内列表，通常都不是扁平文本区，而是“容器 + 重复条目 + 条目字段”的局部结构。

优先按下面模型建模：

- `scope`：外层范围，限定 OCR、图像搜索、拖拽和截图边界。
- `template`：单个重复项的模板，描述条目整体范围。
- `anchor`：模板里的定位字段，用标题、图标、序号或按钮文本把模板对齐到当前真实条目。
- `fields`：模板里的相对字段，读取标题、状态、次数、价格、按钮、奖励等局部信息。
- `actionPoint`：由字段或模板推导出的推荐操作点。
- `evidence`：运行时收集到的文本、图像相似度、bbox 和来源。

所有字段应共享同一个父级坐标系。锚点命中后，模板和字段通过同一套平移或变换得到当前条目的实际范围；不要混用容器裁剪后的局部坐标和整屏坐标。

## 探索流程

1. 先确认当前场景身份，而不是直接拖动或点击。
2. 读取已有资产树，判断是否已有可复用场景、shape、滚动容器或模板。
3. 在相关范围内做 OCR/图像观察，记录候选文本、bbox、截图和推断理由。
4. 对文字型按钮、标题、提示语、场景身份和列表项，优先使用 PaddleOCR line/word bbox 反推候选 shape：记录目标文本、bbox、建议外扩边距、相邻干扰文本，以及为什么该文本能或不能作为场景身份。
5. 对滚动容器保留重叠观察，避免因为惯性或遮挡漏掉条目。
6. 命中候选但位置不适合操作时，只记录候选，不直接当作可点击事实。
7. 由人工确认或补标后，再让 Runtime/行为树使用正式标注执行。

## AI 使用要求

- 不要把未知截图自动保存成正式场景。
- 不要创建“未知场景”占位 shape。
- 不要把未声明跳转结果自动写入 `sceneJumpTarget`。
- 不要把 OCR 污染文本当成稳定业务事实。
- 结论必须保留证据链：截图、OCR 文本、bbox、命中的锚点、推导出的模板位置和建议动作点。

## OCR 辅助标注原则

PaddleOCR 不只是“判断文本是否存在”的匹配工具，也是未知画面、新帧和标注修正的几何辅助工具。

- 文本型 shape 的候选框应优先来自 OCR bbox，再由人工确认和微调；纯视觉目测只能作为候选范围。
- OCR bbox 要和当前真实帧绑定保存为临时证据，不要脱离截图单独使用。
- 对场景身份标识，除了确认目标页命中，还要确认相邻易混页不命中。例如共享粗域标题时，应使用额外细分文本作为 AND 条件。
- 如果 OCR 找不到完整句子，先看 line/word/char 是否被拆分、错字或合并到相邻文本；不要立即判定目标不存在。
- 对动态背景、发光字、半透明遮挡或滚动区域，候选框应适度外扩，但不要把无关区域大面积纳入 required OCR shape。

真实案例：`#265 法则之主旋转选择页` 和 `#266 法则详情页` 都包含“法则之主”粗域标识。`#265[选择提示]` 应框住“可旋转并选择法则之主进行拜谒”提示语，用作区分 `#266` 的细分身份条件；曾经纯目测标到文字上方空白区，导致 required OCR 条件不稳定。正确流程是先用当前帧 OCR bbox 找到该提示语，再外扩成候选 shape，并验证 `#265` 命中、`#266` 不命中。
