# 星云表格轻量协同保存重构

## 背景与目标

当前需要的不是大规模实时协同引擎，而是低并发下简洁、高效、轻量的协同保存：用户只感知自动保存和必要的真实冲突，不感知版本号、重放、快照和同步过程。

本轮目标：

- Sheet 是并发一致性边界，使用短事务和乐观版本，不持有长时间锁。
- 前端以一批区域变更作为提交单位，后端对整批变更原子提交。
- 仅保留当前权威状态，`version` 不代表历史副本。
- 页快照只是有上限、可淘汰的当前版本读缓存。
- 不引入 OT、CRDT、永久操作日志或每版本全量快照。

## 现状核对

当前实现已具备大部分基础：

- `POST /note-sheets/sheets/{sheet_id}/patch` 已支持单元格、格式、列配置、合并、行列结构等有限操作。
- 单元格操作已携带 `expected_value/expected_meta` 和行列稳定 ID，可将过期 Sheet 版本重放到未冲突的位置。
- 后端已在 `UPDATE ... WHERE version = current_version` 中完成 CAS，并对竞争进行有限重试。
- 前端已有 patch 队列、本地草稿和 WebSocket 资源更新通知。
- `SheetPageSnapshot` 会删除非当前版本数据，并将当前 Sheet 数量限制为 16；它不是历史仓库。

主要待收敛点：

1. 响应式 watcher 仍有全量 `document_json` 保存通道，部分已成功 patch 的变更可能继续触发全量保存。
2. patch API 是局部变更协议，但 CodeYun `SheetDocument.document_json` 持久化目前仍会写回整份 JSON。
3. patch 成功后预热默认页快照，虽然不会无限累积，但高频编辑时仍会制造派生写入。
4. 需验证其他在线页面能静默同步，且不覆盖本地未保存编辑。

## 总体设计

```text
Handsontable 变更
    ↓ 合并为一批 patch
保存协调器（单队列）
    ↓ base_version + expected value/meta + mutation_id
Sheet patch API
    ↓ 权限、校验、重放、CAS
当前权威状态
    ↓ commit 后通知
WebSocket 在线客户端
```

| 正交维度 | 边界 |
| --- | --- |
| 并发一致性 | Sheet 级 `version` |
| 一次变更 | 一批区域 patch |
| 物理持久化 | 当前状态；是否分块由实测决定 |
| 读取加速 | 可删除的当前版本页投影 |

这使前端提交格式、并发策略、底层存储和快照策略可以独立演进。

## 详细设计

### 保存通道

- 使用单一保存协调器序列化 patch、标题/视图配置与显式整体替换。
- 已被 patch 完整覆盖的变更不再触发后续全量保存。
- 普通单元格、粘贴、填充、格式、列配置、合并与行列结构走 patch。
- 导入、模板生成和 schema 迁移等低频操作可保留整体替换，但必须显式调用，不由深度 watcher 意外触发。

### 冲突与幂等

- Sheet `version` 是观测到的基线，不把不同区域的变更误判为冲突。
- 过期 patch 只在目标的 `expected_value/expected_meta` 仍匹配时重放。
- 优先用“目标已是期望值”完成等效幂等；如仍不足，只增加有 TTL 和数量上限的近期 `mutation_id` 去重，不建永久日志。
- 真实同位置冲突才返回 409；前端保留草稿并给出最小提示。

### 快照与在线同步

- patch 路径优先使已有快照失效或局部更新，不在每次编辑后同步重建默认页。
- 保留数量上限和旧版本淘汰测试，并增加高频 patch 不产生快照增长的回归。
- WebSocket 只负责 commit 后通知。同源通知直接忽略；无本地未保存变更时静默同步，有本地变更时不得盲目覆盖。

### 物理分块门槛

区域 patch 协议与物理分块存储分开。第一阶段先消除重复全量保存和快照预热，然后在真实大表上测量 patch 耗时、事务时间和数据库/WAL 增量。

只有当整份 `document_json` 写回仍是主瓶颈时，才启动固定行块/页块存储。分块优先限定在普通星云表格，不绕过考勤独立存储引擎，不直接改写依赖完整 `document_json` 的业务专用流程。

## 实施顺序

1. 补齐现有保存路径的回归测试和基准探针。
2. 收敛 watcher 与 patch 队列，消除已覆盖变更的二次全量保存。
3. 把高频交互中仍走全量保存的可稳定表达变更转为现有 patch 语义。
4. 将 patch 后快照改为失效/延迟再生，验证数量不增长。
5. 验证不同区域过期 patch 可重放、同位置冲突返回 409、丢失响应后重试不重复改写。
6. 用真实大表复测；达到物理分块门槛时再单独实施存储适配层和迁移。

## 验收标准

- 普通单元格、区域粘贴、格式和已支持的结构操作不再跟随一次全量 `document_json` 保存。
- 一批 patch 要么全部成功，要么全部回滚，Sheet 版本只增加一次。
- 两个基于旧版本的不同区域修改可自动成功；同一位置的不同新值不会静默覆盖。
- 连续 patch 不产生按版本累积的快照。
- 其他页面对无本地编辑的用户静默同步，对有本地编辑的用户不盲目覆盖。
- 指定后端 API 测试、前端回归和真实页面保存闭环通过，并报告重构前后的请求体、写入次数和耗时。

## 2026-09-01 实施结果

本轮按“先测量、再收敛”的顺序完成第一阶段，不引入分块表迁移：

- 普通增量 patch 不再同步预热默认页快照，而是在同一事务内删除该 Sheet 的旧页投影；下一次真实读取按需再生。
- Sheet 当前状态、CAS、目标值重放、真实冲突 409 和 WebSocket 通知协议保持不变。
- 对已经具备稳定 `row_id/column_id` 的普通星云表格，单元格值与格式 patch 使用浅层写时复制，只复制发生变化的行、网格行和元数据映射；不再为一格修改扫描、规范化并深拷贝整张表。
- 报名表、问卷表、考勤课程表、缺少稳定身份的旧表、结构操作和整体替换仍走原有严格路径，避免优化越过业务专用语义。
- 前端保存协调器经核对已经能用 `suppressNextRemoteSaveWatcher` 阻止普通 patch 的 watcher 二次全量保存；`documentSaveAfterCellPatches` 只恢复 patch 之前已经存在的整体保存，予以保留并增加回归保护。

同一份真实数据库的临时副本上，选择数据库长度约 16.3MB、紧凑 JSON 约 12MB 的普通 FreeBill Sheet；每次只修改一个单元格，请求体约 0.48KB：

| 指标 | 重构前 | 重构后 |
| --- | ---: | ---: |
| patch 总耗时 | 4594±248ms，n=3 | 454±193ms，n=8 |
| p50 | 4666ms | 335ms |
| 最大值 | 4854ms | 771ms |
| patch 后页快照 | 1 | 0 |
| 优化后热态 | - | 413±170ms，n=7，p50=308ms |

总耗时下降约 90.1%。优化后 8 次连续 patch 的临时 SQLite 数据文件与 WAL 合计净增长约 4KB；该数字只用于本次同口径探针，不推断为所有 SQLite 工作负载的固定写放大。

当前结果不支持立即实施物理分块：普通区域 patch 已从秒级降到亚秒级，快照不再跟随编辑写入；固定行块/页块仍保留为后续选项，只在更大普通 Sheet 的稳定热态继续超过产品可接受阈值时启动。

验证结果：

- 保存、并发、结构和快照定向测试：8 项通过。
- note sheet patch、分页和快照相关扩大回归：10 项通过。
- 前端 `vue-tsc --noEmit`：通过。
- 本机后端通过受监督重启加载最终源码，`/api/health` 回读 `status=ok`；没有对真实工作簿执行破坏性写入，写入闭环使用真实数据库临时副本和接口测试验证。
- 性能守卫文件：67 项通过、1 项既存失败；失败是筛选首次加载实现与旧源码字符串断言不一致，不在本轮保存改动范围。
- `test_note_sheets_api.py` 全文件：130 项通过、22 项既存业务测试失败，集中在当前工作区同时修改中的 Excel 导入、报名匹配、考勤独立存储和课程排序，不由本轮普通 Sheet patch 路径触发。
