# 凡修天机阁有奖竞答作业

## 作业身份

- `task_type=tianjige_forum_quiz`
- Scheduler id：`tianjige-forum-quiz`
- 显示名：`天机阁_有奖竞答`
- 初次触发：每周二、三、四 `17:59:50`
- 活动窗口：当天 `17:59:50-19:00:00`
- 等级：0；运行错误 60 秒后重试

这是凡修标准作业，但不操作模拟器。标准作业只表示进入 Scheduler 标准清单；该业务函数本身不会登录游戏、导航场景或在失败时回世界，仍服从 Runtime 页唯一的“工程 / AI”运行权开关。

## 业务流程

1. 使用 pyxllib 的默认 `Chromium()`，复用本机统一 DrissionPage Chrome 登录态。
2. 打开小银月用户动态，按活动日匹配最新竞答：周二首帖允许不写 `DAY1`，周三/周四严格匹配 `DAY2/DAY3`；时间同时接受“刚刚/若干分钟前”和当天绝对日期。
3. 进入帖子，切到最新评论并持续点击“加载更多”，直到按钮消失、抵达当前最早回复；正式分析不按轮次或条数抽样，确保较早发布的版主或互动大神也进入候选。连续两次点击后数量不增长或总加载超过 120 秒会安全失败，不用残缺样本发送。随后提取形如 `1、... 2、... 3、...` 的三行答案。
4. 规范化中英文标点、大小写、空白与不可见字符；三道题分别聚合等价答案并独立投票，最后组合每题的最高置信答案，禁止把三行回复作为不可拆分的整票统计。
5. 身份权重逐题生效：普通回复 1，活跃版主 10，互动大神 100；发送门槛取三道题中最低的获胜权重，默认每题至少达到权重 2 才允许发送。
6. 回复前写入提交意图并读取当前登录昵称，随后只点击文字完全等于“发送”的按钮；发送后必须确认“当前登录昵称名下、完全相同答案”的评论数量增加。其他玩家同期发布相同答案不能作为本次成功证据。
7. 活动窗口内由同一个 Cell 复用同一个工作标签页：未见帖子或有效答案时刷新当前页继续等待，不让 Scheduler 每 10 秒新建/关闭标签；完成、超时、异常或中断时才在 `finally` 中回收，且不关闭共享 Chrome 的最后一个标签页。

不再下载或裁剪题图，不发送微信消息，也不依赖 mi15、xlproject 或 xlsln。

## `job_status -> next_time`

| `job_status` | 含义 | `next_time` |
| --- | --- | --- |
| `outside_window` | 当前不在活动窗口 | 下一个周二/三/四 17:59:50 |
| `waiting_thread` | 同一标签页持续等到活动窗口结束仍未发布 | 下一个活动日 |
| `waiting_answers` | 同一帖子持续等到活动窗口结束仍无达标候选 | 下一个活动日 |
| `ready_dry_run` | 只读验证已选出候选 | 默认 10 秒后，不写提交账本、不发送 |
| `submitted` | 回帖且页面确认新增评论 | 下一个活动日 |
| `already_submitted` | 本帖已有完成记录 | 下一个活动日 |
| `submission_uncertain` | 点击发送后的结果无法确认 | 下一个活动日，不自动重试 |

最后一条是外部写入保护：提交前在 `AppSetting` 写入本帖的 `submitting` 意图。
如果发送后网络异常、Cell 被打断或无法确认新增评论，下次运行看到该意图就不会重复回帖。

- `backend/core/fanxiu/data_annotation/scheduler_defaults.py`：本机标准实例默认值。
