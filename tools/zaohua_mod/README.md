# Code4101的天道系统

`Code4101的天道系统`是基于 BepInEx 6 的《造化仙缘》综合 Mod。游戏内简称“天道系统”，设置入口简称“天道”。源码保存在 CodeYun，游戏原始 DLL 和存档文件均不直接修改。

## 当前功能

- `丹谱`：按游戏品阶折叠展示全部丹方，点击后复用游戏左下角的丹方详情。
- `智能`：读取当前丹方、已装备丹炉、全局药材目录和背包库存，在插件内离线生成基础解、迭代解，以及必要时的背包兜底解。
- 基础解只使用单属性药材，排除相生与异灵根转换药材；按药材固有正负值和丹方目标确定阴阳炉位，从最低品阶向上完成严格五行配平，再验证真实形状能否装入当前丹炉。候选按品阶分布逐档比较，先减少最高档药材、再减少次高档药材，所以两株下品严格优于一株中品；冰等异灵根必须使用的较高档不会掩盖普通五行仍应选低档的事实。
- 单元素组合搜索优先取足当前最低档药材，再尝试用更高贡献药材替换；候选数量不会提前终止搜索，因此只要低档组合能够严格配平并装入丹炉，基础解就不会越级选用高档版本。
- 每个品阶先确认所有目标元素均已有候选，再用最多 2048 个节点构造首个严格配平组合并立即验证真实形状；普通五行继续取各自最低档，只有冰、风、雷等异灵根提升到首个可用档位。低目标丹方可直接发布基础解，只有快速组合无法装炉时才进入完整候选枚举。
- 迭代解只在严格配平、不可约的配方空间内做同元素拆分和规则导向的位置/旋转调整；禁止通过加入净贡献为零的阴阳药材对刷规则收益。结果必须严格提高实际规则收益，否则不展示迭代解。
- 基础解先确定最低阶严格配平组成，再按真实丹方规则优化摆放。迭代解为每个目标属性生成严格配平的 Pareto 配比，按属性、炉位、形状及每条规则的目标命中特征合并等价状态，再联合所有属性形成完整方案；同行、相邻、双目标等规则因此可以同时改变多个属性。只有联合候选通过真实形状摆放并严格优于基础解时才展示，单属性整数配比只是其中的自然快速路径，不绑定具体丹方或属性。
- 对“指定区域内每株目标药材独立计数”的线性规则，装箱器会先计算当前组成的安全收益上界；真实摆放达到上界后立即停止，不再为同收益排列跑满 3 万节点。属性求和、空格、相邻、同行等复杂规则不使用该剪枝，继续完整验证。
- 同一批药材装炉时，先摆放参与底部、顶部、边缘、中心或相邻关系等丹方规则的药材，再摆放只负责五行配平的药材；因此同收益方案优先呈现规则区域连续、其余药材紧凑排列的直观布局。
- 规则优化按最终有效品质计分，品质达到极品后，继续增加的原始品质加成按零收益处理；只有成丹数、耗时、免耗等其他实际收益继续提高时，才会保留进一步的迭代优化。
- 当前游戏进程只有一套丹方状态：每个“丹方 × 丹炉 × 静态药材配置”状态同时保存基础解、迭代解、当前背包解、求解完成度与可用性；丹谱和智能页共同读取它，不各自建立结果缓存。静态求解的“已完成”与“找到几条结果”分别记录，即使基础解、迭代解均未找到，也不会因结果列表为空而重复搜索；只要任一静态方案满足库存，就不计算背包解。
- 背包解是理想迭代解（不存在时回退基础解）的库存约束修复：优先保留品质和成丹收益，再尽量减少相对理想配方的替换。只有两个静态方案均不可用时才动态计算，库存变化只失效背包结果。
- 丹谱展开品阶或选择丹方时，会把对应丹方送入单工作器后台预热队列。后台阶段性结果先写回统一丹方状态，再同时驱动丹谱可用菱形和智能页；进入智能页只读取同一状态，不重新起算。
- 丹谱卡片创建、品阶展开、切回丹谱、丹方切换和库存刷新时都会主动从统一状态重放可用标记；即使求解在页面隐藏期间完成，也不会依赖一次性的后台回调才能显示黄色菱形。
- 智能求解运行在独立后台线程；游戏主线程只采集输入快照、按 0.25 秒节奏读取增量状态并展示结果。离开智能页不会取消丹谱预热，禁用功能、销毁界面或更换丹炉时才结束相关任务。
- 求解结果沿用官方方案卡片，最多同时展示三条；点击方案只回填炼丹格，不会自动炼丹。
- 方案最终成丹数与品质按游戏原生顺序执行已激活炼制天赋和丹炉效果，再叠加丹方基础值与图形规则；方案卡片以“成本：每丹种植时间 5.00 天”的独立行展示，按总种植天数除以最终成丹总数计算，超过 300 天时按 360 天/年换算。
- 方案卡片按最终品质对应物品的原生价格计算经济价值：`日收益 =（成品单价 × 成丹数 - 所用药材总价）÷ max(1, 实际炼制天数)`。实际天数沿用游戏的丹炉、天赋、丹方和摆放规则结算顺序；零耗时方案按 1 天折算。界面只显示四舍五入后的整数日收益，其余明细不占用卡片空间。
- 不依赖 CodeYun 服务、浏览器、`localhost` 或联网 API，可单机分发运行。
- `天道试炼`：在游戏 `设置` 页面提供与 `游戏 / 视频 / 声音 / 键盘` 同级的 `天道` 配置页；主角不受影响。
- `炼丹助手`：在天道配置页动态开启或关闭 `丹谱 / 智能` 炼丹功能，默认开启。
- `NPC 属性倍率` 调整气血、术攻/术防、物攻/物防、护甲、护罩；`速度倍率` 默认关闭，开启后速度使用同一倍率。
- 倍率最低为 `×1`，不设插件上限；极端倍率仍受游戏底层数值类型限制。
- 倍率在游戏完成原有难度、境界压制等计算后乘到 NPC 最终面板，不遍历或改写 NPC 基础属性。
- 精力与神魂始终不放大。
- 天道配置保存为插件级全局设置，可在主菜单修改，所有存档共用并在运行中立即生效。
- 配置文件位于 `BepInEx/config/code4101.zaohua.tiandao.cfg`，按 `天道试炼 / 天道助缘` 分节并带配置版本；新增功能可追加参数而不破坏旧配置。
- 储物空间为丹药提供“全部 / 丹药 / 丹方”二级筛选，为装备提供“全部 / 头饰 / 服饰 / 鞋履 / 饰品”二级筛选，并跟随游戏原有“记住筛选”开关。
- 储物空间原生排序菜单只保留一个“名称排序”入口：普通物品按当前语言环境比较名称；防具分类内部改用游戏原生 `suitId / TbSuitCfg.ItemList` 将同套防具连续排列，无套装散件后置，但按钮仍显示“名称排序”。重复选择可切换套装组或名称的升序和降序，套装内部始终保持官方成员顺序。
- 装备区提供按存档隔离的活动方案下拉框；`方案1` 首次自动接管原有装备，新建方案从六个空槽开始配置。当前方案内的穿戴与卸下会自动持久化，切回时恢复该方案的最新状态。下拉列表只负责选择方案；当前方案标题右侧集中提供“改名 / 删除”，删除需再次点击确认，且至少保留一个方案。
- 配装槽位以装备的稳定 `BlendId.sedId`（物品配置 ID）绑定；`blendEnum` 只是数据表类型，背包实例 `packId` 只用于同配置多件时优先找回原实例。方案文件使用可往返校验的 JSON 协议持久化；切换前会先解析全部非空槽位，任一目标未找到就取消整次切换并保持当前装备不变。
- 功法配置悬浮框会显示当前功法图形规则的实际倍率，例如“当前增幅 ×2”。倍率直接调用游戏刷新丹田布局时使用的原生 `GetUpMultiplier` 计算，因此包括尚未生成运行时加成记录、但会在战斗事件中执行效果的规则；不展示 `UpdateAction` 等内部动作文本。
- 装备方案数据保存在 `Application.persistentDataPath/Code4101.Tiandao/equipment-loadouts.json`，不修改官方存档、不写项目目录，并使用同目录临时文件原子替换。
- 背包属性区和战斗单位生命条的数值达到 `1万` 后自动压缩为“万”，达到 `1亿` 后压缩为“亿”；压缩值按量级保留四位有效数字，生命条左右两值分别判断，底层属性值不变。

## 构建与部署

游戏默认目录为 `D:\SteamLibrary\steamapps\common\GodWorld`。

```powershell
.\tools\zaohua_mod\build.ps1
.\tools\zaohua_mod\deploy.ps1
```

完全退出并重启游戏后验证：

1. 主界面点击“再寻仙踪”。
2. 进入顶部 `K` 炼丹入口，再进入“炼制丹药”。
3. 右侧依次出现 `丹方 / 炼制 / 配方 / 丹谱 / 智能`。
4. `BepInEx\LogOutput.log` 包含 `Code4101 Tiandao patches registered.`。
5. 打开 `设置`，点击左侧 `天道`，可配置 `NPC属性倍率`、`速度倍率` 和 `炼丹助手`；底部 `恢复默认` 会恢复为 `×1 / 关闭 / 开启`。

Steam 文件校验不会修改 CodeYun 中的源码；插件部署产物位于 `BepInEx\plugins`。游戏或 BepInEx 更新后应重新构建并按上述真实入口验证兼容性。
